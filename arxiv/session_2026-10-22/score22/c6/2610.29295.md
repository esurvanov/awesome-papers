## ABSTRACT
Finding K most similar elements for a query in a large gallery of neural network (NN) embeddings is essential in various areas of computer science and industrial applications of artificial intelligence. This paper proposes search algorithms for structured latent spaces (LS) of NNs which allow to speed up top K item retrieval owing to O(1) complexity small candidate gallery subset search. ArcFace-pretrained IResNet50 models are finetuned using Latent Space Configuration (LSC) methodology to obtain new distribution of embeddings with desired geometric properties. Applying the proposed algorithms to embeddings obtained from finetuned models leads to several times speed-up over baseline exhaustive search. Specifically, we report up to 3 times speed-up on GPU and 40% speed-up on CPU compared to the baseline method GPU speed. These results are obtained for the original and reduced numbers of LS dimensions. The results show that LS dimensionality reduction allows to further accelerate the search and even improve rank-N metrics.

## 1 Introduction

Nowadays, various complex systems rely on efficient retrieval of
relevant information from extremely large databases. Often this requires
data ranking by asserting relevance of database data with the query and
returning K most relevant elements (top-K, or
top-k, or top-N) [1]. High-dimensional outputs
(embeddings) of neural networks (NNs) can directly be used as
description vectors that represent the data, so numerical similarity
between vectors becomes a measure of relevance [2]. This is widely
used in document analysis, recommendation systems, speech and audio
recognition [3, 4, 5]. In context of computer vision (CV),
this translates to finding K most relevant images in gallery
G for a query q. This is essential for e-commerce, face
recognition, biometrics, and security [6, 2, 7].

Exhaustive search has $\mathcal{O}(n\textsubscript{g})$ complexity since it
requires to compare queries with all embeddings in G with size
ng. This is not feasible for galleries of million
or billions of elements, so approximate methods are used instead. These
methods often require building indexing structures over the gallery for
fast retrieval of a smaller subset specific to the given query [8, 9, 10]. While indeed allowing sub-linear scaling, these methods are
still computationally expensive and can reduce complexity to
 $\mathcal{O}(\sqrt{n\textsubscript{g}})$ [11].

In this paper we take advantage of geometric properties of vector
systems used for NN latent space configuration (LSC) to find a small
subset in G and significantly accelerate top K retrieval.
LSC is a novel methodology which uses predefined class prototypes to
structure and add geometric properties to NN LS during training
 [12]. It has previously been shown that the complexity of the
search of mean vectors of class embeddings for classifier NNs with
preconfigured LS is $\mathcal{O}(1)$ , which can be realized with a single
sort operation performed on the embedding vector. In context of face
recognition this translates to the search of mean vectors of person
identity (id) embedding clusters with $\mathcal{O}(1)$ complexity.
Hence, the complete search complexity becomes $\mathcal{O}(n\textsubscript{c})$ 
where nc is
id cluster size which can be several orders of magnitude smaller
than ng. It is also important that
nc depends on the number of images per id
(which can differ for different ids) and not
ng.

The desired geometry of NN emebdding distribution can be achieved with
finetuning. NN pretraining on extremely large general purpose datasets
and finetuning on smaller target datasets using supervised or
self-supervied learning methods has proven to be very effective in
various CV areas [13, 7, 14]. It has recently been shown that
finetuning can also be performed using prototype-based training methods [15, 16].
However, most of them use trainable prototypes and
require loss functions which complexity grows linearly with the number
of clusters, classes, or ids in the gallery
nid [17, 15, 18]. On the
contrary, LSC chooses predefined non-trainable prototypes allowing to
avoid nid scaling, which is beneficial for
training and finetuning on datasets with extremely large
nid [12].

In this paper we propose two id cluster search algorithms which
allow to rapidly identify a small candidate subset of gallery embeddings
which similarity with the query needs to be assessed. These algorithms
require that NN LS possesses certain geometric properties, so
configuring LS during finetuning is essential for fast high-accuracy
retrieval. The application of the proposed algorithms to embeddings of
finetuned NN leads to several times speed-up on GPU and 40% speed-up on
CPU compared to exhaustive search performed on GPU. The latter is
particularly important for low computational budget and edge
applications where GPU resources are limited or unavailable.

The rest of the paper is organized as follows: Section 2 outlines the
LSC methodology for finetuning, Section 3 describes the proposed search
algorithms, Section 4 summarizes experimental results, Section 5
discusses potential application scenarios of proposed methods, and
Section 6 concludes the paper.

## 2 Configuring LS of NNs during training and finetuning

LSC training methodology is discussed in detail in [12, 19]. The
goal of LSC is to force mean vectors of embedding clusters to align with
vectors of some predefined vector system Vn with
desired geometric properties. To configure NN LS one needs to choose the
base Vn, to distribute mean vectors of embedding
clusters (corresponding to classes or ids) among them, and to
choose a loss function. It has been shown that cosine loss (which
maximizes cosine similarity between embeddings and prototype vectors)
performs best in high-dimensional cases [12]. Since cosine loss
values illustrate how close id embeddings are to their target
vectors, training naturally reduces cluster size while ensuring
separation of clusters determined by the Vn
vector distribution.

It has been shown that NN discriminative ability depends on properties
of the LS embedding distribution. Firstly, embeddings of similar inputs must
have high similarity and be close in LS, so clusters of embeddings
corresponding to one class or id are compact. Secondly,
embeddings of different classes or ids must have low similarity,
so embedding clusters are well-separated. This is achieved by
introducing loss functions that affect NN embedding distribution by
acting directly in LS [18, 20]. One of the most
important methods is ArcFace which has introduced an additive angular
margine penalty to standard softmax loss to improve cluster
compactization and separation [21]. This has led to significant
improvement in discriminative ability and the overall performance of
face recognition NNs.

However, ArcFace requires to use several complicated loss functions
which include id loss, which requires having an NN layer with
nid size. As previously mentioned, this limits
the application of this method when nid is
extremely large. On the contrary, LSC does not require creating
trainable objects of nid size and, by choosing
sparsely distributed prototypes, the inter- and intra-class (cluster)
distribution requirements mentioned above are automatically satisfied
when clusters formed around Vn vectors are
sufficiently compact.

In general, any system of vectors with some predefined set of desired
properties can be used for LSC. In this paper we use systems of vectors
 $V_{n}^{mk}$ such that all vectors in the system are obtained as
permutations of elements of a base vector which consists of m
ones, k negative ones, and ( $n-m-k)$ zeros [22, 23]. Specifically, we use $V_{n}^{11}$ system, meaning that all
Vn vectors have exactly one “1”, one “-1”,
and ( $n-2)$ zeros. These vectors coincide with root system $A_{n-1}$ 
vectors [24]. For NN training purposes
n coincides with the number of LS dimensions.

## 2.1 Finetuning LS with the original number of dimensions

Figure 1 shows steps required to finetune a pretrained model using
LSC. Firstly, it is necessary to calculate class or id mean
embedding vectors on the target dataset. A classification layer should
be removed if it is present in the architecture. Secondly, mean
id embedding vectors should be paired with closest (with respect
to cosine similarity) unique vectors from the chosen
Vn. This allows to determine which id
corresponds to which Vn vector and use them as
the target cluster center vector C. Afterward the finetuning
process follows basic LSC training procedure described in Section 3.3 in [12].
Ids can be predicted in the same manner in which
labels are predicted in the original method, i.e. by checking the
id assigned to Vn vector closest to a
given embedding. Id prediction accuracy used in Section 4.1 is
the percentage of correct id predictions for all data points in
the dataset used for finetuning.

## 2.2 Finding Vn vectors closest to mean embedding vectors

It has been mentioned in Section 2.1 that each id should be
paired with the closest Vn vector. However, two
or more id clusters may share the same closest
Vn vector, which can be expected for classes or
ids of objects or persons with some degree of similarity.
Assigning the same Vn vector to several
ids will make these ids indistinguishable after
finetuning, which is not acceptable. Hence, all but one id should
be assigned different Vn vectors.

Fortunately, there exists a neat way of finding possible
Vn vectors owing to the structure of the proposed
vector systems. It has previously been shown that for an arbitrary
embedding m of its largest and k of its smallest elements
determine its cosine similarity with $V_{n}^{mk}$ vectors [23].
For $V_{n}^{11}$ this means that only maximum and minimum magnitude
elements in the embedding affect the similarity calculation results, and
one can find their indexes using argmax and argmin operations,
respectively. It should be mentioned that $V_{n}^{11}$ vectors can be
uniquely referred to using indexes of their positive and negative
elements. For example, a vector with elements [1,-1, 0 … 0] is
referred to as (0, 1), another one with elements [0,1, 0 … -1] is
referred to as (1, n-1), etc. This pair is hereafter referred to
as index of $V_{n}^{11}$ vector.

Large and small elements of embedding vectors, as well as their indexes,
can also be found by analyzing sorted embedding vectors. When the
closest vector, i.e., a vector with “1” in embedding’s argmax
position and “-1” in its argmin position, to some mean embedding
vector is already assigned an id, another close
Vn vector can be found by choosing pairs of
indexes as shown in Figure 2. This approach ensures that mean
embedding vectors are not paired with distant Vn
vectors and the original distribution of clusters is not disturbed.

## 2.3 Finetuning LS with the reduced number of dimensions

Reducing the number of dimensions of NN embeddings can lead to faster
computations and storage space reduction [25, 26]. However, this
often leads to worse accuracy metrics, which indicates an important
trade-off. Hence, computation acceleration and accuracy metrics should
be carefully monitored to identify the optimal number of LS dimensions.

In this paper we use random projection to obtain low-dimensional NN
embeddings [27, 28]. Specifically, to obtain embeddings in
LS with reduced number of dimensions nred
(hereafter referred to as reduced LS) using known embeddings in LS
with the original number of dimensions norig, we
first construct a random uniform matrix with dimensions
[norig, nred]. We then
apply QR decomposition to this matrix [29] and use the
obtained matrix Q (with dimensions
[norig, nred]) for
embedding projection

NN embeddings in the original and reduced LS, respectively. It has
previously been shown that for specific nid,

when the number of vectors in Vn system
nvects $\geq$ nid [22].
In case of $V_{n}^{11}$ the number of vectors is

 $n_{vects}=n\cdot(n-1).$

## 3 Search algorithms for fast retrieval of top K relevant images

In this paper we consider exhaustive $\mathcal{O}(n\textsubscript{g})$ search
as baseline for comparison. Algorithms proposed in this Section focus on
finding a small gallery subset for similarity calculation using
geometric properties of Vn used for LSC.
Specifically, we first find closest Vn vectors
for all gallery embeddings and store their indexes (as discussed in
Section 2.2). Then for a query q we find its closest
Vn vector, retrieve all gallery embeddings with
the same closest Vn vector (called candidates),
and then compare q only with these candidates. Since the closest
Vn vector search complexity is $\mathcal{O}(1)$ , the
complexity of the candidate subset search is also $\mathcal{O}(1)$ , and the
overall complexity is $\mathcal{O}(n\textsubscript{c})$ rather than
 $\mathcal{O}(n\textsubscript{g})$ , so the speed gain is proportional to

 $\frac{t_{exh}}{t_{new}}\ \sim\ \frac{n_{g}}{n_{c}(id)}\approx n_{id},$ 

(4)

where texp and tnew are
time intervals required to retrieve top K elements using the
exhaustive search and the proposed algorithms, respectively. Thus, the
more ids the gallery has, the higher acceleration can be
expected.

## 3.1 CPU-focused search acceleration

In this paper we present two possible implementations of the proposed
search method. Algorithm 1 uses the original fast search method [23].
Here a hash table (e.g., a python dictionary) with
indexes of closest Vn vectors to all embeddings
in G as keys and lists of all embeddings with the same closest
Vn vectors as values is created. The number of
keys in this hash table is proportional to nid,
and the number of values in each list is proportional to
nc. For each query its closest
Vn vector is used to retrieve candidates using
this dictionary, which allows to form candidate tensor and compute
similarity. This search is fast due to hash table $\mathcal{O}(1)$ key search
complexity.

There are two main problems with this implementation when queries are
processed in batches. Firstly, dictionary search and data preparation do
not efficiently work in parallel. Secondly, since the number of
candidates varies for different queries in the batch, padding is
required when forming the candidate tensor. This means that candidate
tensor shape is always determined by the largest
nc in the batch, which is suboptimal.
Nevertheless, Algorithm 1 performs extremely well on CPU, as will be
shown in Section 4.
