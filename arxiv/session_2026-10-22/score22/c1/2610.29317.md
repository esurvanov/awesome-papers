## ABSTRACT
Spatial reasoning requires more than access to geometric tools: a reasoner must decide when direct observation is sufficient and when to reconstruct, measure, or change reference frames. We present SpatialBrain, a framework that retains experience about these decisions while keeping its vision-language backbone fixed. The key distinction is between evidence about a scene and experience about how to reason with that evidence. 3DFusionMemory fuses current-scene observations into queryable spatial relations. A Spatial Skill Library provides reusable tool procedures, and Spatial Cognition associates task conditions with experience about when and how to use memory and skills. Completed trajectories are abstracted into process records and consolidated between task blocks, allowing later decisions to draw on earlier execution without transferring scene coordinates or reference answers. Across five spatial-reasoning benchmarks, SpatialBrain improves on direct answers from the same backbone on four and ties on the fifth. Component comparisons, experience-coverage curves, and traced resource decisions characterize how the framework accumulates and uses these resources.

## 1 Introduction

The same visual scene can pose very different reasoning problems. A visible attribute may be read directly, an object-relative direction requires a reference frame, and a distance estimate may require geometric evidence from several views. Route questions additionally require keeping track of successive movements. Spatial benchmarks expose these differences through multi-image reasoning, limited-view scene construction, dynamic spatial aptitude, and degraded observations [28, 24, 12, 19, 33]. A useful reasoner must therefore choose the computation as well as produce the answer. Reconstructing every scene can add unnecessary cost and noisy evidence, while answering directly can overlook information that must be integrated across views.

Spatial representations learned through training [4, 6] and tools for perception, reconstruction, and simulation [17, 5, 7, 35] expand the computations available to a reasoner. Agent methods also retain reflections and reusable workflows from earlier tasks [21, 23, 32, 25]. Access to a resource, however, does not specify when it is useful. A procedure for computing relative directions can be reused across scenes; the coordinates on which it previously operated cannot. The challenge is to retain experience that informs resource use while grounding each answer in the current scene.

SpatialBrain separates scene evidence, reusable computation, and experience
about resource use. It operates as an agent: a vision-language reasoner that
can select and call tools. After completing tasks, it retains abstract
records of the conditions encountered, resources used, and execution
feedback. Later tasks consult these records to choose a reasoning route,
memory-access mode, or skill. We call this cross-task adaptation
self-evolution. The model weights remain fixed; the external
experience available to the controller changes. Unlike correcting an answer
within one task, self-evolution changes the state available to subsequent
tasks.

•

evidence with supporting views and uncertainty.

•

from the scene-specific inputs on which it acts.

• 

Spatial Cognition accumulates condition-specific experience
about when and how to use memory and skills. Past process feedback and costs
inform resource selection, connecting completed trajectories to later

## 2 Related Work

Spatial intelligence.

SpatialVLM and SpatialRGPT develop spatial representations through targeted supervision [4, 6], while Thinking in Space studies cognitive maps for video reasoning [27]. Tool-based approaches expose visual programs, geometric constraints, stateful computation, and simulation to a reasoner [11, 17, 5, 7, 35]. Structured representations include S-Agent’s scene and agent memories and AlloSpatial’s allocentric maps [8, 20]. SpatialCLI provides specialist tools, and SATURN and OmniView-Space emphasize perspective-aware reasoning [34, 13, 16]. SpatialBrain uses execution experience to decide when and how to invoke spatial representations and computations.

Agent skills and memory.

Executable skills and recurring workflows provide reusable computation, as in Voyager and Agent Workflow Memory [23, 25]. Skill-3D distills scene-aware tool workflows and failure lessons from rollouts for skill-guided inference and agentic post-training [14]. SpatialBrain focuses on blockwise, reference-label-free test-time resource adaptation with fixed model weights, separating current-scene geometry from persistent resource-use experience. Episodic reflection and linked memory notes retain broader experience [18, 26], whereas object-centric scene graphs and exploration snapshots retain spatial evidence [9, 29]. In SpatialBrain, the Skill Library stores how to execute a procedure, strategic experience records when and how to use it, and 3DFusionMemory represents what the current scene supports.

Self-evolving agents.

Self-evolving agents differ in what they update. Reflexion retains verbal feedback for subsequent trials [21], while ExpeL distills experience from training tasks for later inference [32]. Agentic Context Engineering consolidates contextual playbooks through generation, reflection, and curation [31]. Automated Design of Agentic Systems searches agent programs using an expanding archive [10], while the Darwin Gödel Machine modifies and tests agent code [30]. SpatialBrain updates external spatial strategies and procedural records from completed test-time trajectories.

## 3 SpatialBrain

## 3.1 Overview

Given images $I_{1:K}$ , a question $q$ , and optional answer choices $O$ ,
SpatialBrain solves a task $x_{i}=(I_{1:K},q,O)$ using a fixed vision-language
backbone and perception and geometry tools. Spatial Cognition selects the
reasoning route and access to memory and skills. Tool observations populate
the scene memory, and skills carry out reusable computations on the current
inputs. An execution trajectory records these decisions, calls, returned
evidence, and process checks. Completed trajectories supply experience for
later tasks without updating model weights, as illustrated in
Figure 2.

Figure 2: Self-evolution from earlier trajectories. (a) Initial reasoning leaves the reference frame unresolved. (b) Completed earlier trajectories are abstracted and consolidated between task blocks. (c) Accumulated experience guides memory access and skill selection for the same target. The trajectories and outcomes are illustrative.

This separation gives two timescales of state: scene evidence changes
within a task, while experience about using evidence changes between
task blocks. Let $i$ index tasks, $t$ a within-task execution step, and $b$ a
block. The state available to the reasoner is

 $\mathcal{S}_{i,t}=(\mathcal{G}_{i,t},\mathcal{H}_{b}),\qquad\mathcal{H}_{b}=(\mathcal{L}_{b},\mathcal{P}_{b}).$ 

(1)

Here $\mathcal{G}_{i,t}$ is the current scene graph, $\mathcal{L}_{b}$ the skill
library, and $\mathcal{P}_{b}$ the strategic experience used by Spatial
Cognition. Observations update $\mathcal{G}_{i,t}$ during
execution; all tasks in a block read the same committed snapshot
 $\mathcal{H}_{b}$ and keep separate scene graphs. A procedure for comparing
object-relative directions can thus persist without carrying its earlier
object coordinates into a new scene.

## 3.2 3DFusionMemory

Different views expose different objects and different sides of the same
object. 3DFusionMemory fuses these observations into a shared scene frame,
where object identities connect evidence across views and spatial relations
connect objects. The memory for the current task is

 $\mathcal{G}_{i,t}=(\mathcal{V}_{i,t},\mathcal{E}_{i,t},\mathcal{C}_{i,t},\mathcal{R}_{i,t}),$ 

(2)

where $\mathcal{V}_{i,t}$ contains object nodes, $\mathcal{E}_{i,t}$ spatial
relations, $\mathcal{C}_{i,t}$ camera states, and $\mathcal{R}_{i,t}$ ordered
route history. Nodes retain detections,
3D centers, available point sets and extents, pose, semantic axes, and
supporting views. Depth and camera poses place observations in the scene
frame; matched observations update an object’s center through
confidence-weighted fusion (Appendix D).
Repeated observations support the same node, while complementary views add
objects that a single view does not cover. Relations are then computed
between these fused object representations (Figure 3).

Figure 3: Multi-view observations become spatial relations.
Three of six input views, a saved fused 3D scene, and view support for five

Queries return distances and camera- or object-frame relations together
with confidence, supporting views, and ambiguity. Ordered route state
supports successive translations and rotations. The planner may receive
compact spatial facts, or memory may be reserved for answer checking.
Skills and reasoning steps can therefore refer to the same grounded objects
instead of reconstructing their relations independently.

## 3.3 Spatial Skill Library

Recurring spatial operations can reuse a computation even when the objects
and images change. The library represents each skill as a procedure with an
explicit applicability condition and input–output interface:

 $\ell=(A_{\ell},X_{\ell},P_{\ell},Y_{\ell}),\qquad\ell\in\mathcal{L}_{b}.$ 

(3)

In equation 3, $A_{\ell}$ specifies applicability, $X_{\ell}$ 
typed input requirements, $P_{\ell}$ a parameterized tool procedure, and
 $Y_{\ell}$ its returned evidence. For example, a relative-direction procedure
binds a reference frame before computing a displacement. Its parameters
refer to the current task’s objects, so the same procedure can operate on
different scenes.

Seed skills initialize the library. Completed trajectories add recurring
execution patterns and records of their use. Spatial Cognition can withhold
a skill, expose it as a planning hint, or permit execution. The executable
configuration also compiles compatible primitive calls into parameterized
procedures and tests them under a limited budget; earlier hint-based
configurations retain procedural records without this compilation. A change
in an existing skill’s availability is consequently distinct from the
creation of new skill code.

A skill may build or query the current scene memory, but cannot supply an
earlier answer or bypass a disabled memory interface.

## 3.4 Spatial Cognition

Deciding when and how to use resources.

Spatial Cognition turns execution experience into conditional resource
decisions. Its strategic store associates input-visible task conditions
with past resource choices, process checks, failures, and costs. A task
signature $\sigma_{i}$ describes the reference frame, relation scope, output
form, temporal structure, metric demand, and view count. It uses neither
reference answers nor benchmark category labels. Given this signature and
the available experience, the controller selects

 $g_{i}=\pi(\sigma_{i};\mathcal{P}_{b},\mathcal{L}_{b})=(r_{i},m_{i},\mathcal{K}_{i},\nu_{i}).$ 

(4)

Here $r_{i}$ chooses direct-first or tool-assisted reasoning, $m_{i}$ controls
memory access (off, answer-checking only, or planner-visible),
 $\mathcal{K}_{i}\subseteq\mathcal{L}_{b}$ gives permitted skills, and $\nu_{i}$ 
specifies verification and revision. Equation 4 is resource
selection, not answer prediction. A skill’s how describes a computation;
Cognition’s how describes how to use that computation and its evidence.
The controller combines initial rules with stored experience rather than
training an additional model.

Resource changes require supporting experience. In the executable
configuration, route and memory alternatives must have sufficient historical
support, acceptable process risk, and lower estimated token cost; otherwise
the default remains. At most one learned route or memory factor changes per
request. Skill selection requires compatible inputs and availability, while
verification and resource limits follow fixed rules.
Appendix D specifies these conditions.
Process feedback is not a correctness reward: it describes execution
reliability and cost, not agreement with a reference answer.

The self-evolution loop.

Tasks first execute using the fixed block snapshot. After task $i$ finishes,
its trajectory $\tau_{i}$ is projected to a label-free record
 $d_{i}=\operatorname{Abs}(\tau_{i})$ : task signature, resource decisions, tool
sequence, process checks, failures, and available costs. This abstraction
excludes answers, literal scene coordinates, and raw task content from the
transferable state. For completed block $\mathcal{B}_{b}$ , let
 $\mathcal{D}_{b}=\{d_{i}:i\in\mathcal{B}_{b}\}$ . Only then do the stores update:

 $\mathcal{P}_{b+1}=U_{\mathrm{policy}}(\mathcal{P}_{b},\mathcal{D}_{b}),\qquad\mathcal{L}_{b+1}=U_{\mathrm{skill}}(\mathcal{L}_{b},\mathcal{D}_{b}).$ 

(5)

Here $U_{\mathrm{policy}}$ consolidates condition-specific strategic records
and statistics; $U_{\mathrm{skill}}$ updates procedural records and their
availability. Equation 5 is a state update, not a gradient
step. The next block can retrieve these records and make different resource
choices. No task in $\mathcal{B}_{b}$ reads these updates, future observations,
or reference answers, allowing parallel execution within each block.

## 4 Experiments

## 4.1 Experimental Setup

We evaluate MMSI, MindCube, OmniSpatial, SpaceDG, and SAT on 1,000, 1,050,
1,533, 1,000, and 150 items, respectively [28, 24, 12, 33, 19].
We report accuracy, using mean relative accuracy (MRA) for numeric SpaceDG
questions. SpaceDG uses a fixed 1,000-item subset, and SAT uses fixed option
order. The direct-answer baseline and SpatialBrain both use GPT-5.6-sol on
the same items. Predictions are fixed before scoring; experience updates
use neither reference answers nor future tasks.

## 4.2 Main Results

SpatialBrain improves on direct GPT-5.6-sol answers on four benchmarks and
ties on SAT (Table 1), raising the unweighted mean from 67.5
to 72.6. MindCube accounts for the largest gain, at 20.4 percentage points;
the smaller changes on OmniSpatial and SpaceDG show that the benefit
depends on the task setting.
Category-level changes are mixed, including regressions on OmniSpatial’s
egocentric questions and SpaceDG’s distance and counting questions.
