Abstract

Generative retrieval (GR) casts search and recommendation as autoregressive generation of discrete semantic identifiers (SIDs). SID design largely determines the quality of GR results: SID models, collision handling mechanisms, decoding frameworks, and training recipes can each change retrieval performance significantly. However, these discrete and interdependent design choices cannot be optimized end-to-end using gradients from downstream retrieval and therefore remain largely designed by hand. In this paper, we introduce a framework for automatically improving these components through LLM-driven evolutionary search on the SID framework, which to the best of our knowledge is the first application of LLM-driven evolutionary program search to GR. A locally servable, open-weight 31B language model is used to mutate executable GR components, so no proprietary LLM API is used at any point, and a 1M-parameter proxy decoder provides fast downstream feedback in place of repeatedly training the 1B target generator, which would otherwise make evolutionary search computationally infeasible. Across 21 SID programs on NQ320K, proxy and target Recall@100 exhibit strong rank correlation ( $\rho=0.90$ ). Guided by this proxy, evolution consistently improves the seed GR on NQ320K, MSMARCO300K, and a multilingual e-commerce dataset, under a training recipe held fixed across conditions. On NQ320K, jointly evolving SID and collision handling improves Recall@1 from 55.8% to 59.3% and Recall@100 from 85.8% to 90.6%. Our component study reveals that proxy reliability depends on which component is evolved. Improvements transfer reliably when evolving the semantic index, but transfer less reliably when evolving the generator’s training objective or the full GR pipeline. These results suggest that LLM-driven evolutionary search is a practical method for improving GR design and show that carefully assessing proxy reliability is essential for successful GR pipeline optimization.

## 1 Introduction

Generative retrieval (GR) casts document retrieval as an autoregressive generation task. Given a query, the model is trained to generate the document identifier which maps back to a document (Tay et al., 2022; Wang et al., 2022). In GR systems that are based on semantic identifiers (SIDs), documents are represented by short sequences of discrete tokens, often constructed from their semantic embeddings (Rajput et al., 2023; Ju et al., 2025). These identifiers define the prediction problem for the generator. During autoregressive decoding, documents that share an SID prefix share early generation decisions, which means a relevant document will become unreachable if an SID token in its prefix is discarded during beam search. SID design therefore determines both what the GR model must learn and how it can reach relevant documents during decoding (Zeng et al., 2024). Improving a generative retriever thus requires careful design of SID generation. This design could involve several interdependent procedures: (1) an index builder assigns SIDs to documents; (2) collision handling distinguishes documents that were assigned the same SID; (3) a training objective teaches the generator to predict these identifiers; (4) generative decoding searches over valid SID sequences. Each procedure affects how the others operate. For example, changing the SID structure reforms the prediction targets, while resolving collisions may induce longer SID sequences for the generator to learn. Existing methods have shown that SID and generative retrieval models can be learned jointly within predefined architectures (Sun et al., 2023; Yang et al., 2023). However, ordinary backpropagation does not directly choose among different implementations of SID construction, collision handling, training, and decoding. Optimizing these executable procedures presents a broader, discrete search problem. To the best of our knowledge, no prior work has applied LLM-driven evolutionary program search to generative retrieval, and this paper is the first to show that doing so improves a GR pipeline.

Figure 1: Our two-tiered evolutionary framework. The outer loop manages the population database, selects parent programs, and constructs feedback for the mutator LLM. The inner loop gatekeeps and refines candidate programs, approximating fitness with a tiny decoder.

LLM-driven evolutionary search offers a way to explore this search space by proposing code mutations and retaining programs that perform well on an execution-based evaluation (Romera-Paredes et al., 2024; Novikov et al., 2025). While recent work has applied evolutionary program search to discover lexical retrieval (Nian et al., 2026a) and reranking pipelines (Lin et al., 2026), directly applying this approach to generative retrieval faces a substantial evaluation bottleneck. Evaluating each candidate index requires training the downstream generator and measuring its retrieval performance. In our setting, a target generator training run takes five hours on an H200 GPU, whereas training a proxy takes 20 minutes. Using the proxy therefore reduces the per-candidate evaluation time by 15 $\times$ , making it practical to evaluate many more candidate programs within a fixed computational budget. The central challenge is therefore to obtain inexpensive feedback that remains informative for guiding evolutionary search. In addition, recent discovery systems often use frontier models as the mutator (Qu et al., 2026; Virk et al., 2026; Cemri et al., 2026), which is expensive and less transparent. We run the entire search with an open-weight model that fits on a single GPU. We do not claim that a 31B mutator LLM is sufficient for program search in general, only that it was sufficient for evolving GR to outperform the seed.

As shown in Figure 1, we introduce a framework for evolving executable generative retrieval components using a small retrieval proxy and a locally served, open-weight mutator. Specifically, we use gemma-4-31b-it (Gemma Team, 2026), which can be served locally on a single H200 via vLLM (Kwon et al., 2023). Building on the AdaEvolve search algorithm (Cemri et al., 2026), the mutator proposes SEARCH/REPLACE edits to the program under fixed input and output constraints. For SID generation, the program receives document and query embeddings together with training relevance labels and returns an SID for each document. Evolution can change the procedure implementing this mapping. A tiny autoregressive decoder with approximately 1M non-embedding parameters is trained and tested on the training dataset only, to provide proxy retrieval performance feedback for candidate program evaluation. Programs are selected and evolved using proxy feedback alone, and in the end the best candidate is fully evaluated by training the google/gemma-3-1b-pt (Gemma Team, 2025) target generator on the training dataset and measuring the retrieval performance on the reserved test set from its final checkpoint.
Across NQ320K (Kwiatkowski et al., 2019), MSMARCO300K (Bajaj et al., 2016), and a multilingual e-commerce dataset, the selected evolved SID programs improve their corresponding seed programs when the SIDs they produce are used to train the target 1B generator. On NQ320K, jointly evolving SID construction and collision handling improves Recall@1 from 55.8% to 59.3% and Recall@100 from 85.8% to 90.6%. Our component study also identifies a boundary of proxy-guided search. Improvements transfer more consistently for the index-construction programs, whereas changes to the generator’s training objective or the full GR pipeline can improve proxy performance while reducing target performance. This distinction suggests that the usefulness of a small proxy evaluator depends on the artifacts being optimized. A shared SID structure can benefit both proxy and target generators, while a training objective that the proxy benefits from may not be suitable for the much larger target decoder. We state the scope of our claims plainly. We do not claim state-of-the-art GR, nor that GR dominates lexical or dense retrieval. Our contributions are as follows:

• 

We introduce a framework for evolving executable generative retrieval procedures with a tiny proxy decoder and a locally served 31B language model mutator, the first such framework for generative retrieval and one that uses no proprietary LLM API.

• 

We demonstrate retrieval improvements over matched seed systems across three retrieval datasets, observing substantial gains from jointly evolving SID construction and collision handling.

• 

We show that proxy-to-target transfer depends on the component being evolved, with semantic index improvements transferring more consistently than decoder training objective changes.

## 2 Generative Retrieval

Generative retrieval maps a query to a document by generating its identifier (Tay et al., 2022; Wang et al., 2022). Let ${\mathbb{D}}$ denote the document corpus. Each document $d\in{\mathbb{D}}$ is assigned a semantic identifier ${\bm{z}}(d)=(z_{1}(d),\ldots,z_{L(d)}(d))$ , where $L(d)$ is the number of tokens in its identifier. Given query text $q$ , an autoregressive generator with parameters ${\bm{\theta}}$ models

 $P_{{\bm{\theta}}}({\bm{z}}(d)\mid q)=\prod_{\ell=1}^{L(d)}P_{{\bm{\theta}}}\bigl(z_{\ell}(d)\mid q,{\bm{z}}_{<\ell}(d)\bigr),$ 

(1)

where ${\bm{z}}_{<\ell}(d)$ denotes the preceding identifier tokens. We train the generator on relevant query–SID pairs using teacher-forced next-token cross-entropy loss.

Inference traces a prefix trie of the valid SID sequences. Constrained beam search only permits child trie nodes as next tokens. In the end, the completed SIDs are mapped back to documents. Documents sharing the same SID prefix share early decoding decisions, so pruning a prefix early removes every document beneath it from the remaining search. The SID index therefore determines both the prediction targets during training and the branching structure during retrieval.

## 2.1 Semantic Indexing

Our seed program combines RQVAE-based SID construction with TIGER-style collision handling (Lee et al., 2022; Rajput et al., 2023). We first encode document text using a fixed Contriever or mContriever encoder (Izacard et al., 2022). These embeddings provide the input to the index builder. The generative retriever only receives query text.

SID construction. The seed constructs SIDs using residual quantization. Let ${\bm{x}}(d)$ be the fixed embedding of document $d$ and ${\bm{r}}_{0}(d)$ its latent representation produced by the RQVAE encoder. At each level $\ell$ , the quantizer selects a codebook vector and subtracts it from the current residual:

 $z_{\ell}(d)=\argmin_{k}\left\|{\bm{r}}_{\ell-1}(d)-{\bm{e}}_{\ell,k}\right\|_{2}^{2},\qquad{\bm{r}}_{\ell}(d)={\bm{r}}_{\ell-1}(d)-{\bm{e}}_{\ell,z_{\ell}(d)},$ 

(2)

where ${\bm{e}}_{\ell,k}$ is the $k$ -th vector in the codebook at level $\ell$ . After $M$ levels, the selected indices $(z_{1}(d),\ldots,z_{M}(d))$ form the semantic part of the identifier. Following Lee et al. (2022), the RQVAE is trained with reconstruction and quantization losses to preserve information from the document embeddings. These losses do not directly optimize downstream retrieval performance.

Collision handling. 
SID construction commonly assigns the same SID sequence to multiple documents. Following TIGER (Rajput et al., 2023), the seed program adds a unique disambiguation token $z_{M+1}(d)$ within each group of documents that were assigned the same SID sequence:

 ${\bm{z}}(d)=\bigl(z_{1}(d),\ldots,z_{M}(d),z_{M+1}(d)\bigr),\qquad L(d)=M+1.$ 

(3)

SID construction and collision handling define the generator prediction targets. Semantic tokens determine which documents share a prefix, while the final token distinguishes documents with identical semantic codes. Because changing the quantizer also changes the collision groups, we study both evolving SID construction with fixed collision handling and evolving the two components jointly.

## 3 Proxy-Guided Evolutionary Search

We mainly evolve the program that constructs SIDs and use a small generative retriever to evaluate the SIDs it produces. Each candidate program is evaluated by executing the program to obtain document-to-SID mappings, training the small generator on the relevant query–SID pairs, and measuring its retrieval performance. This feedback serves as a proxy that guides evolutionary program search without training the full 1B target generator at every step.

Executable search space. When evolving semantic indexes, the candidate program receives fixed corpus document embeddings, training query embeddings, and training relevance pairs. The program returns an integer array containing one SID per document, aligned to the input documents. The input and output interface is fixed, while the procedure implementing this mapping is mutable. For example, evolution can change the quantization process or codebook initialization, or even switch to an entirely different method. The input embeddings and relevance labels are fixed and come from the training data. The mutator LLM only has access to the SID generation code and performance feedback. The mutation prompts (Appendix B) encourage creativity but also include suggested algorithm families, such as alternative quantization and clustering methods. Test data is entirely unreachable to the mutator LLM.

For SID-only search, collision handling is held fixed. For joint SID and collision handling search, the mutable program determines how documents with identical SIDs are distinguished. We also study broader search spaces for changes to the training objective of generative retrievers, generator decoding logic, and collision-handling-only changes. Full-pipeline search is also studied, where SID construction, collision handling, generator training, and decoding can all be changed. These scopes allow us to examine how the choice of mutable component affects proxy-guided search.

Proxy generative retriever. While SID collision rate and per-codebook perplexity can describe desired properties of SIDs, they do not directly measure the SIDs’ usefulness for retrieval. Across 21 evaluated NQ320K SID programs, the collision rate logged during evolution is negatively associated with final target Recall@100 (Spearman $\rho=-0.855$ ). Although this makes collision rate a usable signal, it cannot serve as the fitness function because it is too easy to hack. For example, random assignments can produce few collisions and balanced code usage without providing meaningful semantic structure for the downstream generator. We therefore evaluate candidate programs through downstream retrieval, using a small generator to assess how well their identifiers can be learned and retrieved. Our proxy is a two-layer GPT-2 (Radford et al., 2019) model with approximately 1M non-embedding parameters (7M including token embeddings). Like the target 1B generator, it receives query text and predicts relevant documents’ SIDs using constrained decoding.

To keep search blind to test data, we randomly split each dataset’s original training relevance pairs into $\mathcal{R}_{\mathrm{proxy}}$ (two thirds) and $\mathcal{R}_{\mathrm{feedback}}$ (one third). The split is over query–document pairs, so a query with several relevant documents can contribute pairs to both sides. During search, both the candidate program and the proxy retriever $g_{\mathrm{P}}(c)$ see only $\mathcal{R}_{\mathrm{proxy}}$ , and the candidate’s fitness is

 $F_{\mathrm{P}}(c)=\operatorname{Recall@100}\bigl(g_{\mathrm{P}}(c);\mathcal{R}_{\mathrm{feedback}}\bigr).$ 

(4)

The proxy measures how well a small generator can learn and retrieve the candidate’s SIDs. Its scores do not need to match the target generator, but they must provide useful preferences among programs in the search space. Whether these preferences transfer to the target generator is an empirical question, which we explore in Section 5.2.

Program mutation and execution. 
As shown in Figure 1, we use AdaEvolve (Cemri et al., 2026) to maintain an island-based population of programs and control exploration and exploitation. At each outer step, the search controller selects a parent program and additional programs to provide context for mutation. We use gemma-4-31b-it (Gemma Team, 2026), served locally with vLLM (Kwon et al., 2023) on a single H200, to propose SEARCH/REPLACE edits within the marked mutable regions of the parent program. The proposed edits are applied to the parent, and the resulting candidate program is executed. We check that the candidate executes successfully and passes the collision gate before training the proxy. For SID-only search, we reject candidates with a collision rate above 50%, and if a candidate is accepted, we apply TIGER-style collision handling. Candidate execution is limited to two hours. When a proposal fails, the mutator receives the execution error, collision diagnostics, or timeout message and is asked to revise its edits to the parent. We allow up to 20 retries before abandoning the proposal and moving to the next outer step.

## 4 Experimental Setup

Our experiments examine whether programs selected with a small, cheap proxy improve the final 1B generator, and how this transfer depends on the component being evolved. We compare evolved programs against the seed under a fixed target training recipe, measure proxy–target agreement, and inspect the evolved programs and computational cost.

Datasets and Baselines. 
We evaluate on NQ320K (Kwiatkowski et al., 2019) and MSMARCO300K (Bajaj et al., 2016), which are both reduced collections of the original datasets, following prior work (Tay et al., 2022; Zhou et al., 2024; Zhou et al., 2023; Mekonnen et al., 2025). We also evaluate on a proprietary multilingual dataset from a large e-commerce company. The NQ320K collection contains 109,739 documents and 7,830 evaluation queries. The MSMARCO300K subset contains 319,927 documents and 808 evaluation queries. The e-commerce corpus contains millions of distinct purchased items collected over one month. We use two random seeds to downsample the purchase queries into two equal-sized training sets. Both are tested on 25,000 purchase queries from the day following that month, stratified-sampled by purchase frequency. Items are represented by title, description, and brand, with purchases as query–item relevance labels.

We use fixed Contriever (Izacard et al., 2022) embeddings for NQ and MSMARCO and mContriever embeddings for e-commerce because most of its text is not in English. Keeping the encoder fixed makes the seed and evolved SID programs operate on the same input representations, which isolates the effect of SID structure. In Table 1, the only difference between the Seed GR and SID evolution rows is the SID program (SID construction and, where evolved, collision handling). The SID construction program receives document and query embeddings together with training relevance pairs, and the generative retriever receives query text, the resulting SIDs, and relevance pairs. Search uses only the original training relevance pairs, split as in Section 3, with no synthetic or test queries. For final training, the best program by proxy fitness is rerun on all original training pairs to produce SIDs, and the target generator is trained on the same pairs. For NQ and MSMARCO only, both steps also include one synthetic query per corpus document generated by gemma-4-31b-it (Gemma Team, 2026), following prior work (Zhou et al., 2022; Zhou et al., 2023; Zhang et al., 2024; Mekonnen et al., 2025), which typically generates ten per document with a weaker generator. E-commerce uses no synthetic queries because purchase data is plentiful. All reported numbers are on the held-out test queries, which neither stage ever sees. Our primary comparison is against the generative retrieval pipeline using the seed program (Seed GR), which uses RQVAE and the fixed collision handling described in Section 2.1. We also report BM25 and Contriever performance as references rather than competitors.

Program Search and Evaluation Configuration. 
The seed program uses three residual codebooks with 256 entries each and a 256-dimensional latent representation. We train the seed RQVAE (Lee et al., 2022; Rajput et al., 2023) for 100 epochs using AdamW with learning rate $10^{-4}$ , batch size 2,048, weight decay 0.01, and commitment coefficient 0.01. The proxy is a two-layer GPT-2 decoder with approximately 1M non-embedding parameters, or 7M including token embeddings. AdaEvolve (Cemri et al., 2026) maintains the program population with 3 islands, and gemma-4-31b-it proposes mutations through vLLM (Kwon et al., 2023) on one H200. Candidate execution is limited to two hours, with up to 20 inner-loop retries. SID-only candidates must pass a 50% collision-rate gate before fixed collision handling is applied. Joint SID and collision handling candidates must pass a 5% gate on their returned SIDs. After each evolution step, the proxy GPT-2 is trained with cross-entropy loss on SID tokens and EOS for 10 epochs using AdamW with learning rate $5\times 10^{-4}$ , batch size 512, and weight decay 0.01.

We study several evolution regimes: SID-only evolves SID construction while retaining TIGER collision handling, whereas joint SID-collision updates both simultaneously. On NQ, we additionally evaluate collision evolution (fixing the seed SID program), sequential SID-collision (evolving collision handling after fixing an evolved SID constructor), objective evolution (modifying the downstream generator’s loss, distinct from the SID constructor’s loss), and full-pipeline evolution (spanning SID construction, collision handling, generator training, and decoding).

We evaluate the best program from each evolution run with gemma-3-1b-pt (Gemma Team, 2025), which we refer to as the “target” generator. We use the pretrained rather than the instruction-tuned checkpoint because it carries general pretraining knowledge without having been adapted to any downstream task, which makes it a clean base for learning the GR objective. It is always trained with AdamW for 3 epochs with learning rate $5\times 10^{-5}$ , batch size 32, weight decay 0.01, and warmup fraction 0.05. On an H200 GPU, a proxy run takes around 20 minutes, compared with five hours for the target generator. For 100 candidate evaluations, these runtimes correspond to 33 hours of proxy computation versus 500 hours of target evaluation. LLM mutation, SID construction, and failed candidate executions incur additional costs. We report the target generator’s Recall@1, Recall@5, Recall@10, Recall@100, and MRR@10, all as percentages.

## 5 Results

## 5.1 Evolved Semantic Indexes

Table 1 shows improvements over Seed GR on all three datasets. SID evolution increases Recall@100 from 85.82% to 90.57% on NQ and from 79.70% to 82.55% on MSMARCO, and raises the e-commerce Recall@100 gain over BM25 from $+49.01$ to $+50.66$ points. Recall@1 and MRR@10 also improve on all three datasets, indicating that although evolutionary search optimizes Recall@100, its benefits extend to early ranking quality rather than only retrieving additional relevant documents near the end of the list; on e-commerce, however, these early-rank gains are within one standard deviation. For NQ and MSMARCO, the best SID evolution program comes from jointly evolving SID construction and collision handling. For e-commerce, it comes from evolving SID construction only. On NQ, the seed underperforms Contriever on Recall@100, yet a different SID structure is sufficient for the final generator to outperform Contriever, while everything else, from data to the target generator and training recipe, remains the same. On MSMARCO, evolved GR exceeds BM25 at rank one, but BM25 remains stronger at larger recall cutoffs and in MRR@10. We do not claim that the evolved GR pipeline achieves state-of-the-art results, nor that GR dominates lexical or dense retrieval. Instead, we argue that evolutionary search on the semantic index can reliably improve a well-established GR pipeline whose every other component is held fixed. While improving the semantic index improves retrieval performance, it does not eliminate the limitations of the general GR pipeline. On the e-commerce dataset, where relevance is defined by purchase rather than by whether the document answers the query as in NQ and MSMARCO, GR outperforms BM25 by a large margin. This is expected because the purchased product does not necessarily contain the query terms in its title, brand, or description. Search queries are also often short and ambiguous, which makes it hard for lexical retrieval to compete with dense and generative retrieval.

## 5.2 Proxy Transfer Depends on What is Evolved

Figure 2(a) shows the optimization trajectory of the run that produced the best joint SID-collision program for NQ. The LLM-driven evolutionary search steadily improves the defined fitness score. If the evaluator were exactly faithful to the real task, the program it selects would be the best program for that task. In practice, an exact evaluator is often too expensive. In our case, the true evaluation is training the target gemma-3-1b-pt on the SIDs produced by each mutated program, which takes five hours; a 100-step search would cost nearly 500 hours, or about 21 days. In production e-commerce settings, where the generator is trained on a year of purchase data, a single training run can take weeks. This motivates a lightweight proxy evaluator, whose usefulness depends on how well its rankings agree with the downstream task. Figure 2(b) examines 21 programs from a separate joint SID-collision calibration experiment: 20 candidates sampled at random from across the optimization, plus the seed. We train both the 1M-parameter proxy and the 1B-parameter target generator on the SIDs produced by these 21 programs on NQ, without synthetic queries. Proxy and target Recall@100 have a strong positive rank correlation (Spearman $\rho=0.90$ ). The proxy need not reproduce the target’s absolute score to be useful. As long as it favors semantic index changes that also help the target generator, evolutionary search can be effective.

The contrast in Table 2 shows why this evidence cannot be extended to every mutable component. Once the generator’s training objective becomes mutable, the proxy becomes not only less informative but misleading. Objective evolution increases proxy Recall@100 from its initialization of 52.10% to 53.80%, but target Recall@100 falls to 84.46%. Full-pipeline evolution also mutates the generator’s objective. It reaches a much higher proxy score of 62.85% while reducing target Recall@100 to 76.12%. This transfer failure extends beyond the selected examples in Table 2. Across five distinct evolved programs (three objective-only and two full-pipeline programs), all five improve proxy fitness over initialization while regressing on target recall relative to Seed GR, and proxy and target Recall@100 are inversely ranked (Spearman $\rho=-0.80$ , $n=5$ ; too few programs for a significance claim). The main distinction is what the generators learn versus how they learn it. Semantic index evolution changes the SID structures shared by both generators. Objective evolution changes the optimization signal, whose effect can depend on model architecture, pretraining, and training recipe. An objective highly optimized for the 1M-parameter proxy does not necessarily transfer to the 1B-parameter target. Full-pipeline evolution, which can change both the objective and the semantic index, did not produce positive results either. Isolating per-component credit assignment during multi-component evolution is left to future work (Lin et al., 2026). The finding we are sharing here is that proxy transfer depends on the allowed search region.

As shown in Table 2, SID-only evolution improves target retrieval, while collision-only evolution leaves it close to the seed at 85.72% versus 85.82% Recall@100. Joint evolution provides the largest gain. Evolving collision handling after fixing an evolved SID constructor reaches 87.25%, with no additional mean improvement over SID-only evolution at 87.40%. Joint evolution reaches 90.57%, exceeding the sequential result by 3.32 points. This pattern is consistent with a dependence between the two procedures. SID construction determines which documents share an identifier and thus the groups within which collision handling must distinguish documents. Holding that partition fixed restricts the collision procedure’s choices, while joint search can change both the groups and the suffix targets. The NQ results suggest value in this coordinated design, although different search budgets, gates, and selected programs prevent attributing the gain to coordination alone.

## 6 The Evolved SID Program

We examine the joint SID and collision handling program evolved on NQ, which reaches a proxy Recall@100 of 64.39% and raises target Recall@100 from 85.82% to 90.57% (Program ). The program retains the RQVAE structure and the four-token SID of Equation 3, with $M=3$ semantic tokens and one collision suffix. Its changes mainly concern how the semantic codes are assigned and trained, and how the suffix is constructed.

Direction-based residual quantization. The evolved program selects the code with maximum cosine similarity to the current residual, replacing the squared-Euclidean assignment in Equation 2. It still subtracts the selected, unnormalized code vector. Codebook vector lengths therefore affect the residual passed to the next level, even though selection depends only on direction. This rule is used during both index training and final SID construction. The program also doubles each codebook from 256 to 512 entries while retaining the 256-dimensional latent representation.

Training the index with query information. The seed program learns the index using only document reconstruction. The evolved program adds query-based supervision by encouraging each reconstructed document embedding to align with its relevant training queries. Specifically, for each document $d$ , the embeddings of its associated training queries are averaged and $\ell_{2}$ -normalized to form a query target ${\bm{t}}(d)$ . If $d$ has no associated training query, then ${\bm{t}}(d)=\mathbf{0}$ . Let $\hat{{\bm{x}}}(d)$ denote the RQVAE decoder’s reconstruction of the document embedding from its quantized latent, and let $\mathcal{N}$ denote $\ell_{2}$ normalization. For a document minibatch $\mathcal{B}$ , the evolved program adds the alignment loss

 $\mathcal{L}_{\mathrm{align}}=\frac{1}{|\mathcal{B}|}\sum_{d\in\mathcal{B}}\left[1-\left\langle\mathcal{N}(\hat{{\bm{x}}}(d)),{\bm{t}}(d)\right\rangle\right].$ 

(5)

This loss encourages each reconstructed document embedding to point in the same direction as the average query embedding associated with that document. It is weighted by 0.8 and optimized together with the reconstruction, quantization, and codebook regularization (entropy and orthogonality) losses. The program also adds training stabilizers: a data-based initialization of the first codebook, EMA codebook updates, periodic dead-code revival, learning-rate warmup, and gradient clipping. The query-alignment idea resonates with existing work (Zhang et al., 2025; Zeng et al., 2024; Nian et al., 2025) showing that semantic embeddings and indexing should be aware of the downstream task, though the formulations differ.

Geometry-based collision handling. The seed assigns disambiguation tokens to documents with identical semantic codes in document ID order, and appends a suffix to every document. The evolved program instead gives non-colliding documents a fixed suffix of 0. Within each collision group, it averages the normalized document embeddings and assigns suffixes $1,2,\ldots$ in order of decreasing cosine similarity to that centroid. Small suffix values therefore represent relatively central documents across different groups, giving the suffix a shared interpretation that TIGER-style collision handling lacks.

## 6.1 Other Evolved Programs

The best NQ SID program adds relevance supervision to reconstruction. Other evolved programs also leverage queries and relevance labels, but in very different formulations. Some MSMARCO SID programs train document and query projections on relevance pairs, then freeze the document encoder and fit residual K-means. Some NQ programs remove neural index training entirely. One example (Program ) mixes normalized document embeddings with the mean of normalized relevant query embeddings, with weights 0.7 for the document and 0.3 for the queries, then applies residual K-means. Related programs from the e-commerce training sets incorporate query embeddings into centroid updates. Relevance information can therefore shape the vectors or the clustering procedure without a reconstruction decoder. Every program above was proposed by a locally servable 31B model, which establishes that evolutionary search over GR components can be carried out without a proprietary LLM API. We leave the use of state-of-the-art proprietary LLMs to future work.

## 7 Related Work

Generative Retrieval. DSI and NCI were the first to formulate retrieval as document identifier generation (Tay et al., 2022; Wang et al., 2022). Since then, the generative retrieval community has improved many aspects of the pipeline. TIGER (Rajput et al., 2023) constructs SIDs through residual quantization. GenRet and ASI (Sun et al., 2023; Yang et al., 2023) jointly learn indexing and retrieval. RIPOR and MERGE (Zeng et al., 2024; Zhang et al., 2025) incorporate relevance supervision into identifier construction. DDRO directly optimizes document relevance (Mekonnen et al., 2025). GLEN (Lee et al., 2023) addresses SID collisions, and TSGen (Zhang et al., 2024) introduces term-set identifiers with permutation-invariant decoding. Our work focuses on making automatic semantic index evolution feasible and shows that index-related improvements transfer more consistently than changes to the generator’s training objective.

Evolutionary program search and proxy evaluation. FunSearch and AlphaEvolve use a coding LLM to propose code edits to candidate programs, managed by an island-based evolutionary search algorithm (Romera-Paredes et al., 2024; Novikov et al., 2025). Subsequent work improves search through adaptive population management in AdaEvolve (Cemri et al., 2026), component-level attribution feedback in Lin et al. (2026), evolving search strategies in EvoX (Liu et al., 2026b), and coordinated multi-agent discovery in CORAL (Qu et al., 2026) and SwarmResearch (Virk et al., 2026). In information retrieval, RankEvolve (Nian et al., 2026a) applies LLM-driven evolutionary search to discover lexical ranking algorithms, where candidates can be evaluated directly without training a neural generator. Proxy evaluation also has established precedents, such as AutoML-Zero (Real et al., 2020), which searches learning algorithms on proxy tasks, and SESS (Nian et al., 2026b), which approximates full evaluation via submodular subset selection in prompt optimization. Lion (Chen et al., 2023) addresses generalization from small search tasks to larger workloads. ShinkaEvolve (Lange et al., 2025) demonstrates transfer of evolved training losses to larger models.

## 8 Conclusion

In this paper, we presented a framework for improving generative retrieval through evolutionary search over executable components, using a locally served 31B LLM as the mutator and a tiny 1M-parameter retrieval proxy for candidate evaluation to make evolution practical. Across three retrieval datasets, proxy-selected semantic index programs improve the overall generative retrieval pipeline on the target 1B generator, demonstrating the value of automatically refining SID construction and collision handling. Our component study reveals that evolve-time improvements transfer more consistently for semantic indexes than for changes to the generator training objective. The effectiveness of proxy-guided evolutionary search therefore depends on what is being optimized, and correlation with the target system must be established for the chosen search space. These findings support semantic index evolution as a practical direction for automated generative retrieval system design and motivate further study of evaluators that remain informative across model scales and generative retrieval components.

## Appendix A Seed and Evolved SID Programs

Programs are reproduced verbatim from the search, including comments and docstrings written by the mutator. Docstrings inherited from the seed (e.g., “codebook 256” in Program ) may therefore not describe the evolved code.

## A.1 Seed RQVAE with Fixed Collision Handling

⬇

"""Evolve SID generation with de-collision blended IN-BAND.

The mutator owns ONE function: ‘generate_sids(query_emb, doc_emb, qrel_pairs, doc_ids, *, device)‘.

Its return is ‘(n_docs, L) int32‘ with **every row unique** — no post-hoc de-collision runs.

The scorer rejects any candidate whose row-uniqueness is not

essentially perfect (< 5% collision) — the mutator must produce good SIDs AND

resolve collisions in the same pass.

"""

import numpy as np

import torch

import torch.nn as nn

import torch.nn.functional as F

torch.manual_seed(0)

def generate_sids(query_emb, doc_emb, qrel_pairs, doc_ids, *, device):

 """

 Args:

 query_emb (torch.Tensor): Shape (n_queries, 768), float32.

 doc_emb (torch.Tensor): Shape (n_docs, 768), float32.

 qrel_pairs (torch.Tensor): (N, 2) long — (q_row, d_row).

 doc_ids (Sequence[str]): length n_docs — corpus doc ids in row order.

 Passed in so that decollision policies can use stable per-doc ties

 (see the TIGER-style append at the tail of the seed body).

 device (str): "cuda" or "cpu".

 Returns:

 np.ndarray: Shape (n_docs, L) with dtype=int32. **Every row must be unique.**

 The scorer rejects candidates whose collision rate is > 5%.

 """

# EVOLVE-BLOCK-START

 """

 Seed baseline:

 1. Train an RQ-VAE (3 layers, codebook 256) on doc embeddings.

 2. Extract raw codes -> (n_docs, 3) int32 (may collide).

 3. Append ONE disambiguation token per collision group (TIGER-style)

 -> (n_docs, 4) int32, all rows unique.

 """

 NUM_LAYERS = 3

 CODEBOOK_SIZE = 256

 LATENT_DIM = 256

 HIDDEN_MULT = 4

 COMMITMENT_COST = 0.01

 LR = 1e-4

 WEIGHT_DECAY = 0.01

 CODEBOOK_INIT_STD = 0.02

 EPOCHS = 100

 BATCH_SIZE = 2048

 RECON_WEIGHT = 1.0

 VQ_WEIGHT = 1.0

 dev = torch.device(device if torch.cuda.is_available() else "cpu")

 doc_tensor = torch.as_tensor(doc_emb, device=dev, dtype=torch.float32)

 x_all = F.normalize(doc_tensor, p=2, dim=-1)

 n_docs, in_dim = x_all.shape

 hidden_dim = HIDDEN_MULT * in_dim

 class _Encoder(nn.Module):

 def __init__(self):

 super().__init__()

 self.net = nn.Sequential(

 nn.Linear(in_dim, hidden_dim), nn.GELU(),

 nn.Linear(hidden_dim, hidden_dim), nn.GELU(),

 nn.Linear(hidden_dim, LATENT_DIM)

 )

 def forward(self, x): return self.net(x)

 class _Decoder(nn.Module):

 def __init__(self):

 super().__init__()

 self.net = nn.Sequential(

 nn.Linear(LATENT_DIM, hidden_dim), nn.GELU(),

 nn.Linear(hidden_dim, hidden_dim), nn.GELU(),

 nn.Linear(hidden_dim, in_dim)

 )

 def forward(self, z): return self.net(z)

 class _ResidualVQ(nn.Module):

 def __init__(self):

 super().__init__()

 self.codebooks = nn.ModuleList([

 nn.Embedding(CODEBOOK_SIZE, LATENT_DIM) for _ in range(NUM_LAYERS)

 ])

 for emb in self.codebooks:

 emb.weight.data.normal_(mean=0.0, std=CODEBOOK_INIT_STD)

 def forward(self, z_e):

 residual = z_e

 quantized_sum = torch.zeros_like(z_e)

 total_vq_loss = z_e.new_zeros(())

 for codebook in self.codebooks:

 flat_r = residual.view(-1, residual.size(-1))

 distances = (

 flat_r.pow(2).sum(dim=1, keepdim=True)

 + codebook.weight.pow(2).sum(dim=1)

 - 2 * torch.matmul(flat_r, codebook.weight.t())

 )

 idx = distances.argmin(dim=1).unsqueeze(1)

 encodings = torch.zeros(idx.size(0), codebook.num_embeddings, device=z_e.device)

 encodings.scatter_(1, idx, 1)

 quantized = torch.matmul(encodings, codebook.weight).view(z_e.shape)

 quantized_sum = quantized_sum + quantized

 e_loss = F.mse_loss(quantized.detach(), residual)

 q_loss = F.mse_loss(quantized, residual.detach())

 total_vq_loss = total_vq_loss + q_loss + COMMITMENT_COST * e_loss

 residual = residual - quantized

 z_q = z_e + (quantized_sum - z_e).detach()

 return z_q, total_vq_loss

 @torch.no_grad()

 def encode(self, z_e):

 residual = z_e

 codes = []

 for codebook in self.codebooks:

 distances = (

 residual.pow(2).sum(dim=1, keepdim=True)

 + codebook.weight.pow(2).sum(dim=1)

 - 2 * torch.matmul(residual, codebook.weight.t())

 )

 idx = torch.argmin(distances, dim=1)

 codes.append(idx)

 residual = residual - codebook(idx)

 return torch.stack(codes, dim=1)

 class _VQVAE(nn.Module):

 def __init__(self):

 super().__init__()

 self.encoder = _Encoder()

 self.vq = _ResidualVQ()

 self.decoder = _Decoder()

 def forward(self, x):

 z_e = F.normalize(self.encoder(x), dim=-1)

 z_q, vq_loss = self.vq(z_e)

 x_recon = self.decoder(z_q)

 return x_recon, vq_loss

 @torch.no_grad()

 def codes(self, x):

 z_e = F.normalize(self.encoder(x), dim=-1)

 return self.vq.encode(z_e)

 model = _VQVAE().to(dev)

 no_decay_keys = ("bias", "LayerNorm.weight")

 all_params = list(model.named_parameters())

 optim = torch.optim.AdamW([

 {"params": [p for n, p in all_params if not any(k in n for k in no_decay_keys)], "weight_decay": WEIGHT_DECAY},

 {"params": [p for n, p in all_params if any(k in n for k in no_decay_keys)], "weight_decay": 0.0},

 ], lr=LR)

 # Training

 for epoch in range(EPOCHS):

 perm = torch.randperm(n_docs)

 model.train()

 for start in range(0, n_docs, BATCH_SIZE):

 idx = perm[start:start + BATCH_SIZE]

 batch = x_all[idx].to(dev, non_blocking=True)

 x_recon, vq_loss = model(batch)

 recon_loss = F.mse_loss(x_recon, batch)

 loss = RECON_WEIGHT * recon_loss + VQ_WEIGHT * vq_loss

 optim.zero_grad()

 loss.backward()

 optim.step()

 model.eval()

 raw_codes = np.zeros((n_docs, NUM_LAYERS), dtype=np.int32)

 with torch.no_grad():

 for start in range(0, n_docs, BATCH_SIZE):

 1. Train an RQ-VAE (3 layers, codebook 256) on doc embeddings.

 2. Extract raw codes -> (n_docs, 3) int32 (may collide).

 3. Append ONE disambiguation token per collision group (TIGER-style)

 NUM_LAYERS = 3

 CODEBOOK_SIZE = 512

 LATENT_DIM = 256

 HIDDEN_MULT = 4

 LR = 1e-4

 WEIGHT_DECAY = 0.01

 quantized_sum = torch.zeros_like(z_e)

 total_vq_loss = z_e.new_zeros(())

 for codebook in self.codebooks:

 flat_r = residual.view(-1, residual.size(-1))

 # Use cosine similarity for assignment to improve semantic clustering

 # flat_r: (B, D), codebook.weight: (C, D)

 norm_r = F.normalize(flat_r, p=2, dim=-1)

 norm_w = F.normalize(codebook.weight, p=2, dim=-1)

 sims = torch.matmul(norm_r, norm_w.t()) # (B, C)

 idx = sims.argmax(dim=1).unsqueeze(1)

 encodings = torch.zeros(idx.size(0), codebook.num_embeddings, device=z_e.device)

 encodings.scatter_(1, idx, 1)

 quantized = torch.matmul(encodings, codebook.weight).view(z_e.shape)

 quantized_sum = quantized_sum + quantized

 e_loss = F.mse_loss(quantized.detach(), residual)

 q_loss = F.mse_loss(quantized, residual.detach())

 # Entropy regularizer with temperature to encourage better codebook distribution

 # sims: (B, CODEBOOK_SIZE) on dev

 probs = F.softmax(sims / 0.5, dim=-1)

 # Corrected entropy: sum over C, then mean over B

 entropy_loss = -torch.mean(torch.sum(probs * torch.log(probs + 1e-6), dim=1))

 # Orthogonality loss to prevent codebook collapse: sum of squared dot products of normalized weights

 # norm_w: (CODEBOOK_SIZE, LATENT_DIM) on dev

 ortho_loss = torch.sum(torch.matmul(norm_w, norm_w.t())**2) - CODEBOOK_SIZE

 total_vq_loss = total_vq_loss + q_loss + (COMMITMENT_COST * 2.0) * e_loss - 0.05 * entropy_loss + CODEBOOK_ORTHO_WEIGHT * ortho_loss

 residual = residual - quantized

 z_q = z_e + (quantized_sum - z_e).detach()

 return z_q, total_vq_loss

 @torch.no_grad()

 def encode(self, z_e):

 residual = z_e

 codes = []

 for codebook in self.codebooks:

 # Consistent cosine assignment for inference

 norm_r = F.normalize(residual, p=2, dim=-1)

 norm_w = F.normalize(codebook.weight, p=2, dim=-1)

 idx = torch.matmul(norm_r, norm_w.t()).argmax(dim=1)

 codes.append(idx)

 residual = residual - codebook(idx)

 return torch.stack(codes, dim=1)

 def __init__(self):

 super().__init__()

 self.encoder = _Encoder()

 self.vq = _ResidualVQ()

 self.decoder = _Decoder()

 z_q, vq_loss = self.vq(z_e)

 x_recon = self.decoder(z_q)

 return x_recon, vq_loss

 return self.vq.encode(z_e)

 doc_targets = torch.zeros((n_docs, in_dim), device=dev)

import torch

import torch.nn as nn

import torch.nn.functional as F

def generate_sids(query_emb, doc_emb, qrel_pairs, *, device):

 """

 Args:

 query_emb (np.ndarray): Shape (307358, 768), dtype=float32.

 Dense embeddings for unique queries.

 doc_emb (np.ndarray): Shape (109739, 768), dtype=float32.

 Dense embeddings for all documents in the corpus.

 qrel_pairs (np.ndarray): Shape (N_pairs, 2), dtype=int32.

 Index mapping pairs connecting queries to relevant documents:

 - ‘qrel_pairs[:, 0]‘: Row indices into ‘query_emb‘

 - ‘qrel_pairs[:, 1]‘: Row indices into ‘doc_emb‘

 Example usage for contrastive/alignment loss:

 ‘q_vecs = torch.from_numpy(query_emb[qrel_pairs[:, 0]])‘

 ‘d_vecs = torch.from_numpy(doc_emb[qrel_pairs[:, 1]])‘

 device (str): Execution device ("cuda" or "cpu").

 Returns:

 np.ndarray: Shape (109739, NUM_LAYERS) with dtype=int32,

 containing discrete codes in range [0, CODEBOOK_SIZE) for each document.

 """

# EVOLVE-BLOCK-START

 """

 Residual K-Means (RQ-KMeans) Paradigm.

 Successively quantizes the residue of the previous layer.

 This creates a coarse-to-fine hierarchical SID that significantly

 reduces collision rates by utilizing the full codebook capacity.

 """

 NUM_LAYERS = 3

 CODEBOOK_SIZE = 256

 KMEANS_ITERS = 15

 dev = torch.device(device if torch.cuda.is_available() else "cpu")

 # doc_tensor shape: (n_docs, dim), device: dev

 doc_tensor = torch.as_tensor(doc_emb, device=dev, dtype=torch.float32)

 x_all = F.normalize(doc_tensor, p=2, dim=-1)

 n_docs, dim = x_all.shape

 # Task-Aware Alignment for Layer 1

 x_first_layer = x_all.clone()

 if qrel_pairs.size(0) > 0:

 q_tensor = torch.as_tensor(query_emb, device=dev, dtype=torch.float32)

 q_tensor = F.normalize(q_tensor, p=2, dim=-1)

 q_idx = torch.as_tensor(qrel_pairs[:, 0], device=dev)

 d_idx = torch.as_tensor(qrel_pairs[:, 1], device=dev)

 q_sum = torch.zeros((n_docs, dim), device=dev)

 q_cnt = torch.zeros((n_docs, 1), device=dev)

 q_sum.index_add_(0, d_idx, q_tensor[q_idx])

 q_cnt.index_add_(0, d_idx, torch.ones((qrel_pairs.size(0), 1), device=dev))

 mask = (q_cnt > 0).squeeze()

 avg_q = q_sum / torch.clamp(q_cnt, min=1.0)

 x_first_layer[mask] = 0.7 * x_all[mask] + 0.3 * avg_q[mask]

 x_first_layer = F.normalize(x_first_layer, p=2, dim=-1)

 def run_kmeans_residual(data, k, iters=15):

 n_samples = data.size(0)

 if n_samples <= k:

 return torch.arange(n_samples, device=dev), data

 indices = torch.randperm(n_samples, device=dev)[:k]

 centroids = data[indices].clone()

 labels = torch.zeros(n_samples, dtype=torch.long, device=dev)

 for _ in range(iters):

 dist = torch.cdist(data, centroids)

 labels = dist.argmin(dim=1)

 new_centroids = torch.zeros_like(centroids)

 for i in range(k):

 mask = (labels == i)

 if mask.any():

 new_centroids[i] = data[mask].mean(dim=0)

 else:

 new_centroids[i] = data[torch.randint(0, n_samples, (1,), device=dev)]

 centroids = new_centroids

 return labels, centroids

 all_codes = torch.zeros((n_docs, NUM_LAYERS), dtype=torch.long, device=dev)

 current_residual = x_first_layer

 for layer in range(NUM_LAYERS):

 labels, centroids = run_kmeans_residual(current_residual, CODEBOOK_SIZE, iters=KMEANS_ITERS)

 all_codes[:, layer] = labels

 # Residual: R_{l+1} = Normalize(R_l - Centroid_{label})

 assigned_centroids = centroids[labels]

 current_residual = current_residual - assigned_centroids

 current_residual = F.normalize(current_residual, p=2, dim=-1)

 # Status tracking placeholder

 print(f"Residual K-Means Complete | Layers: {NUM_LAYERS} | Codebook: {CODEBOOK_SIZE}^3")

 all_codes = all_codes.cpu().numpy().astype(np.int32)

 assert isinstance(all_codes, np.ndarray), f"Expected np.ndarray output, got {type(all_codes)}"

 assert len(all_codes) == len(doc_emb), f"Doc count mismatch! Expected {len(doc_emb)} rows, got {len(all_codes)}"

 assert not np.isinf(all_codes).any(), "Output contains Infinite values!"

## Task

You are an expert AI researcher discovering a better Semantic ID (SID) generation algorithm for generative retrieval. Unlike the classic setup, **de-collision is IN-BAND** — your ‘generate_sids‘ returns SIDs that are already unique row-by-row. Your goal is to propose code modifications WITHIN the ‘# EVOLVE-BLOCK-START‘ and ‘# EVOLVE-BLOCK-END‘ enclosed regions to minimize SID collision rate at the source, maximize codebook perplexity, and most importantly, maximize downstream generator Recall@100 on a held-out test split when trained on query-to-SID supervision.

## You must use clear and fundamental reasoning. What makes the SID good for generative retrieval?

- **Hierarchical Structure:** The SID should preserve coarse-to-fine hierarchy as the generator (a language model) excel at coarse-to-fine reasoning.

- **Similar yet Distinguishable:** A good SID must balance clustering (generalization) with uniqueness (discrimination). Similar items should share early tokens. But their SID should also be meaningfully distinguishable.

- **Task Alignment:** A good SID reflects the retrieval task dynamics, not just raw semantic content. Content semantics is not the same as query relevance.

- **Balanced Codebook:** At inference time, the generator uses trie-constrained decoding with beam search. Good SID should produce a well-balanced prefix tree.

## De-collision is now part of your job

The returned array is used AS-IS for training and retrieval — the scorer runs

no post-hoc ‘decollide_sids‘. **Every row must be unique.** The scorer rejects

candidates with > 5% collision, but that ceiling is a soft safety net — an

E3 candidate should aim for a collision rate near zero. In-band de-collision

is the whole point.

Two axes to think about:

- **When**: resolve collisions in-band during quantization (avoid producing

 collisions in the first place — balanced clustering, split-on-collision,

 Gumbel jitter on tied assignments) OR after quantization (append tail

 tokens to disambiguate residual collisions). Both are valid; hybrid is often

 best — reduce the raw collision rate first, then patch what’s left.

- **How the disambiguating suffix is ORDERED**: a good suffix places

 semantically-similar collided docs near each other in the tail token space,

 so the generator learns a smooth extension from the coarse prefix. Recent

 work explores: rank by doc_emb similarity within group, LSH bits of the

 residual vector as the tail, content-hash bits, adaptive depth (only extend

 the sequence for docs that actually collided — TIGER’s baseline appends to

 everyone; BONSAI’s variable-length trie only appends where needed).

Beam search still uses the trie: keep the tail short and structured. A tail

of 1 token per doc (as in the seed) is the cheapest option; longer tails

are fine if they aid disambiguation but must stay bounded.

## Memory scale (hard constraint)

The corpus can hold up to ~320 K documents and up to ~370 K training queries (MSMARCO scale; NQ is ~110 K docs / ~310 K queries). **NEVER allocate an ‘(n_queries, n_docs)‘ or ‘(n_docs, n_docs)‘ dense tensor** — that is hundreds of GB and OOMs immediately. Safe patterns for supervised / contrastive / task-aligned quantization:

- iterate ‘qrel_pairs‘ in mini-batches (a few thousand pairs at a time),

- sample K negatives per positive instead of scoring the full corpus,

- compute distance-to-codebook (‘n_docs × codebook_size‘, safe: ‘320K × 256 ≈ 320MB‘).

Anything you allocate that exceeds a few GB is a red flag. If unsure, chunk it.

## Existing known ideas to use, combine, and evolve

You can explore entirely different paradigms:

- **Task-Aware / Supervised Quantization:** Use ‘qrels‘ and ‘query_emb‘ in your loss function (e.g., contrastive loss), to make the SID aligned with the downstream task.

- **Better Initialization:** Initialize codebook weights based on existing document embeddings can prevent codebook collapse. For example, KMeans or KMeans++ initialization.

- **Product Quantization (PQ) & Optimized PQ (OPQ):** Instead of residual quantization on the full vector, split the vector into sub-vectors and apply KMeans/VQ to each slice independently.

- **Non-Neural Clustering:** Residual Quantized K-Means (RQ-KMeans), Hierarchical K-Means,

## Candidate paradigms (pick ONE that is far from the parent)

- **Product Quantization (PQ):** Split the doc embedding into M sub-vectors of dim D/M; run KMeans on each slice independently; SID is the concatenation of M cluster indices. No residual, no neural encoder.

- **Optimized PQ (OPQ):** Learn a rotation R before PQ so the sub-vector splits are optimally decorrelated.

- **Hierarchical K-Means:** Recursively cluster doc embeddings. First-level cluster -> partition -> recursively cluster within each partition. Each level contributes one SID token.

- **Residual K-Means (RQ-KMeans, non-neural):** Like RQ-VAE but pure KMeans on residuals. No autoencoder, no gradients — just KMeans passes on residual vectors.

- **Task-Aware Supervised Quantization:** Train a small model with a contrastive loss using ‘qrels‘ and ‘query_emb‘ so the SID is retrieval-aligned rather than reconstruction-aligned. Contrastive loss on ‘query_emb[q_idx]‘ vs quantized ‘doc_emb[d_idx]‘ from qrel pairs.

- **LSH-Style Random Projections + Quantization:** Random projection into low-dim space then binary/ternary quantization; can be layered for hierarchy.

- **Balanced Clustering (constrained KMeans):** Explicitly enforce roughly equal cluster sizes at each layer to maximize codebook perplexity. Naturally reduces collision rate.

- **DiffQ / Gumbel-Softmax VQ:** Replace argmin quantization with differentiable Gumbel-Softmax assignments and temperature annealing.

- **Adaptive-depth / variable-length SIDs (BONSAI-style):** Grow the SID only where collisions occur. Easy docs get short SIDs; hard docs get longer ones. Trie stays balanced without a uniform tail token.

- **In-band split-on-collision:** After each quantization layer, docs sharing a code that exceeds a capacity limit are re-assigned to a fresh sub-codebook (or perturbed and re-quantized). Zero residual collisions by construction.

- **Content-hash / LSH suffix:** Replace the rank-based tail with a hash of the residual vector or of ‘doc_text[i]‘. Semantically-similar colliders end up in adjacent tail codes without needing a separate ordering step.
