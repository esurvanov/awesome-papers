Abstract

Feed-forward 3D Gaussian Splatting (FF3DGS) reconstructs 3D scenes from images in a single forward pass, making it well-suited to applications that must operate within limited resource budgets. To further improve its practicality, recent budget-controllable FF3DGS methods allow the number of Gaussians to be adjusted at inference, so that the output meets a given storage limit or rendering-latency constraint. However, these methods overlook the cost of inference itself: to produce a representation with the target number of Gaussians, they first predict a dense set of Gaussians and then prune or select from it, requiring nearly constant latency and peak memory regardless of the budget. We therefore propose RLSplat, a resource-linear budget-controllable FF3DGS framework whose representation size, inference latency, and peak memory all decrease linearly as the Gaussian budget is reduced. Instead of pruning or selection, RLSplat learns a Gaussian allocation policy that distributes the budget across local scene regions, so that exactly the requested number of Gaussians is generated. These Gaussians are then refined through resource-linear Gaussian decoding, in which each Gaussian attends only to nearby Gaussians found via an efficient hierarchical neighbor search, so that the decoding cost decreases linearly with fewer Gaussians. In zero-shot evaluation, RLSplat outperforms prior budget-controllable methods at every budget, surpassing the strongest baseline even with 4 $\times$ fewer Gaussians, while running up to 4.1 $\times$ faster with 9.6 $\times$ less peak memory at low budgets. Code is available at https://github.com/mlvlab/RLSplat.

## 1 Introduction

3D Gaussian Splatting (3DGS) (Kerbl et al., 2023) has become a leading representation for photorealistic, real-time novel view synthesis, supporting applications from AR/VR (Qian et al., 2024; Jiang et al., 2024) to robotics (Keetha et al., 2024; Matsuki et al., 2024) and digital content creation (Tang et al., 2024; Chen et al., 2024b). Its explicit form further allows it to serve as a 3D scene representation for downstream models, such as 3D vision-language models (Li et al., 2025; Thai et al., 2025). Since per-scene optimization of 3DGS takes minutes to hours and requires many calibrated views, feed-forward 3DGS (FF3DGS) methods instead predict Gaussians in a single forward pass (Charatan et al., 2024; Chen et al., 2024a), and recent variants even operate directly on uncalibrated images (Jiang et al., 2025). Owing to this fast and readily available reconstruction, FF3DGS has become a practical choice for applications that build 3D scene representations on the fly.

Early FF3DGS methods (Charatan et al., 2024; Chen et al., 2024a; Ye et al., 2025) simplify the problem by allocating a fixed number of Gaussians to each input pixel, which allows the feed-forward network to be trained effectively. However, this pixel-aligned design produces many redundant Gaussians, since Gaussians from overlapping views become increasingly redundant as more views are added. To address this redundancy, query-based methods (An et al., 2026; Itkin et al., 2026) decode a fixed set of learnable query tokens into Gaussians. Yet neither approach can adjust the number of Gaussians without retraining. This lack of controllability makes it difficult to adapt to the diverse resource budgets encountered in real-world deployment. To address this, recent works have proposed Gaussian budget-controllable methods. Given a Gaussian budget $B$ , EcoSplat (Park et al., 2026) first predicts one Gaussian per pixel and keeps the $B$ Gaussians with the highest opacity. $\text{F}^{4}$ Splat (Kim et al., 2026) instead predicts Gaussians at multiple scales and selects the $B$ Gaussians. However, these methods overlook the computational cost of inference itself. Both methods first predict a much larger set of candidate Gaussians before reducing them to $B$ , so their inference latency and peak memory remain nearly constant regardless of the budget, as shown in Fig. 1(b) and (c).

We therefore propose RLSplat, a budget-controllable FF3DGS framework that is resource-linear: both its representation size and inference cost scale linearly with the budget $B$ . Given uncalibrated images and a budget $B$ , a geometry backbone encodes the images into anchor tokens, each representing a local 3D region of the scene. To obtain a compact representation, we formulate Gaussian generation as an allocation problem rather than pruning or selection: we predict how many Gaussians to assign to each anchor’s region, summing to $B$ . Since these discrete allocations are non-differentiable and can only be evaluated by rendering the resulting Gaussians, we model this prediction as a Gaussian allocation policy and train it with policy optimization, using Group Sequence Policy Optimization (GSPO) (Zheng et al., 2025) with rendering quality as the reward. Given the allocation, each anchor token spawns as many Gaussian tokens as its allocated count, yielding a total of $B$ Gaussian tokens. To efficiently decode these tokens into the final Gaussians, we introduce a resource-linear decoder. It refines each Gaussian token through local cross-attention over its $K_{\rm{gs}}$ nearest Gaussian tokens, which we find with an efficient hierarchical neighbor search. Whereas global self-attention over all $B$ tokens costs $\mathcal{O}(B^{2})$ , each token here attends to only $K_{\rm{gs}}$ neighbors, so the decoding cost is $\mathcal{O}(BK_{\rm{gs}})$ and scales linearly with the Gaussian budget (Fig. 1(c)).
As a result, RLSplat achieves higher quality than prior budget-controllable methods at every budget (Fig. 1(a)), while its peak memory and latency decrease with the budget. At 2K Gaussians, it achieves higher PSNR than F4Splat while using 9.6 $\times$ less peak memory (Fig. 1(b)) and running 4.1 $\times$ faster (Fig. 1(c)).

In summary, our contributions are as follows:

• 

We identify that existing budget-controllable FF3DGS methods control only the size of the output, not the cost of producing it, and introduce RLSplat, a resource-linear FF3DGS framework in which the number of Gaussians, inference latency, and peak memory all decrease linearly as the budget $B$ is reduced.

• 

We formulate Gaussian generation as an allocation problem and learn a Gaussian allocation policy via policy optimization that places exactly $B$ Gaussians where the scene needs them, together with a resource-linear decoder whose cost decreases linearly as the budget decreases through local cross-attention and an efficient hierarchical neighbor search.

• 

RLSplat consistently outperforms prior budget-controllable methods across all budgets.
At a budget of 2K Gaussians, it improves PSNR by 0.9 dB over F4Splat while using 9.6 $\times$ less peak memory and running 4.1 $\times$ faster.

## 2 Related Work

Feed-Forward 3D Gaussian Splatting.
3D Gaussian Splatting (3DGS) (Kerbl et al., 2023) represents a scene with explicit Gaussian primitives and achieves real-time rendering, but requires time-consuming per-scene optimization from many calibrated views. Feed-forward 3DGS (FF3DGS) methods instead predict Gaussians in a single forward pass, from a single image (Szymanowicz et al., 2024) or from a few posed views (Charatan et al., 2024; Chen et al., 2024a; Xu et al., 2025; Zhang et al., 2024). Building on 3D foundation models (Wang et al., 2024; Leroy et al., 2024; Wang et al., 2025), recent methods further remove the need for known camera poses (Ye et al., 2025; Smart et al., 2024; Huang and Mikolajczyk, 2025; Jiang et al., 2025). Most of these methods predict one Gaussian per pixel or per voxel, so the number of Gaussians is determined by the input resolution and the number of views rather than by the scene content. This leads to redundant Gaussians in overlapping and textureless regions, and the number of Gaussians cannot be specified directly.

Compact and Gaussian budget-controllable FF3DGS.
For per-scene 3DGS, many works aim to represent a scene with fewer Gaussians without sacrificing quality, either by pruning redundant Gaussians (Fan et al., 2024; Lee et al., 2024; Papantonakis et al., 2024) or by deciding where to place Gaussians under a fixed or constrained budget during densification (Fang and Wang, 2024; Mallick et al., 2024; Kheradmand et al., 2024). These methods, however, rely on iterative per-scene optimization. In FF3DGS, C3G (An et al., 2026) and GlobalSplat (Itkin et al., 2026) decode a fixed set of learnable query tokens into compact sets of Gaussians, whose size is determined by the architecture. EcoSplat (Park et al., 2026) and $\text{F}^{4}$ Splat (Kim et al., 2026) instead accept a target count at inference, by keeping the Gaussians with the highest budget-conditioned opacity and by selecting one of multiple scales per region, respectively; both derive the output from a dense set of candidates. ZipSplat (Veicht et al., 2026), developed concurrently with our work, controls the number of Gaussians by clustering visual tokens at inference. In contrast, we learn to allocate exactly the requested number of Gaussians and decode only those, so that our inference cost scales with the budget.

Policy optimization.
Policy gradient methods (Williams, 1992; Schulman et al., 2017) optimize non-differentiable, discrete decisions from a scalar reward, and have been applied to generative vision models, e.g., to align diffusion models with reward functions (Black et al., 2024). Group-relative variants such as GRPO (Shao et al., 2024) and GSPO (Zheng et al., 2025) remove the need for a learned value function by normalizing rewards within a group of samples, and have become standard for fine-tuning large language models. In particular, GSPO defines the importance ratio from the likelihood of the whole sequence rather than of individual tokens, and clips it at the sequence level. We adopt this approach to learn Gaussian allocation, treating an allocation as a sequence of $B$ Gaussians and using rendering quality as the reward.

## 3 Method

We present RLSplat, a feed-forward 3DGS framework whose Gaussian count and inference cost are both controlled by a single budget $B$ . Rather than pruning or selecting from a dense set of Gaussians, RLSplat formulates Gaussian generation as allocation: a Gaussian allocation policy decides how many Gaussians each local region of the scene receives (Sec. 3.2), and a resource-linear decoder generates the allocated Gaussians and efficiently refines them with local cross-attention (Sec. 3.3). We begin with an overview (Sec. 3.1) and conclude with the training procedure (Sec. 3.4).

Figure 2: Overview of RLSplat.
Given uncalibrated context images, the geometry backbone predicts camera parameters and extracts anchor tokens $\{\mathbf{a}_{n}\}$ representing local 3D regions. The Gaussian allocation policy distributes the budget $B$ across anchors, assigning $k_{n}$ Gaussians to each anchor with $\sum k_{n}=B$ . Each anchor then spawns $k_{n}$ Gaussian tokens, which are decoded into $B$ Gaussians and locally refined using hierarchical neighbor search.

## 3.1 Overview of RLSplat 

Given $V$ uncalibrated context images $\{\mathbf{I}_{i}\}_{i=1}^{V}$ and a target Gaussian budget $B$ , RLSplat $\mathbf{F}_{\theta}$ predicts a set of 3D Gaussians $\mathcal{G}$ along with the context camera parameters $\{\mathbf{P}_{i}\}_{i=1}^{V}$ :

 $(\mathcal{G},\{\mathbf{P}_{i}\}_{i=1}^{V})=\mathbf{F}_{\theta}\big(\{\mathbf{I}_{i}\}_{i=1}^{V},B\big),\qquad\mathcal{G}=\{\mathbf{g}_{b}\}_{b=1}^{B}.$ 

(1)

Here, the 3DGS attribute $\mathbf{g}_{b}$ consists of a 3D center, opacity, scale, rotation, and color coefficients.

As illustrated in Fig. 2, a geometry backbone (Burzio et al., 2026) encodes the images into $N$ anchor tokens $\{\mathbf{a}_{n}\}_{n=1}^{N}$ . These anchors serve as the foundational sites from which the 3D Gaussians are spawned. To use the limited budget effectively, RLSplat adaptively distributes the $B$ Gaussians across these anchors. Specifically, a Gaussian allocation policy assesses the local significance of each anchor to predict a discrete allocation $\mathbf{k}\in\mathbb{Z}_{\geq 0}^{N}$ that strictly sums to the budget ( $\sum k_{n}=B$ ), and we optimize this policy via reinforcement learning (Sec. 3.2). Next, a resource-linear decoder instantiates exactly $k_{n}$ Gaussian tokens at each anchor. It predicts an initial state for each Gaussian and efficiently processes them via a refinement module to produce the final set of $B$ Gaussians. This decoder’s computational footprint scales linearly with the requested budget, as described in Sec. 3.3.

## 3.2 Gaussian Allocation Policy

To achieve a compact and high-fidelity representation, Gaussians must be densely allocated to the anchors that encode geometrically complex local 3D regions. We formulate this discrete allocation task as a reinforcement learning problem, parameterizing a policy $\pi_{\psi}(\mathbf{k}|\{\mathbf{a}_{n}\}_{n=1}^{N},B)$ that maps the anchor tokens and target budget to a discrete allocation $\mathbf{k}=\{k_{n}\}_{n=1}^{N}$ . Specifically, the policy model predicts allocation proportions $\mathbf{p}=\{p_{n}\}^{N}_{n=1}$ , where $p_{n}$ represents the expected fraction of the Gaussian budget assigned to anchor $n$ . The allocation process is modeled as drawing trials from a multinomial distribution, such that $\mathbf{k}\sim\operatorname{Mult}(B,\mathbf{p})$ .

To optimize $\pi_{\psi}$ over these non-differentiable discrete allocations, we leverage Group Sequence Policy Optimization (GSPO) (Zheng et al., 2025). At each training step, we draw a group of $C$ rollouts, i.e., candidate allocations $\mathbf{k}^{(c)}\sim\pi_{\mathrm{old}}=\operatorname{Mult}(B,\operatorname{sg}(\mathbf{p}))$ for $c\in\{1,\dots,C\}$ , from the current policy with gradients stopped by $\operatorname{sg}(\cdot)$ . For each rollout $c$ , we first generate the 3DGS representation $\mathcal{G}^{(c)}$ . We then render an image $\hat{\mathbf{I}}^{(c)}$ from $\mathcal{G}^{(c)}$ at novel target views, computing the reconstruction loss $\mathcal{L}_{\mathrm{recon}}^{(c)}$ against the ground-truth $\mathbf{I}$ without gradient tracking. This loss directly serves as the reward signal for rendering quality, defined as $R_{c}=-\mathcal{L}_{\mathrm{recon}}^{(c)}$ . Thanks to the highly efficient rasterization of 3DGS, evaluating multiple rollouts introduces minimal training overhead. We then compute the group-relative advantage $\hat{A}_{c}$ by standardizing the rewards within the group:

 $\hat{A}_{c}=\frac{R_{c}-\operatorname{mean}\left(\{R_{c^{\prime}}\}_{c^{\prime}=1}^{C}\right)}{{\operatorname{std}\left(\{R_{c^{\prime}}\}_{c^{\prime}=1}^{C}\right)}}.$ 

(2)

Following the GSPO framework, we view the allocation of Gaussians as a sequence of length $B$ and compute a length-normalized importance ratio $s_{c}$ for each rollout:

 $s_{c}=\left(\frac{\pi_{\psi}(\mathbf{k}^{(c)})}{\pi_{\mathrm{old}}(\mathbf{k}^{(c)})}\right)^{\frac{1}{B}}=\exp\left(\frac{1}{B}\sum_{n=1}^{N}k^{(c)}_{n}\log\frac{p_{n}}{\operatorname{sg}(p_{n})}\right).$ 

(3)

The policy is then updated by maximizing the clipped objective

 $\mathcal{J}_{\mathrm{policy}}=\mathbb{E}\left[\frac{1}{C}\sum_{c=1}^{C}\min\Big(s_{c}\hat{A}_{c},\;\operatorname{clip}\big(s_{c},1-\epsilon,1+\epsilon\big)\hat{A}_{c}\Big)\right],$ 

(4)

where $\epsilon$ is the clipping range, and the expectation is taken over scenes, budgets, and rollout groups. At inference time, we bypass stochastic sampling and deterministically convert the expected counts $B\mathbf{p}$ into an integer allocation whose counts sum exactly to $B$ . Details of the rounding procedure are provided in appendix B.

## 3.3 Resource-Linear Gaussian Decoding

Given a Gaussian allocation $\mathbf{k}=\{k_{n}\}_{n=1}^{N}$ , the resource-linear decoder spawns exactly $B$ Gaussian tokens from the anchors and decodes them into the final Gaussians at a cost linear in $B$ . We describe the token spawning, the local refinement with hierarchical neighbor search, and the regularizers that keep this search accurate.

Gaussian token spawning.
For each anchor $\mathbf{a}_{n}$ , a token generator instantiates $k_{n}$ distinct Gaussian tokens, each conditioned on its slot index within the anchor (appendix D):

 $\{\mathbf{t}_{b}\}_{b=1}^{B}=\mathrm{TokenGen}\big(\{(\mathbf{a}_{n},k_{n})\}_{n=1}^{N}\big).$ 

(5)

We denote by $n_{b}$ the anchor that spawned token $b$ . A head then predicts an initial Gaussian $\mathbf{g}_{b}^{0}=\mathrm{Head}(\mathbf{t}_{b})$ from each token, including its initial center $\bm{\mu}^{0}_{b}$ .

Local refinement with hierarchical neighbor search.
Since the initial tokens lack spatial context, they must attend to neighboring Gaussians to refine their parameters. To avoid the prohibitive $\mathcal{O}(B^{2})$ cost of global attention, we employ a local cross-attention mechanism over $L$ layers.
Anchors with $k_{n}=0$ are excluded from the hierarchical neighbor search. For each remaining anchor $n$ , we compute the centroid $\bar{\bm{\mu}}_{n}$ of its initial Gaussians:

 $\bar{\bm{\mu}}_{n}=\frac{1}{k_{n}}\sum_{b:\,n_{b}=n}\bm{\mu}^{0}_{b}.$ 

(6)

To find neighbors efficiently, we search hierarchically: we find the $K_{\rm{anc}}$ nearest anchors, and then search for the $K_{\rm{gs}}$ nearest Gaussian tokens only among the Gaussians belonging to these local anchors:

 $\displaystyle\mathcal{N}^{\mathrm{anc}}(n)$ 
 $\displaystyle=\mathrm{KNN}_{K_{\rm{anc}}}\big(\bar{\bm{\mu}}_{n};\{\bar{\bm{\mu}}_{m}:k_{m}>0\}\big),$ 

(7)

 $\displaystyle\mathcal{N}^{\mathrm{gs}}(b)$ 
 $\displaystyle=\mathrm{KNN}_{K_{\rm{gs}}}\big(\bm{\mu}^{0}_{b};\{\bm{\mu}^{0}_{j}:n_{j}\in\mathcal{N}^{\mathrm{anc}}(n_{b})\}\big).$ 

By restricting the search space, we keep the neighbor querying highly efficient. Both neighbor sets are computed once using the detached initial positions and shared across all $L$ layers. Each token $\mathbf{t}_{b}$ is then refined by $L$ layers of cross-attention over
its neighbors, each followed by a feed-forward layer:

 $\mathbf{t}_{b}\leftarrow\mathbf{t}_{b}+\mathrm{CrossAttn}\big(\mathbf{t}_{b},\,\{\mathbf{t}_{j}\}_{j\in\mathcal{N}^{\mathrm{gs}}(b)}\big).$ 

(8)

Finally, a residual head predicts a correction $\Delta\mathbf{g}_{b}$ from $\mathbf{t}_{b}$ , giving $\mathbf{g}_{b}=\mathbf{g}_{b}^{0}+\Delta\mathbf{g}_{b}$ .

Locality regularizers.
For this hierarchical search to be valid, a Gaussian’s true spatial neighbors must actually reside within its parent’s anchor neighborhood $\mathcal{N}^{\mathrm{anc}}(n_{b})$ . We enforce this using two regularizers. First, a Voronoi loss keeps each Gaussian closer to its own parent anchor’s centroid $\bar{\bm{\mu}}_{n_{b}}$ than to any neighboring anchor’s centroid $\bar{\bm{\mu}}_{m}$ :

 $\mathcal{L}_{\mathrm{vor}}=\frac{1}{B}\sum_{b=1}^{B}\sum_{m\in\mathcal{N}^{\mathrm{anc}}(n_{b})}\max\left(0,\ \|\bm{\mu}^{0}_{b}-\bar{\bm{\mu}}_{n_{b}}\|-\|\bm{\mu}^{0}_{b}-\bar{\bm{\mu}}_{m}\|\right).$ 

(9)

Second, an offset loss constrains the residual correction $\Delta\bm{\mu}_{b}$ to limit Gaussian drift:

 $\mathcal{L}_{\mathrm{offset}}=\frac{1}{B}\sum_{b=1}^{B}\max\Big(0,\ \frac{\|\Delta\bm{\mu}_{b}\|}{d_{n_{b}}}-\delta\Big)^{2},$ 

(10)

where $d_{n}$ is the local anchor spacing, defined as the median distance from $\bar{\bm{\mu}}n$ to its $K{\rm anc}$ nearest anchors, and $\delta=0.5$ is a margin limiting Gaussian movement relative to the local anchor scale.

## 3.4 Training

We train RLSplat in two stages: base training trains the geometry backbone and decoder with random allocations, and policy training introduces the Gaussian allocation policy and fine-tunes the entire model with policy optimization.

Objectives.
To supervise view synthesis, we apply a reconstruction loss $\mathcal{L}_{\mathrm{recon}}$ , combining pixel-wise MSE and LPIPS between the rendered and ground-truth target views. For geometric alignment, a camera loss $\mathcal{L}_{\mathrm{cam}}$ supervises the translation, rotation, and field-of-view of the predicted context cameras. Additionally, a projection loss $\mathcal{L}_{\mathrm{proj}}$ reprojects each anchor’s Gaussians toward their source image patch. Incorporating a cheirality penalty to prevent Gaussians from landing behind the camera, $\mathcal{L}_{\mathrm{proj}}$ effectively ties an anchor’s allocation to a specific scene region and prevents arbitrary drift. These terms are combined with the locality regularizers ( $\mathcal{L}_{\mathrm{vor}}$ and $\mathcal{L}_{\mathrm{offset}}$ ) previously introduced in Sec. 3.3. Finally, during the policy training stage, we activate the policy loss $\mathcal{L}_{\mathrm{policy}}=-\mathcal{J}_{\mathrm{policy}}$ (Eq. 4) to optimize the discrete allocations via GSPO. The overall training objectives are detailed in appendix E.

Two-stage training. We train RLSplat in two stages. In base training, we train the encoder and decoder with random allocations, and sample budgets over the full supported range. This exposes the decoder to widely varying per-anchor counts, so that it learns to render diverse allocations before the policy is introduced. In policy training, we add the policy head, initialized to output uniform probabilities (appendix B), and fine-tune the entire model with the policy loss $\mathcal{L}_{\mathrm{policy}}$ . Since base training involves no policy, there is no reference policy to regularize toward, and unlike typical RL fine-tuning, we do not apply a KL penalty. During this stage, budgets are sampled with a skew toward the lower end of the range, where the choice of allocation matters most for rendering quality.

## 4 Experiments

Datasets and evaluation.
We train on RealEstate10K (RE10K) (Zhou et al., 2018) with $V\in\{2,3,4,6,8,12,24\}$ uncalibrated context views. To assess generalization, we evaluate the RE10K-trained model zero-shot on ACID (Liu et al., 2021) (249 test scenes), which consists of aerial footage of coastal and natural scenes. We follow the evaluation protocol of $\text{F}^{4}$ Splat (Kim et al., 2026) at a resolution of $256\times 256$ and report PSNR, SSIM, and LPIPS together with the number of Gaussians (#GS). To measure inference cost, we report the latency and peak VRAM of Gaussian generation, excluding data loading, pose alignment, and rendering. All methods are run on a single RTX A6000 with a batch size of one. For each budget, we discard the first scene as warm-up, reset the peak-memory counter before each timed run, and report the mean over the test scenes.

Baselines.
We mainly compare with budget-controllable methods, EcoSplat (Park et al., 2026) and $\text{F}^{4}$ Splat (Kim et al., 2026), which take a target Gaussian count as input at inference time.
We evaluate all methods at the same requested Gaussian budgets, with particular focus on the low-budget regime.
For a broader comparison, we also include budget-fixed methods, which place Gaussians uniformly, either one per pixel (NoPoSplat (Ye et al., 2025), SPFSplat (Huang and Mikolajczyk, 2025)) or one per voxel (AnySplat (Jiang et al., 2025)). Their Gaussian count is therefore determined by the input resolution and the number of views, or by the voxel size, rather than chosen by the user.

Implementation details.
In the base training stage, we train the geometry backbone and Gaussian decoder with random allocations for 40,000 steps. In the subsequent policy training stage, we train for an additional 5,000 steps. During training, the Gaussian budget is sampled from $[2048,16384V]$ , where $V$ is the number of input views. Unless otherwise noted, we use $K_{\rm{anc}}{=}K_{\rm{gs}}{=}16$ for Gaussian decoding in all experiments. Details are provided in appendices E and F.

## 4.1 Novel-view Synthesis Results

Table 1 compares RLSplat with budget-controllable methods at matched budgets of 1K, 2K, and 4K Gaussians per context view. RLSplat achieves the best LPIPS, SSIM, and PSNR at every budget and view count. Importantly, its advantage becomes increasingly pronounced as the Gaussian budget decreases. For example, with 8 context views, the PSNR advantage over F4Splat grows from 0.74 dB at 4K Gaussians per view to 0.99 dB at 2K and 1.22 dB at 1K. This trend is consistent across 16 and 24 context views, demonstrating that RLSplat preserves reconstruction quality particularly well under tight representation budgets. This robustness is consistent with how the final $B$ Gaussians are decoded: the baselines predict a dense set of Gaussians and then prune or select from it, whereas RLSplat directly decodes the requested number of Gaussians and refines them through resource-linear decoding.

For a broader comparison, Table 2 includes budget-fixed methods whose output size is determined by the input. Despite using substantially fewer Gaussians, RLSplat outperforms all of these methods on LPIPS, SSIM, and PSNR across all view counts. In particular, with 24 context views, RLSplat achieves 25.58 dB PSNR using only 24K Gaussians, compared with 25.00 dB for SPFSplat using 1536K Gaussians, corresponding to 64 $\times$ fewer Gaussians.

Fig. 4 shows how each method uses the same total budget of 8K Gaussians on RE10K. In the highlighted stair region, EcoSplat and F4Splat retain 2,521 and 3,026 Gaussians, respectively, whereas RLSplat allocates 5,388 Gaussians to the thin, high-frequency structure. The tile-wise allocation maps further show that RLSplat concentrates its budget around the stair balusters while spending fewer Gaussians on the comparatively smooth wall. This targeted allocation leads to substantially better reconstruction of the thin structures: the local PSNR of the highlighted region increases from 17.79 dB for EcoSplat and 20.00 dB for F4Splat to 23.51 dB for RLSplat . The improvement is also reflected in the full-view PSNR (21.82, 23.42, and 26.51 dB, respectively). These results illustrate that the learned allocation policy uses a fixed Gaussian budget more effectively by concentrating capacity where fine geometric and appearance details require it.

## 5 Conclusion

We presented RLSplat, a budget-controllable feed-forward 3DGS framework whose inference cost scales linearly with the requested number of Gaussians $B$ . A Gaussian allocation policy, trained with GSPO, distributes exactly $B$ Gaussians across anchors, and a resource-linear decoder refines them through local cross-attention with a hierarchical neighbor search. On ACID, RLSplat achieves the best rendering quality among budget-controllable methods at every tested budget. Its latency and peak memory decrease linearly with $B$ , and it matches or exceeds the quality of the baselines at a fraction of their memory and latency.

## Appendix A Limitations and Future Work

Image encoding remains a fixed cost independent of $B$ , which bounds the achievable speed-up at small budgets. We also evaluate at a resolution of $256\times 256$ and in a single cross-dataset setting. RLSplat controls both the size of the representation and the cost of producing it. It can therefore serve as a 3D scene representation for downstream tasks that have their own resource limits, such as 3D vision-language models and robot learning. Evaluating it on such tasks is a natural next step.

## Appendix B Allocation Policy Details

## Policy head.

The policy head predicts a logit $l_{n}$ for each anchor token, and the
allocation probabilities are obtained as
 $\mathbf{p}=\operatorname{softmax}(\mathbf{l})$ with
 $\mathbf{l}=\{l_{n}\}_{n=1}^{N}$ . The head is
 $\mathrm{LN}(d)\rightarrow\mathrm{Linear}(d,h)\rightarrow\mathrm{SiLU}\rightarrow\mathrm{Linear}(h,1)$ , applied per anchor token.
The last linear layer is zero-initialized, so $\mathbf{p}$ starts uniform.

## Budget conditioning.

The head is modulated by FiLM parameters $(\bm{\gamma},\bm{\eta})$ . They are predicted from a single scalar, the log-ratio of the requested budget to the number of anchors, $u=\log_{2}(B/N)$ , by $\mathrm{Linear}(1,h)\rightarrow\mathrm{SiLU}\rightarrow\mathrm{Linear}(h,2d)$ . The modulation is applied after the layer norm: $\text{hidden}\leftarrow\text{hidden}\odot\big(1+\tanh\bm{\gamma}(u)\big)+\bm{\eta}(u)$ . The last layer of the FiLM generator is also zero-initialized. The ratio $B/N$ is floored at $1/64$ so that $u$ stays finite for very small budgets.

## Policy initialization at the start of policy training.

The policy head does not exist during base training. It is created with zero-initialized output layers when policy training begins, so it outputs exactly $0$ for every anchor and $\mathbf{p}$ is uniform at the first policy-training step. Base training’s random allocation already covers this regime, so the transition introduces no distribution shift for the decoder.

## Deterministic integer allocation.

At inference, and for the reconstruction loss during policy training, the expected counts $B\mathbf{p}$ are converted into an integer allocation $\mathbf{k}^{\star}$ by systematic rounding with a fixed phase. Anchors are laid out on a line in a fixed (view, patch-raster) order, anchor $n$ owning the interval $[BP_{n-1},\,BP_{n})$ with $P_{n}=\sum_{m\leq n}p_{m}$ and $P_{0}=0$ . We place $B$ points at $\varphi,\varphi+1,\dots,\varphi+B-1$ with $\varphi=\tfrac{1}{2}$ and count those that fall inside each interval:

 $k^{\star}_{n}\;=\;\big\lceil BP_{n}-\varphi\big\rceil-\big\lceil BP_{n-1}-\varphi\big\rceil.$ 

(11)

This rule has three properties we rely on: (i) the counts sum to exactly $B$ , since the telescoping sum equals $\lceil B-\tfrac{1}{2}\rceil-\lceil-\tfrac{1}{2}\rceil=B$ ; (ii) every count is either $\lfloor Bp_{n}\rfloor$ or $\lceil Bp_{n}\rceil$ , since an interval of length $Bp_{n}$ contains that many unit-spaced points; and (iii) an anchor with $p_{n}=0$ receives no Gaussian. With a uniformly random phase, Eq. 11 is systematic resampling and satisfies $\mathbb{E}[k_{n}]=Bp_{n}$ , the mean of the multinomial rollouts. Fixing $\varphi$ makes it deterministic. It needs a single cumulative sum, so it takes $\mathcal{O}(N)$ time, involves no sorting and has no ties to break. We compute it in double precision and renormalize $P_{N}$ to one.

## Settled hyperparameters.

## Appendix D Decoder Details

## Gaussian token construction.

For anchor $n$ with $k_{n}$ allocated Gaussians, token $r\in\{0,\dots,k_{n}-1\}$ 
has relative position $\rho_{n,r}=(r+\tfrac{1}{2})/k_{n}\in(0,1)$ , so the
tokens of any anchor tile the unit interval regardless of $k_{n}$ . We use a
mip-NeRF-style (Barron et al., 2021) integrated positional encoding
 $\mathrm{PE}(\rho,k)$ that averages Fourier features over the token’s
bin of width $1/k_{n}$ , which suppresses the frequencies that would
otherwise alias between nearby values of $k_{n}$ . The token is

 $\mathbf{t}^{0}_{n,r}=\mathbf{a}_{n}+\big(1+\tanh\bm{\alpha}_{n}\big)\odot\mathrm{MLP}\big(\mathrm{PE}(\rho_{n,r},k_{n})\big)+\bm{\beta}_{n},\qquad(\bm{\alpha}_{n},\bm{\beta}_{n})=\mathrm{Linear}\big(\mathrm{LN}(\mathbf{a}_{n})\big),$ 

(12)

with the FiLM layer zero-initialized. All $B$ tokens across a batch are
packed into one sequence, so no computation is spent on padding.

## Neighbor search.

Anchor centroids $\bar{\bm{\mu}}_{n}$ are the mean initial centers of
each anchor’s tokens. $\mathcal{N}^{\mathrm{anc}}(n)$ , the $K_{\rm{anc}}{=}16$ nearest anchors
to $n$ (including $n$ itself), is found once by a $K$ -nearest-neighbor
search over the detached centroids and shared by all $L=2$ decoder
layers. A Gaussian’s neighbor set $\mathcal{N}^{\mathrm{gs}}(b)$ is the $K_{\rm{gs}}$ nearest Gaussian tokens, by detached Euclidean distance, among the tokens belonging to $\mathcal{N}^{\mathrm{anc}}(n_{b})$ .

## Residual head.

The initial-Gaussian head and the residual head share the same
architecture, $\mathrm{LN}\rightarrow\mathrm{Linear}(d,256)\rightarrow\mathrm{SiLU}\rightarrow\mathrm{Linear}(256,11+3d_{\mathrm{sh}})$ ,
predicting a center offset (3), an opacity logit (1), scales (3), a
quaternion (4), and spherical-harmonic color coefficients. The residual
head is zero-initialized, and its center output is scaled by
 $\alpha_{\mu}$ .

## Appendix E Training Details

Context views are loaded at $256\times 256$ and bilinearly upsampled to $504\times 504$ immediately before the backbone, while target views, losses, and evaluation remain at $256\times 256$ . The DVLT (Burzio et al., 2026) backbone runs 12 inference steps. Each training step draws the number of context views $V$ from the divisors of 24, $V\in\{2,3,4,6,8,12,24\}$ , and sets the batch size to $24/V$ , so that every step processes 24 context views in total regardless of $V$ .

## Base training.

The encoder and decoder are trained for 40K steps with allocations drawn uniformly at random, which exposes the decoder to a wide range of per-anchor counts before any policy is learned. The per-sample budget is sampled from a Beta distribution over $[2048,16384V]$ . We use AdamW with a learning rate of $10^{-4}$ ( $0.1\times$ for the backbone), 1,000 warm-up steps, and cosine decay on 4 GPUs. The loss weights are $1.0$ for MSE, $0.05$ for VGG-LPIPS, $0.1$ for the reprojection term and $0.05$ for the cheirality term of $\mathcal{L}_{\mathrm{proj}}$ , and $1.0$ for $\mathcal{L}_{\mathrm{vor}}$ . The offset loss $\mathcal{L}_{\mathrm{offset}}$ is weighted $\lambda_{\mathrm{offset}}=0.01$ .

## Policy training.

Starting from the pretrained model, all parameters are fine-tuned for 5K
steps with $C=5$ rollouts per step and a rollout temperature of
 $\tau=1.0$ ; the render used for the reconstruction loss is produced from the
deterministic allocation of Sec. 3.2. The learning rate is reduced to
 $10^{-5}$ , with a $30\times$ multiplier on the allocation head, and
 $\mathcal{L}_{\mathrm{offset}}$ is disabled. The policy loss
 $\mathcal{L}_{\mathrm{policy}}$ is weighted $1.0$ . Each sample’s budget is drawn independently from $\mathrm{Beta}(1,4)$ 
over the same range, which biases training toward low budgets where allocation
matters most. The total budget of a step is capped, so that peak memory is
bounded independently of the per-sample maximum.

## Appendix F Ablation Protocol

Each ablation changes a single component relative to its reference, except for the variant that removes both locality regularizers. Pretraining ablations (Table 3) are trained from scratch for 5K steps, one eighth of the full schedule, with all step-dependent schedules (cosine horizon, optimizer warm-up, view-sampler warm-up, and validation and checkpoint intervals) scaled by the same factor. We compare the full recipe with variants that remove the local refinement module, the projection loss (both its reprojection and cheirality terms), the offset loss, or both the offset and Voronoi losses. The neighbor match rate without the Voronoi loss is measured with the same schedule. Allocation ablations (Tables 4 and 6) fine-tune for 1K steps from a single shared pretrained checkpoint and vary the group size $C\in\{3,5,7\}$ , the temperature $\tau\in\{0.8,1.0,1.2\}$ , and the allocation rule, replacing the learned policy with a uniform split or a learning-free Sobel-energy heuristic. Since a shorter run anneals on its own cosine schedule, each variant is trained for its own horizon rather than truncated from a longer run. All ablations are evaluated on ACID with 8 context views (249 scenes). Allocation ablations are evaluated at $B/V=1024$ .

## Appendix H Additional Qualitative Comparison

Figs. 11, 12 and 13 compare RLSplat with F4Splat and EcoSplat as the Gaussian budget is reduced from 128K to 32K.
As the budget decreases, the baselines progressively blur or lose thin, high-frequency structures such as stair balusters, railings, window frames, and foliage, while RLSplat retains these details at every budget.
This is consistent with Table 1, where RLSplat exhibits substantially less quality degradation than the baselines as the budget decreases.
Unlike the baselines, which reduce a dense set of candidates, RLSplat allocates the budget where the scene needs it and decodes only those Gaussians, preserving fine details even under the tightest budgets.
