## Staged Continual Adaptation of Multimodal Foundation Models

for Japanese Financial Documents

Genshin Kakimoto

Affiliation: Kyoto University, Kyoto, Japan

Atsushi Yanagisawa

Affiliation: Kyoto University, Kyoto, Japan

Correspondence to: yanagisawa.atsushi.62t@st.kyoto-u.ac.jp

Abstract

Staged post-training of multimodal foundation models chains vision–language alignment, reasoning distillation, and domain tuning, yet how each phase trades capabilities against the others remains under-characterised. Tracking an 8.4B-parameter model from an un-fine-tuned baseline through three training phases on Japanese financial documents (evaluated on five text-input benchmarks), we find the phases interact non-additively: math-only distillation overwrites the financial knowledge acquired earlier even as procedural math skill survives, and the domain phase repairs more than it installs. A skip-phase ablation is best for domain knowledge but forfeits numerical-reasoning gains, so per-phase contributions are not decomposable and the best checkpoint is task-dependent, with implications for checkpoint retention and scheduling rather than added stages.

Keywords: 
Multimodal Learning, Structured Data, Synthetic Data, Financial Documents, Foundation Models, Continual Adaptation

## 1 Introduction

Adapting a multimodal foundation model to a specialised domain rarely proceeds in a single step: contemporary recipes typically combine vision–language alignment, reasoning distillation, and domain tuning, where each stage can both install new capabilities and erode previously acquired ones. LLaVA-style recipes (Liu et al., 2023; Ye et al., 2023; Zhang et al., 2023; Li et al., 2024; Zhou et al., 2025) establish the architectural template for such multi-stage adaptation but say little about how earlier phases interact with later ones when the target domain demands structured, layout-dependent tasks beyond free-form QA. We ask: do the phases of a staged adaptation pipeline contribute monotonically, or does staging induce capability trade-offs whose best checkpoint differs by task?

Financial document understanding is a compelling testbed for staged adaptation because the domain simultaneously demands regulatory knowledge, numerical reasoning, and language-specific competence, capabilities that naturally map to distinct training phases. Each country maintains its own disclosure regime (e.g. SEC 10-K filings in the US, FSA filings in Japan), and domain-specialised LLMs for these regimes remain under-explored, especially for non-English domains where data is scarce and efficient training pipelines are valuable. Within this setting, Japanese financial disclosures are a particularly demanding case: their layout-rich pages of dense tables and multi-column statements must be read as images, and even state-of-the-art LLMs perform only marginally better than logistic regression on EDINET tasks (Sugiura et al., 2026). We study this through a three-phase staged continual adaptation pipeline—vision–language alignment, mathematical reasoning distillation, financial-domain adaptation—on an 8.4B-parameter model pairing SigLIP-v2 (Tschannen et al., 2025) with llm-jp-4-8B-Instruct (LLM-jp, 2025b; LLM-jp, 2025a) via a two-layer MLP projector (Zhang et al., 2023; Li et al., 2024). The un-fine-tuned instruction baseline serves as Phase 0; Phase 1 aligns visual and language representations using Japanese captioning/VQA corpora and OCR/visual QA synthesised from government PDFs (Cabinet Office, FSA, MOF); Phase 2 distils chain-of-thought mathematical reasoning from Qwen3-30B-A3B-Thinking-2507 (Qwen Team, 2025b); Phase 3 injects financial-domain knowledge via text-only financial QA (Chen et al., 2021; Chen et al., 2022; Zhu et al., 2021) and visual QA from government PDFs. As testbeds we adopt EDINET disclosures (Sugiura et al., 2026) for real-world financial tasks, JP Fin Harness (Hirano, 2023) for Japanese finance knowledge, and GSM8K (Cobbe et al., 2021) for mathematical ability. All three are text-input evaluations: they probe how staging reshapes the backbone’s financial and numerical capabilities, not the in-modality page-reading skill that the visual stages target, which available benchmarks do not yet measure and we leave to future work. Within this scope, the phases interact non-additively, and a skip-phase ablation that omits Phase 2 isolates the resulting trade-off between numerical reasoning and domain priors.

Contributions: (1) evidence that the phases interact non-additively on EDINET and JP Fin Harness (Hirano, 2023): asymmetric forgetting (procedural skill survives, declarative knowledge is overwritten), repair rather than installation by the domain phase, and a suggestive cross-phase enabling effect, all anchored to the un-fine-tuned baseline; (2) a three-phase staged continual adaptation pipeline that trains end-to-end on page images, the visual stages serving as an adaptation vehicle whose in-modality skill our text-input benchmarks do not yet probe; (3) a reproducible synthetic-data pipeline generating OCR, visual QA, and domain-specific financial QA from government PDFs, with code and the resulting datasets released publicly;11

## 2 Model Design and Training Pipeline

## 2.1 Architecture

The model consists of three components: a vision encoder, an MLP projector, and a language model (overall architecture diagram in Figure 1, Appendix A). We adopt SigLIP-v2 SO400M-patch14-384 (Tschannen et al., 2025) as the vision encoder. Inspired by LLaVA-style projectors (Liu et al., 2023; Zhang et al., 2023; Li et al., 2024), the projector is a two-layer MLP (Linear $\to$ GELU $\to$ Linear) that maps visual features into the language model’s embedding space and bridges the visual and linguistic representations. The language model is llm-jp-4-8B-Instruct (LLM-jp, 2025b) (8B parameters); together with the vision encoder (approximately 0.4B) the total parameter count is approximately 8.4B.

## 2.2 Data Generation from Government-Published PDFs

The synthetic supervision at the core of this study comes from two sources: publicly available PDFs issued by the Cabinet Office, FSA, and MOF, and public math corpora (see Table 3, Appendix A). We chose these agencies because they publish a large volume of finance-related materials.

From these government-published PDFs we construct three single-page datasets using Qwen3-VL-32B-Instruct (Qwen Team, 2025c) as the teacher: (i) an OCR dataset that targets text transcription of each page, following LLaVAR (Zhang et al., 2023); (ii) an extractive/reasoning visual-QA dataset in which the first turn extracts a specific element from the page and the second turn asks for the evidence grounding that answer, in the spirit of LLaVAR-2 (Zhou et al., 2025); and (iii) a finance-specific QA dataset that tests finance knowledge grounded in each page, with questions ranging from simple content extraction to multi-step numerical computations over the extracted content. For dataset (iii) only, we manually identify finance-relevant sub-sites within the Cabinet Office, FSA, and MOF web presences and restrict the source PDFs to those sub-sites. Examples and the full prompt templates are provided in Appendices B and C.

For the math reasoning dataset we draw problems from six publicly available math corpora—MGSM-ja (SB Intuitions, 2024), MathInstruct (TIGER-Lab, 2023), OpenMathReasoning (NVIDIA, 2025), OpenR1-Math-220k (Open-R1, 2025), orca-math-word-problems-200k (Microsoft, 2024), and NuminaMath-1.5 (AI-MO, 2025)—and randomly sample 150K problems in total across these corpora. Each sampled problem is re-annotated by prompting Qwen3-30B-A3B-Thinking-2507 (Qwen Team, 2025b) to emit its response as a restated problem, reasoning process, and final answer inside <Problem>, <Thinking>, and <Answer> tags—a format chosen to localise intermediate-reasoning errors and to fit the multi-step numerical reasoning common in financial documents.

## 2.3 Three-Stage Training

As shown in Table 1, training proceeds in three phases (P1, P2, P3), each comprising one or more stages (S). Phase 1 (P1, vision–language alignment) is required because the pretrained LLM has no prior exposure to image tokens from SigLIP-v2’s embedding space: Stage 1 (P1-S1) trains only the projector on STAIR Captions (Yoshikawa et al., 2017) and OCR data derived from government PDFs, with the vision encoder and LLM frozen; Stage 2 (P1-S2) then updates the projector and the vision encoder and adapts the LLM with LoRA (Hu et al., 2022), using extractive and reasoning QA we constructed from government PDFs together with the JA-VG-VQA conversation dataset (LLM-jp, 2024) and SakanaAI JA-VG-VQA-500 (SakanaAI, 2024). Phase 2 (P2, mathematical reasoning distillation) is motivated by the observation that financial documents require multi-step numerical deduction (e.g., consistency checks across tables): we construct approximately 150K math problems with XML-structured chain-of-thought supervision (full dataset details in Appendix A) and train the LLM (via QLoRA-SFT) using Qwen3-30B-A3B-Thinking-2507 (Qwen Team, 2025b) as the teacher. Phase 3 (P3, financial-domain adaptation) re-introduces domain-specific supervision, as general-purpose math distillation does not cover financial terminology or reporting conventions: P3-S1 applies LoRA to the LLM on text-only financial benchmarks (FinQA, ConvFinQA, TAT-QA) (Chen et al., 2021; Chen et al., 2022; Zhu et al., 2021), while P3-S2 trains the projector together with LoRA adapters on the LLM using visual domain QA from government PDFs; the vision encoder is frozen throughout P3. Hyperparameters, training-loss curves, and an example model response on a finance-related reasoning problem are provided in Appendix A; the full prompt templates used for synthetic data generation are listed in Appendix C.

## 3 Experimental Results

## Per-phase evaluation.

Table 2 reports scores on five benchmarks for the un-fine-tuned baseline (P0), after each training phase (P1–P3), and for the skip-P2 ablation (P1 $\to$ P3). P0 $\to$ P1 raises JP Fin Harness (45.0 $\to$ 53.5), GSM8K (58.5 $\to$ 64.3), EDINET fraud (0.516 $\to$ 0.554), and EDINET industry (4.7 $\to$ 8.7). From P1, GSM8K rises to 73.8 (P2) before slipping to 71.6 (P3), and EDINET fraud peaks at P3 (0.614), while JP Fin Harness (53.5 $\to$ 31.6 $\to$ 49.6) and EDINET industry (8.7 $\to$ 7.9 $\to$ 8.2) decline past P1. (EDINET earnings is near-chance throughout and is not interpreted.) These are single greedy-decoding runs; the 3-seed means in Table 9 are lower and re-order some rows (e.g. GSM8K P2 $69.4\pm 1.4$ , and the EDINET fraud peak moves from P3 to P1 at $0.562\pm 0.008$ ), so individual peaks should be read cautiously.

## Skip-P2 ablation.

Skipping Phase 2 (P1 $\to$ P3) reveals a clear trade-off: mathematical reasoning drops sharply (GSM8K 59.6 vs. 71.6) and EDINET fraud falls (0.499 vs. 0.614), yet domain knowledge is better preserved, with JP Fin Harness and EDINET industry reaching their overall peaks (56.2 and 10.4). Phase 2 thus installs numerical reasoning but erodes domain priors that Phase 3 alone cannot fully restore.

## External-model context.

For perspective on absolute quality, we compare our checkpoints against larger external models: Llama-3.3-70B, GPT-5, and DeepSeek-R1 on EDINET, and the official JP Fin Harness 0-shot leaderboard (Hirano, 2023). The full tables are deferred to Appendix A.6. In its best single run, our P3 reaches 0.614 ROC-AUC on EDINET fraud, exceeding the much larger Llama-3.3-70B (0.59) and DeepSeek-R1 (0.56) and approaching GPT-5 (0.62), all three as reported by EDINET-Bench (Sugiura et al., 2026) for the same text-input configuration as ours. This parity rests on one run: the 3-seed fraud mean is lower ( $0.547\pm 0.005$ ; Table 9). A well-adapted small model can thus rival far larger ones on specific financial tasks, though ours trails every external baseline on the harder EDINET industry task.

## Per-task JP Fin Harness breakdown.

Subtask behaviour is heterogeneous (Table 5, Appendix A): the P0 $\to$ P1 gain concentrates on chabsa (0.859 $\to$ 0.943), cma_basics, and security_sales_1; every subtask collapses at P2 and only partly recovers at P3; and skip-P2 (P1 $\to$ P3) takes the best score on four of five subtasks, while cpa_audit alone peaks at P0 (0.276). The chabsa collapse and partial recovery (0.943 $\to$ 0.581 $\to$ 0.935) mirrors the aggregate declarative-knowledge trajectory discussed below.

## 4 Discussion

## Beyond recency.

A natural reading of Table 2 is recency—each benchmark peaks just after the phase that supervises it—yet this holds for only two of our signals (GSM8K at P2; single-run EDINET fraud at P3). JP Fin Harness and EDINET industry instead peak at the skip-P2 ablation, not at the financial phase P3, and both sit below their P1 values by P3; EDINET earnings stays near-chance throughout (ROC-AUC 0.46–0.52), so we do not read its P0 maximum as a capability. That the best checkpoint is usually not the most recently supervised one motivates examining how the phases interact.

## Forgetting is asymmetric.

The interference between phases is direction-dependent. Procedural math skill installed at P2 largely survives later financial tuning (GSM8K 73.8 $\to$ 71.6 at P2 $\to$ P3, and stable across seeds), whereas the declarative financial knowledge acquired at P1 is overwritten by the math phase (JP Fin Harness 53.5 $\to$ 31.6 at P1 $\to$ P2; evidence-grounded chabsa collapses likewise). These two effects come from different perturbations, and the math corpus is far larger than the financial ones, so the asymmetry is partly entangled with phase ordering and corpus size. We therefore read “procedural skills resist later tuning while declarative knowledge does not” as a hypothesis about kinds of capability within this pipeline rather than an established law; our evidence is limited to financial declarative knowledge (chabsa is financial sentiment), and a non-financial Japanese language task would be needed to test a broader linguistic claim.

## The domain phase repairs more than it installs.

Most financial ability is acquired already at the general alignment phase P1, destroyed at P2, and only partly restored at P3, which never regains the P1 level. The same trajectory appears on two independent benchmarks (JP Fin Harness and EDINET industry). The dedicated financial phase thus performs damage repair rather than acquisition, and skipping the reasoning phase (skip-P2) is best on both because nothing needs repairing. Why P3 falls short of P1 is, however, confounded: overwritten knowledge may be intrinsically hard to recover, or the P3 corpus is simply far smaller than P1’s; a volume-matched or interleaved P3 would separate these.

## Compositional enabling and design implications.

One effect hints at positive composition rather than mere interference: removing the math phase drops EDINET fraud below the untrained baseline (skip-P2 0.499 vs. P0 0.516), as if reasoning distillation were a prerequisite for the later phase to express fraud detection. The effect is small, though: a 0.017 ROC-AUC gap astride 0.5 on a roughly 200-example test set, and under multiple seeds the fraud peak moves to P1 (Table 9), so the ordering is not robust. We therefore report it as a hypothesis and flag a multi-seed skip-P2 ablation as the priority follow-up. Taken together, a later phase can erase, preserve, or enable what an earlier one produced, so per-phase contributions are not decomposable and no single checkpoint is best for every task. The effective levers are then scheduling and parameter isolation: per-phase adapters composed rather than overwritten, replay or interleaving, and phase reordering, rather than more stages or data. This aligns with the workshop’s sustainability aims.

## Limitations and scope.

(i) We provide multi-seed checks in Appendix A.8 (Table 9), which are broadly stable for GSM8K and earnings; the skip-P2 ablation could not be included for resource reasons, making it—together with the fraud single-run variance noted above—the clearest target for future work. (ii) The results characterise a single model (8.4B), language (Japanese), and domain (finance), so we read the phase interactions as properties of this specific pipeline. (iii) Training is restricted to single-page inputs; multi-page training is a natural follow-up. (iv) P2 uses QLoRA while other stages use full-precision LoRA, so a small contribution from quantization cannot be excluded.

## 5 Conclusion

We tracked an 8.4B-parameter multimodal model for Japanese financial documents from an un-fine-tuned baseline through three adaptation phases. The phases interact non-additively: math-only distillation overwrites declarative domain knowledge while procedural skill persists, and the domain phase repairs more than it installs. Per-phase contributions are thus not decomposable and the best checkpoint is task-dependent, so the key design levers are scheduling and parameter isolation rather than additional stages. Though scoped to Japanese finance, the methodology should transfer to other financial-disclosure regimes where specialised LLMs are needed.

## A.1 Model Architecture Diagram

Figure 1: Architecture of the proposed model. The input image is connected to the language model through SigLIP-v2 and the MLP projector, and is processed jointly with the input text. ## A.2 Staged Learning Pipeline Diagram

Figure 2: Overview of the three-phase staged continual adaptation pipeline. Phase 1 (Vision-Language Alignment): P1-S1 trains only the projector on STAIR Captions and government-PDF OCR (vision encoder and LLM frozen); P1-S2 fine-tunes all three components (vision, projector, LLM via LoRA) on Visual QA and JA-VG-VQA. Phase 2 (Mathematical Reasoning Distillation): P2-S1 updates the LLM via QLoRA on approximately 150K math problems with XML-structured chain-of-thought supervision from Qwen3-30B-A3B-Thinking-2507 (vision encoder and projector frozen). Phase 3 (Financial-Domain Adaptation): P3-S1 adapts the LLM to text-only financial benchmarks (FinQA, ConvFinQA, TAT-QA); P3-S2 then trains the projector together with LoRA adapters on the LLM using visual financial QA from government PDFs (vision encoder frozen throughout P3). Flame icons indicate trainable modules; snowflake icons indicate frozen modules.

## A.6 External-Model Comparison on EDINET and JP Fin Harness

These tables place our checkpoints next to substantially larger models, as indicative context rather than head-to-head results: the Llama-3.3-70B, GPT-5, and DeepSeek-R1 numbers on EDINET are taken from EDINET-Bench (Sugiura et al., 2026) (Table 6, means over three runs) and the JP Fin Harness rows from the official 0-shot leaderboard (Hirano, 2023), so they come from different evaluation runs than ours. We emphasise that the EDINET evaluation here is text-only: the financial statements (Summary, balance sheet, profit-and-loss, and cash-flow tables) are tokenised and fed to the LLM backbone as text, so the page-image modality that is the focus of the main pipeline is not exercised by this benchmark. To keep the comparison consistent, all three external entries are read from the same input setup of EDINET-Bench as our own configuration (Summary+BS+CF+PL); we further restrict the comparison to LLM-based systems.

Table 6 places our P3 checkpoint alongside Llama-3.3-70B, GPT-5, and DeepSeek-R1 on EDINET, and Table 7 compares our JP Fin Harness results with the official 0-shot leaderboard (Hirano, 2023). On EDINET fraud, our best single run (P3, 0.614 ROC-AUC) exceeds the Llama-3.3-70B (0.59) and DeepSeek-R1 (0.56) numbers reported by EDINET-Bench (Sugiura et al., 2026) and approaches GPT-5 (0.62); under three seeds, however, the fraud mean is lower ( $0.547\pm 0.005$ ) and peaks at P1, so we read the parity with GPT-5 as a best-run result rather than a stable one. On EDINET earnings every system except GPT-5 is at or below chance (ROC-AUC $\leq$ 0.5: ours 0.488, Llama-3.3-70B 0.41, DeepSeek-R1 0.46; even GPT-5 reaches only 0.62), so this row is not informative and we draw no conclusions from it. EDINET industry remains a weakness: our P3 result (8.2) and even our best checkpoint (10.4, P1 $\to$ P3; Table 2) trail every external baseline (14.0–31.0). On JP Fin Harness, evaluated 0-shot with the harness’s standard prompting to match the leaderboard, our P1 $\to$ P3 ablation (56.2) exceeds Qwen-14B-Chat (49.1) and Meta-Llama-3-8B-Instruct (44.7) but trails Qwen2-72B-Instruct (67.7) and Claude 3.5 Sonnet (77.0). On GSM8K (Table 8), our P2 (73.8) exceeds Qwen-14B Chat (59.3) but remains 11–16 points below the base-model Llama 3 8B (84.5) and Qwen3 8B-base (89.84).

## A.9 Example Model Response to a Finance-Related Problem

Input

Given that revenue was 100 in the previous period and 120 in the current period, compute the year-over-year growth rate.

Output

<Problem>Given that revenue was 100 in the previous period and 120 in the current period, compute the year-over-year growth rate.</Problem>

<Thinking>

To compute the year-over-year growth rate, I need to use the formula:

Growth Rate = (Current Value - Previous Value) / Previous Value * 100

In this case:

- Previous Value = 100

So, the calculation would be:

(120 - 100) / 100 * 100

Let me simplify this:

(20 / 100) * 100 = 20%

Therefore, the year-over-year growth rate is 20%.

</Thinking>

<Answer>

 $\boxed{20}$ 

</Answer>

Figure 3: Example model response when the input is a finance-related reasoning problem. The model emits the input restated as <Problem>, intermediate reasoning as <Thinking>, and the final boxed answer as <Answer>—the structure that Phase 2 distillation installs.

## Appendix C Prompt Templates for Synthetic Data Generation

This appendix lists the prompt templates used to generate OCR, visual QA, and financial-domain QA supervision from government-published PDFs. All prompts are reproduced below; minor redactions (noted in captions) remove auxiliary fields that were not reported as part of this paper’s claims.

## C.1 OCR Prompt

⬇

[SYSTEM]

You are a high-precision OCR assistant.

You will receive a single image as input.

Task:

- Extract only the text information written in the image as accurately

 and completely as possible.

- Transcribe the text exactly as written in the original script; do NOT

 translate or paraphrase.

- Consider the reading order of the text and arrange it in a natural

 reading sequence.

 * Imagine reading from top-left to bottom-right across the entire page.

 * Follow the order a human would read: headings -> body text ->

 figure/table captions -> footnotes/annotations.

Output Format:

- Output plain text only. Do not include explanations or summaries.

- Insert line breaks where lines or paragraphs change, preserving the

 original layout to some extent.

- Do not guess or infer unreadable or missing characters.

Prohibited Actions:

- Do not summarize or add explanatory text about the image content.

- Do not create new text that does not exist in the image.

- Do not translate or paraphrase the text.

[USER]

List all text that can be confirmed in the given image.

Listing 1: OCR generation prompt. Used to transcribe a single page image into plain text while preserving reading order.

## C.2 Visual QA Prompts (Extractive and Reasoning)

⬇

[SYSTEM]

You are an AI visual assistant. You are viewing a single image.

Task:

Generate multiple single-turn QA pairs from the given document image.

Each QA should focus on different components within the image (text,

figures, tables, numbers, etc.) and should not overlap with each other.

Requirements for generated QA:

1. Only ask questions about content visible in the image that you can

 answer with confidence.

2. You may also answer when you can clearly determine that something

 does NOT exist in the image.

3. Do not include questions you cannot answer with confidence.

4. Ask questions about visual content (text, figures, tables, graphs,

 layout, etc.).

Question Diversity:

- Reading text / titles / headings

- Extracting numbers / dates / times

- Reading values from figures / graphs

- Understanding layout / structure

- Extracting data from tables

Output Format (JSON only, no additional text):

{

 "de_pairs": [

 {"question": "...", "answer": "..."},

 {"question": "...", "answer": "..."}

 ]

}

Notes:

- Answers must be based on information visible in the image.

- Do not ask about uncertain details.

- Each QA should focus on different parts of the image.

- Generate approximately 5-10 QA pairs.

[USER]

Generate multiple extractive QA pairs in JSON format, focusing on

different components within this document image.

Listing 2: Extractive QA-generation prompt. Produces multiple single-turn QA pairs grounded in visible content.

⬇

[SYSTEM]

You are an AI visual assistant. You are viewing a single image.

Task:

For a given reference QA (extractive QA), generate a corresponding

reasoning QA (why/where/how QA). The reasoning QA asks "why/where/how

was that extractive answer obtained?"

Rules for generating reasoning QA:

1. Generate a question that asks for the reason behind the reference

 QA’s answer, or asks how the answer was derived.

2. When the reasoning process of the reference QA is very explicit

 (e.g., simple extraction):

 - The reasoning QA should focus on the source of the answer.

 - Example: "From which part of the image was this information

 extracted?"

 - "Where in the image is that value stated?"

3. When the reasoning process of the reference QA is complex:

 - The reasoning QA should infer relationships between related

 objects in the image.

 - Example: "What visual elements did you connect to reach this

 conclusion?"

4. Diversify the style of generated questions.

5. Answer the reasoning question using evidence from the image, but

 answer from the perspective of only viewing the image.

6. The reasoning QA must be closely related to the reference QA and

 the image. Avoid extending to new concepts.

Output Format (JSON only, no additional text):

{

 "dr": {"question": "...", "answer": "..."}

}

Listing 3: Reasoning QA-generation prompt. Given a reference extractive QA, produces a why/where/how follow-up.
