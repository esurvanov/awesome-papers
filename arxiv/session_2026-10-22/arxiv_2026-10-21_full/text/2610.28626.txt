Abstract

Motivated by the human ability to integrate experience across language, perception, and action, we introduce UniWALM, a unified world-action-language model that learns video, action, and language in a single shared representation, where each modality is both a conditioning signal and a supervision target.
We ask: can jointly generating language enrich this shared representation, improving manipulation and supporting memory-dependent behavior?
Unlike prior approaches that attach a reasoning or vision-language model to a video-action backbone and run them as distinct stages, UniWALM unifies all three modalities inside a single mixture-of-transformers backbone whose per-modality diffusion heads co-denoise synchronously, decoding subtask and textual memory in the same pass as action with no separate planning stage; the generated language is re-consumed on the next step, closing a language-as-memory loop without an external planner or memory bank.
To keep the action stream reliable under this richer objective, we further introduce Flow Matching with Correction (FMC), a training objective that teaches recovery from perturbed action trajectories at no inference-time cost.
UniWALM consistently improves over same-backbone baselines (e.g., FastWAM [52]) on compositional pick-and-place (MolmoSpaces) and across the memory-dependent subset of RMBench [10], where it reaches 34.5% without any pretrained language or reasoning model and exceeds Mem-0’s keyframe-equipped setup (28.5%) using only a single anchor frame.
On a real-world Find-the-Item task, generating textual memory lifts success from 11.1% to 61.1%, while state-of-the-art VLAs stay at or below chance ( $\leq 33.3\%$ ).

## 1 Introduction

Humans integrate perception, language, and action in an any-to-any manner: regions like the posterior parietal and premotor cortex continuously fuse afferent inputs with efferent motor copies [2], and cognitive representations are inherently shaped by what an agent can do in the world [19, 12]. For embodied agents, language, video, and action are three complementary views of a single interaction; a unified representation should let each one inform the others: language guiding physical prediction, visual dynamics grounding action, and action anchoring predictions in embodied behavior. Multimodal models have operationalized this framing for vision and text [31, 47, 55] but largely omit action and motor control.

The same substrate that integrates these modalities also remembers: the hippocampus, which the brain uses to recall past experience, is also recruited to imagine the future and locate the self in time [17, 53]. We routinely enlist language itself as working memory (counting out loud, repeating a phone number, silently rehearsing a passage while reading to retain it) to track state through long-horizon, memory-dependent tasks. A truly unified representation should therefore not only let modalities inform one another but also let generated language serve as the working memory that threads behavior across step boundaries. Concretely, because language is co-denoised with action in one representation, the generated string serves as a learned, in-loop plan (next subtask) and textual memory (what has been done so far), while an anchor-frame visual memory preserves scene context across occlusion; re-consumed on the next step, these close a memory loop with no external planner, VLM, or retrieval buffer.

Recent robotic foundation models connect video, language, and action, but typically along only a subset of these directions. Vision-language-action models [36, 26] consume language as fixed conditioning but do not generate it. Chain-of-thought VLAs [21, 6, 54, 3, 56] generate intermediate language within a control step, but autoregressively, so action must wait for token decoding, and the generated string is not re-consumed across steps. World-action models (DreamZero [51], FastWAM [52]) co-model video and action but drop language entirely. Memory-augmented systems [42, 35, 10] attach retrieval buffers or an external planner to a pretrained backbone; $\pi_{0.7}$ [35] supplies language from a high-level semantic policy while a separate world model generates subgoal images that condition a VLA (Fig. 1(f)). On memory-dependent evaluations like RMBench [10]’s $M(n)$ subset, where decisions require $n$ task-relevant past observations, policies that condition only on the current frame and prompt collapse.

A natural response is to compose a pretrained vision-language model with a video-action backbone and supply reasoning via auxiliary conditioning or an additional loss (Fig. 1(f)). This family (hybrid planner + VLA systems [35], concurrent compositional WALMs) is more accurately described as WAM + VLM features: it typically uses two vision backbones optimized for different objectives and only loosely coupled, treats language as an external hidden state rather than a generation target, and bolts memory on as a separate retrieval module. UniWALM (Fig. 1(g)) uses a single video backbone jointly optimized for all three modalities, with video, action, and language as first-class diffusion heads co-denoised in one pass; the generated language is re-consumed next step, closing a language-as-memory loop with no external planner, VLM, or memory bank. Where prior world-action models supervise the backbone with frame-level predictive structure (future video), UniWALM adds a task-level predictive stream (future subtask and task state as language), a second, longer-horizon supervision signal that frame prediction alone cannot cheaply express.

In this work we study two questions: (i) does jointly generating language enrich the shared representation of a video-action model and improve manipulation? (Fig. 1(g)) and (ii) can a policy use its own generated language, re-consumed across steps, as working memory on memory-dependent tasks? (Fig. 2)

## Contributions.

We introduce UniWALM, a multimodal world-model architecture that takes a step toward any-to-any modeling across language, video, and actions, where each modality serves as both a conditioning signal and a supervision target. Specifically:

• 

World-Action-Language Model (WALM): We introduce WALM, a unified World Action Language Model implemented as a mixture of transformers that takes video, language, and actions as input and generates all three as output. The language stream emits a subtask and textual memory in the same denoising pass as action, and re-consumes them as prompt on the next control step, closing a language-as-memory loop. UniWALM’s language and action experts are trained from scratch on a video-only backbone: no pretrained language or reasoning model is used.

• 

Flow Matching with Correction (FMC). We introduce FMC to improve the reliability of generated actions. During training, FMC perturbs action trajectories and supervises a corrective velocity that returns the perturbed denoising path toward the clean trajectory. This trains recovery from action-space perturbations without adding model capacity or sampling steps at inference.

• 

Evaluation in simulation and real-world manipulation. UniWALM achieves the highest success on all three MolmoSpaces [24] compositional pick-and-place variants, improving over the same-backbone FastWAM baseline by +14.8% on average (Tab. 1). On RMBench’s memory-dependent M(n) subset, UniWALM reaches 34.5% without pretrained language or reasoning model, improving over same-backbone FastWAM (13.3%) by +21.2 points and above Mem-0’s keyframe-equipped setup (28.5%) using a single anchor frame instead of per-task privileged keyframes (Tab. 3). On a real-world bimanual Find-the-Item task, generating textual memory lifts success from 11.1% (FastWAM, same video backbone, no language) to 61.1%, while state-of-the-art VLAs stay at or below chance ( $\leq 33.3\%$ ) (Tab. 2).

Together, these results motivate further investigation of any-to-any world modeling as a foundation for generalist embodied agents.

## 2 Related Works

## Generalist Visuomotor Policies.

Generalist robot policies [36, 5, 14, 33, 46, 6, 34, 44] improve over single-task models [11, 57] by initializing from vision-language backbones [49, 13, 9, 39, 8, 32] and training for action. These policies map observations to actions but do not model world dynamics or reason over long-horizon subtasks.

## World-Action Models.

A recent line of works [52, 51, 23, 4, 16, 30, 27] adds a video-prediction objective, jointly modeling world dynamics and action. FastWAM [52], closest to our work, couples a pretrained Wan2.2 [45] video DiT with a parallel action DiT through unified attention. These models treat language purely as a conditioning input, never as a generation target and provide no mechanism for subtask reasoning or memory.

## Reasoning, Memory, and Hybrid Policies.

Long-horizon and memory-dependent tasks have motivated explicit reasoning and memory [10, 38], and hybrid systems [35, 43, 7, 25, 48] that combine a high-level VLM planner, a low-level policy, and a video model to imagine action effects. Because these components are trained separately on heterogeneous data, they lack a shared representation and execute planning and control asynchronously.

## Unified and Omnimodal Models.

Any-to-any modeling originates in multimodal LLMs [55, 47] which omit generating actions, and vision works like 4M [31], which unify many modalities via masked token modeling but target perception rather than control and do not reason. Concurrent work [48] additionally generates actions, DINO features, semantics, and video, but cannot reason or preserve memory during manipulation. Concurrent omnimodal models such as Cosmos 3 [1] extend any-to-any modeling to action within a single framework, but decode text autoregressively in one tower and continuous modalities by diffusion in another, running reasoning and generation as separate stages in a 64B model. UniWALM instead generates language, video, and action entirely by diffusion in one shared representation, denoising language and action synchronously so that reasoning and control co-refine in a single unified model.

An extended discussion contrasting UniWALM with CoT / inner-monologue policies, multi-scale memory VLAs, and recent unified models is deferred to Appendix A.

## 3 UniWALM

UniWALM jointly models the future video, robot actions, and language within a shared multimodal representation, enabling reasoning and control to be learned together.
Next, we describe its world-action-language formulation, multimodal co-training, and corrective flow-matching objective.

## 3.1 Reasoning with Video Action Models

Video Action Models typically map the current observation and a coarse prompt to near-term video and actions, with no explicit mechanism to generate language that can reason about subtasks or maintain task memory.
We introduce UniWALM, a World Action Language Model (WALM) that jointly generates future video, actions, and language within a unified model.
Its language generation expert is a diffusion model that provides language reasoning in the form of subtasks and memory.

## World Action Language Model (WALM).

World Action Language Models are a new class of models that take as input the current observation ( $\mathcal{O}$ , $k$ RGB views11
 1

 We use $k=2$ in MolmoSpaces sim and $k=3$ in real-world and RMBench sim.), robot state ( $\mathcal{S}$ ), visual memory $\mathcal{F}$ (a set of one or more frames), and task prompt ( $T$ ) to predict future video ( $\mathcal{V}$ ), action ( $\mathcal{A}$ ), language ( $L$ ), and a learned task-completion signal ( $\beta$ ) using a Mixture of Transformers (MoT) architecture with a single shared representation.
UniWALM (Fig. 2) is a step towards a single-representation, synchronous WALM. Formally, UniWALM jointly generates

 $\mathcal{V}_{1:H},\ (\mathcal{A},\ \beta)_{1:N},\ L\ :=\ \text{UniWALM }\big(\mathcal{O},\ \mathcal{S},\ \mathcal{F},\ T\big),$ 

where $\mathcal{V}_{1:H}$ is $H$ future frames, $(\mathcal{A},\beta)_{1:N}$ is a chunk of $N$ future actions each augmented with a 1-D task-completion signal $\beta$ that fires at subtask completion, and $L$ is a compact string (subtask $\|$ textual memory) re-consumed as prompt on the next control step. The visual memory $\mathcal{F}$ is an optional input, enabled for memory-dependent tasks (see Sec. 3.3) and omitted for standard manipulation. $\beta$ gates when the textual memory is advanced, so memory updates only at subtask completions.

## Generating Video, Action, and Language.

Given a pretrained video model, the observation frames are encoded first and passed through the video DiT.
We replicate the video DiT’s structure, matching its depth (30 layers) while reducing hidden dimension, to define the action and language DiTs, whose weights are initialized from scratch.
Each layer of the video, action, and language DiT processes features via unified self-attention enabling feature sharing between modalities.

UniWALM is a unified mixture-of-transformers (MoT) world-action-language model that co-denoises video, language, and action in a single shared representation.

The language stream emits a subtask together with a textual memory string, which is re-consumed as the prompt on the next control step, closing a language-as-memory loop across time. Video generation is disabled at inference, so the language and action DiTs run without producing future frames.

## Training the Language Expert for Reasoning.

Per-frame RGB prediction captures short-horizon dynamics but cannot cheaply carry task-level information (what subtask is active, what has been done), and we need this signal produced in the same pass as action rather than through a separate autoregressive planner.
We therefore adopt a discrete language diffusion [40] expert that denoises in tandem with video and action, giving us speed and architectural symmetry with the video model.
At each training step we perturb ground-truth text ( $L_{GT}$ ) depending on the diffusion time step, $t$ , and predict the correct token embedding ( $\hat{L}$ ) using a cross entropy objective ( $\mathcal{L}_{lang}$ ):

 $\displaystyle L_{t}:=\text{RandomReplace}(L_{GT},t)$ 

 $\displaystyle\hat{L}:=\text{DiffusionStep}(L_{t},t)$ 

 $\displaystyle\mathcal{L}_{lang}:=\text{CrossEntropy}(\hat{L},L_{GT}).$ 

This teaches the model to freeze already-correct tokens and update the incorrect ones based on the condition.
We use the language expert to predict the next subtask the robot should perform, and additionally emit textual memory for memory-dependent tasks.

## 3.2 Multi-Modal Co-Training

## Co-training Objective.

UniWALM trains Video DiT, Action DiT, and Language DiT in a co-training objective that combines the following:

 $\displaystyle\mathcal{L}_{video}:=||{}^{v}v^{\theta}_{t}-{}^{v}v^{GT}_{t}||_{1}$ 

 $\displaystyle\mathcal{L}_{action}:=||{}^{a}v^{\theta}_{t}-{}^{a}v^{GT}_{t}||_{1}$ 

 $\displaystyle\mathcal{L}:=\mathcal{L}_{video}+\mathcal{L}_{action}+\alpha\mathcal{L}_{lang}$ 

Here, $\mathcal{L}_{video},\mathcal{L}_{action}$ are flow-matching losses;
 $\mathcal{L}_{lang}$ is the discrete diffusion loss (Sec. 3.1).
The ${}^{v/a}v^{\theta}_{t}$ and ${}^{v/a}v^{GT}_{t}$ are predicted and ground truth velocities for video/action modality respectively.

We use an $\ell_{1}$ penalty for the flow-matching terms, which we find more stable than $\ell_{2}$ for learning actions. Together, these three terms supervise the shared representation at two levels of abstraction in parallel: $\mathcal{L}_{video}$ is frame-level predictive structure (per-step dense RGB prediction, which prior world-action models like FastWAM [52] and DreamZero [51] already use), while $\mathcal{L}_{lang}$ is task-level predictive structure (future subtask and task state as a short string), a longer-horizon signal that frame prediction alone cannot cheaply express; the action loss anchors both to physical behavior.
Training with both predictive levels in one backbone, rather than only one, is what lets a single end-to-end policy internalize the structure usually externalized to a planner or VLM.
During training, either all or a subset of the mixture of transformers can be trained in tandem depending on the availability of data to reap benefits from all modalities.

## 3.3 Memory

UniWALM integrates three memory mechanisms directly into the shared representation: a textual memory that is re-consumed as the next-step prompt (closing a language-as-memory loop without an external planner), a visual memory that admits one or more keyframes, and a task-completion channel that gates when the textual memory is updated. Full implementation details (RoPE-shifted keyframe tokenization, task-completion supervision, and RMBench-specific training configuration) are in Sec. B.4.

## Textual Memory Re-consumption.

Policies that reason once per step cannot carry information across step boundaries, which is exactly what long-horizon and memory-dependent tasks require. At inference, the language head emits a compact string (subtask $\|$ textual memory) in the same denoising pass as action. For memory-dependent tasks, this string is re-consumed as prompt on the next control step, closing a language-as-memory loop without an external planner or memory bank.

## Visual Memory.

Textual memory alone struggles with scene state that is hard to describe in words (precise object locations, occluded layouts), so we add a lightweight visual-memory stream $\mathcal{F}$ the policy can always attend to. For tasks that hide or move objects mid-episode, $\mathcal{F}$ preserves the layout otherwise lost as observations advance.

## Task-Completion Signal ( $\beta$ ).

If the textual memory is rewritten at every control step, intermediate reasoning overwrites past progress and the summary ceases to be a reliable record of what has been done, especially since the language stream has no explicit supervision for when a subtask is actually complete. We therefore co-train a 1-D task-completion channel $\beta$ , appended to the action vector, that fires at subtask completion and gates when the textual memory is updated, so the memory advances only at subtask boundaries rather than every step. Because $\beta$ is concatenated into the action vector, it is supervised jointly with the action by $\mathcal{L}_{action}$ (Sec. 3.2) and requires no additional loss term.

Taken together, these three mechanisms correspond to three distinct learned abstractions over the task that live in the shared representation: the generated subtask is a plan (what to do next), the generated textual memory is a running summary (what has been done), and $\beta$ is a task-completion signal (when to commit a subtask as done). All three are first-class outputs of the same backbone that generates video and action, not external modules bolted onto a pretrained VLM or retrieval buffer.

## 3.4 Flow Matching with Correction (FMC)

Flow matching [11, 28, 18] learns a parameterized velocity field $v^{\theta}_{t}$ that transports samples from a Gaussian prior $\mathcal{N}(0,I)$ to the data distribution $p_{\text{data}}(x)$ via a continuous normalizing flow.
During training, a data sample $x\sim p_{data}(x)$ is linearly noised to $x_{t}=(1-t)x+t\epsilon$ at timestep $t$ where $t\in[0,1]$ .
The parameterized function learns to estimate the velocity $v_{t}:=\frac{d}{dt}x_{t}=(\epsilon-x)$ using a mean-square-error objective $||v^{\theta}_{t}-v_{t}||_{2}$ where $v^{\theta}_{t}:=p_{\theta}(x_{t},t)$ is the predicted velocity.
Then data is sampled $x_{1}\sim\mathcal{N}(0,I)$ and denoised to the clean sample $x:=x_{1}-\int_{0}^{1}v^{\theta}_{t}dt$ .

Flow matching is a ubiquitous objective in training large scale video and action policies because it supports high-quality generation with relatively few sampling steps.
However, policies trained with flow matching often exhibit minor deviations during the generation process resulting in imprecise rollouts.
To curb this, we implement a flow correction strategy that simulates a perturbed noisy trajectory to teach the model to self-correct to a clean denoising trajectory, which we call Flow Matching with Correction (FMC).

Figure 3: 
Flow Matching with Correction (FMC).
A clean action $x_{0}$ (green path) and its perturbed counterpart $x_{0}+\epsilon_{1}$ (red path) are noised to the same time $t$ . The model is trained to transport the perturbed sample back onto the clean trajectory within $\Delta t$ (yellow arrow), while the clean branch follows standard flow matching. This requires no extra conditioning or model capacity and leaves inference unchanged.

Given a clean action $x_{0}$ (cf. Fig. 3(a)), we first construct a perturbed action $x^{p}_{0}:=x_{0}+\epsilon_{1}$ where $\epsilon_{1}\sim\mathcal{N}(0,sI)$ , where
 $s$ is the noise scale for perturbation (cf. Algo. 1).
The goal of flow correction is to avoid denoising to the perturbed action $x^{p}_{0}$ and instead denoise to the correct action $x_{0}$ . Using the same noise sample $\epsilon$ , the corresponding point at time $t$ is

 $x^{p}_{t}:=(1-t)x^{p}_{0}+t\epsilon,$ 

which lies off the nominal denoising trajectory. Applying the standard flow-matching target at this point would continue denoising without explicitly removing this deviation. Instead, FMC chooses a target velocity such that one reverse step of size $\Delta t$ from $x_{t}^{\mathrm{p}}$ returns to the nominal trajectory at $x_{t-\Delta t}=x_{t}^{\mathrm{p}}-\Delta tv_{\mathrm{corr}}$ .
Solving for the correction target yields

 $v_{\mathrm{corr}}:=\frac{x_{t}^{\mathrm{p}}-x_{t-\Delta t}}{\Delta t}=(\epsilon-x_{0})+\frac{1-t}{\Delta t}\epsilon_{1}.$ 

The expanded form makes the mechanism explicit: $v_{corr}$ is the standard flow-matching velocity $\epsilon-x_{0}$ plus a correction term that cancels the perturbation $\epsilon_{1}$ , and it reduces exactly to the standard target when $\epsilon_{1}=0$ .

Since the correction term scales with $(1-t)/\Delta t$ , we apply the correction branch only for $t\geq 0.5$ , ensuring the sample is close to the noise manifold and the correction magnitude remains bounded; at smaller $t$ the injected noise $\epsilon_{1}$ dominates and correction provides no meaningful signal.
The procedure is detailed in Algo. 1.
FMC teaches the policy to both denoise and self-correct in tandem.
Since the corrected velocity field coincides with the standard flow-matching field on the clean path, inference is unchanged: no additional conditioning, sampling steps, or model capacity is required.
This results in more precise actions and improves the policy’s success rate (Tab. 4).

FMC is related in spirit to corrective imitation approaches such as DAgger-style residual correction [37], yet operates entirely within the denoising process and does not require expert relabeling. It is also related to consistency-style objectives, but differs in its goal: rather than accelerating sampling, FMC trains recovery from local action-space perturbations around the ground-truth trajectory. A hyperparameter sweep over the perturbation scale, drift strength, and correction threshold on a 2D robot-trajectory benchmark is given in Sec. B.5.

## 3.5 Architecture and Training Details

## Architecture.

Figure 4: 
Mixture of Transformers Layer.
Each modality is processed by its own transformer that performs adaptive layer norm followed by Q,K,V projection.
The (a) unified self-attention enables feature sharing between different modalities.
Each modality transformer then cross attends to the (b) task instruction and proprioception for conditional generation of video, language, and action in a unified architecture.

UniWALM’s architecture consists of a video prediction backbone [45] and expands it to add action and language DiTs.
Our action and language DiT models are designed to match the video DiT and have $30$ layers each.
We reduce the size of the architecture by lowering the hidden dimension resulting in 1B action DiT (hidden dim $=1024$ ) and $0.5$ B language DiT (hidden dim $=512$ ).
Fig. 4 displays one instance of the MoT layer.
Each modality in the MoT expert layer has its own adaptive layer norm for time conditioning followed by $Q$ , $K$ , $V$ projection.
These query, key, and value tokens from video, action, and language are concatenated along the token dimension to perform a unified self-attention.
We use RoPE position encoding on the query and key for unified self attention.
The unified self-attention is followed by a cross attention operation that attends video, action, and language (queries) to the task instruction and proprioception (keys).

## Implementation Details.

Our approach initializes from a Wan2.2 pretrained model and attaches an action and language DiT expert.
We fine-tune the video backbone with LoRA (rank 256) [20], restricting its update to a low-rank subspace.
This reduces trainable parameters and makes optimization easier and more stable on limited data.
During training, we randomly drop proprioception with a probability of 10%, and use a single image as input.
We ensure that the reasoning tokens only attend to the visual features and input prompt and allow the action tokens to attend to the language tokens during generation (Fig. 2).
The model is trained with 8-bit AdamW optimizer [29, 15] on 12 H200 nodes with 8 gpus each for 44 hours.
We use an image resolution of 224 x 448 for simulator (two views) and 224 x 672 (three views) for real world experiments.
The language and action DiT are initialized from scratch.
We turn off video generation during inference, similar to FastWAM, and the language DiT runs synchronously with the action DiT.
Unoptimized UniWALM without language generation runs at 76 ms and with the language expert runs at 123 ms to generate an action chunk of 32 with 10 denoising steps.
Our model allows interleaved language generation by caching language features from the last step to choose the frequency of language generation.

Full training configuration: action chunk $N=32$ , video horizon $H=5$ , 20 action and language denoising steps at inference, batch size $3840$ , learning rate $4\mathrm{e}{-4}$ , 15k steps on the 221K-trajectory MolmoSpaces mixture (the ablation in Tab. 4 uses a $38K$ $Pick\&Place$ subset).
Our model generates 64 language tokens for each diffusion forward process.

## Data Flexibility.

UniWALM by construction has a modular architecture and training objective that supports co-training (by masking attention) on heterogeneous data (e.g., video-only, video-action, video-VQA, and video-action-VQA) within one representation.
We validate the design on in-domain video-action and reasoning data and leave large-scale multi-source co-training to future work.

## MolmoSpaces (sim, manipulation).

MolmoSpaces [24] contains 221K trajectories across Pick, Pick-RandCam, Pick&Place, Pick&Place-NextTo, and Pick&Place-Color on a DROID-style [22] Franka setup; we evaluate on 1000 OOD episodes per task using the Filament renderer, comparing against MolmoBot [14], $\pi_{0.5}$ [36], and FastWAM [52].

## RMBench $M(n)$ (sim, memory).

RMBench [10] organizes memory-dependent manipulation by the number $n$ of task-relevant past observations required for optimal action; we evaluate on all four $M(n)$ tasks (Press Button, Blocks Ranking Try, Cover Blocks, Battery Try) on a dual-arm AgileX tabletop, with 50 demos / 100 rollout episodes per task, against same-backbone FastWAM, Mem-0 [10] (with and without privileged keyframes), and concurrent WLA-0 [50].

## Real-World (dexterous, bi-manual).

Two Flexiv Rizon arms with dexterous hands (Sharpa Wave or Paxini) over three tasks (Fig. 5): Cube Pick & Place (simple, 44-DoF), Empty Container (bi-manual, varied items), and Find the Item (memory; items are covered mid-episode and queried). We evaluate on 20 held-out episodes per dexterous task and 18 for the memory task against $\pi_{0.5}$ [36], GROOT-N1.7 [33], FastWAM [52], and MolmoBot [14]. Full environment and per-task details are deferred to Appendix B.

## Q1: Language generation improves manipulation.

On MolmoSpaces (Tab. 1), UniWALM surpasses MolmoBot on all Pick&Place variants by +7% on average without video history, despite using neither video history nor a large-scale pretrained vision-language generator (only the Wan2.2 video backbone is pretrained; language and action DiTs are trained from scratch). That UniWALM still beats grounding- and language-pretrained baselines on compositional placement indicates the gains stem from the unified representation rather than inherited VLM priors.
FastWAM shares the same Wan2.2 backbone and action DiT structure, and is effectively the frame-level world model ablation of our co-training objective (video + action, no task-level language stream); against it, UniWALM improves success by 14.8% on average, isolating the benefit of adding task-level predictive structure.
UniWALM underperforms on the two short-horizon grasp-only tasks (Pick, Pick-RandCam), which are bounded by a 303-step budget that penalizes our more deliberate trajectories; our gains grow with task compositionality (highest on Pick&Place-NextTo and Pick&Place-Color), indicating the unified representation contributes most where reasoning and placement precision, not raw reaching speed, are the bottleneck.

## Q2: Generated language serves as working memory.

On RMBench’s memory-dependent $M(n)$ subset (Tab. 3, qualitative rollouts in Fig. 6), UniWALM succeeds 34.5% on average without any pretrained language or reasoning model, versus 13.3% for same-backbone FastWAM and 5–13% for other memoryless baselines (Mem-0 with its key memory ablated collapses to 4.8%); it also exceeds Mem-0’s keyframe-equipped setup (28.5%) using only a single anchor frame rather than per-task privileged keyframes. On RMBench we match the Mem-0 and WLA-0 input setup (visual memory + task-completion channel + textual memory), while using less information: no history keyframes. FastWAM shares our backbone and action-expert size but has no language stream; same-backbone FastWAM reaches only 13.3%, so the +21.2-point RMBench gap is attributable to the language-memory loop and the anchor-frame visual memory, with per-mechanism attribution in Tab. 5. Concurrent WLA-0 [50] scores higher but is a pipeline of a pretrained VLM plus a pretrained image-generation model linked via meta-queries; it inherits web-scale language and image-generation priors that UniWALM does not use, and does not form a unified representation. On the real-world Find-the-Item task (Tab. 2, rollouts in Fig. 9), we use textual memory only (no anchor frame, no task-completion channel) for fairness to the baselines ( $\pi_{0.5}$ , GR00T-N1.7, FastWAM, MolmoBot), which have no anchor-frame mechanism; the entire memory signal therefore comes from UniWALM’s own re-consumed language string. Objects are covered mid-episode, so any policy that re-plans from the current frame loses their identities; UniWALM’s re-consumed textual memory retains them across steps, raising success from 11.1% (FastWAM, same video backbone, no language) to 61.1%, while VLA and WAM baselines stay at or below chance ( $\leq 33.3\%$ ). This gap indicates that generating language reasoning, not action quality alone, drives memory-dependent performance. Per-mechanism attribution of the memory gain is in Sec. 4.1; a Press Button failure case is in Appendix B.

## Memory (Press Button).

A per-mechanism ablation on RMBench Press Button (Tab. 5) confirms language generation carries the memory signal. Under a limited training budget, visual memory alone (anchor frame only, no language generation) reaches only 1%, while language generation alone (no anchor frame) reaches 15%; the fully trained UniWALM with both visual memory and language generation reaches 51%. Both mechanisms are needed, with generated language carrying most of the signal: it encodes the symbolic state the policy needs to decide whether to press a given button, while the visual anchor stabilizes which buttons remain targets as frames advance.

## Conclusion.

We present UniWALM, a single-representation WALM that jointly denoises video, action, and language, and re-consumes its generated language as working memory for the next control step.
Without any pretrained language or reasoning model, UniWALM achieves state-of-the-art on MolmoSpaces Pick&Place (+14.8 pts over FastWAM), lifts real-world Find-the-Item from 11.1% to 61.1%, and reaches 34.5% on RMBench $M(n)$ , exceeding both memoryless baselines and Mem-0 [10]’s keyframe-equipped setup while using only a single anchor frame.

## Limitations.

Failures include grasping complex geometries and cluttered scenes. On RMBench we observe cases where the subtask and textual memory correctly track state but the action expert fails to execute it (e.g., subtask-boundary over/undershoot from task-completion timing lag; Fig. 12), and near-identical observations with different underlying memory occasionally confuse the model; the full list of failure modes is in Appendix C.

## Future Work.

We aim to scale multimodal co-training (ego-video, VQA, grounding), extend FMC to learn from the model’s own rollout errors, and extend visual memory to multiple keyframes; see Appendix D for extended directions.

## Appendix Contents

## Appendix A Related Works

## Generalist Visuomotor Policies.

Generalist robot policies [36, 5, 14, 33, 46, 6, 34, 44] improve over single-task models [11, 57] by initializing from vision-language backbones [49, 13, 9, 39, 8, 32] and training for action. These policies map observations to actions but do not model world dynamics or reason over long-horizon subtasks.

## World-Action Models.

A recent line of works [52, 51, 23, 4, 16, 30, 27] adds a video-prediction objective, jointly modeling world dynamics and action. FastWAM [52], closest to our work, couples a pretrained Wan2.2 [45] video DiT with a parallel action DiT through unified attention. These models treat language purely as a conditioning input, never as a generation target and provide no mechanism for subtask reasoning or memory.

## Reasoning, Memory, and Hybrid Policies.

Long-horizon and memory-dependent tasks have motivated explicit reasoning and memory [10, 38], and hybrid systems [35, 43, 7, 25, 48] that combine a high-level VLM planner, a low-level policy, and a video model to imagine action effects. Because these components are trained separately on heterogeneous data, they lack a shared representation and execute planning and control asynchronously.

## Unified and Omnimodal Models.

Any-to-any modeling originates in multimodal LLMs [55, 47] which omit generating actions, and vision works like 4M [31], which unify many modalities via masked token modeling but target perception rather than control and do not reason.
Concurrent work [48] additionally generates actions, DINO features, semantics, and video, but cannot reason or preserve memory during manipulation.
Concurrent omnimodal models such as Cosmos 3 [1] extend any-to-any modeling to action within a single framework, but decode text autoregressively in one tower and continuous modalities by diffusion in another, running reasoning and generation as separate stages in a 64B model.
UniWALM instead generates language, video, and action entirely by diffusion in one shared representation, denoising language and action synchronously so that reasoning and control co-refine in a single unified model.

## World-Action Models (WAM background).

World-Action Models (WAMs) [52, 51, 23] extend video-generation backbones with a parallel action head so that action prediction can leverage the priors learned by large-scale video pretraining. FastWAM [52] — the WAM we compare against throughout — initializes from a pretrained Wan2.2 [45] video DiT and attaches a matched action DiT whose tokens attend to the video tokens through a per-layer unified self-attention, followed by a cross-attention over proprioception and the task prompt. Language is consumed only as fixed conditioning; there is no language expert and no memory over time. UniWALM keeps the same video backbone and unified-attention mechanism but adds (i) a language DiT that co-denoises subtasks and textual memory alongside action, (ii) an anchor-frame visual memory, and (iii) the FMC training objective; the FastWAM-to-UniWALM delta therefore isolates these three additions under matched backbone.

## Multi-scale memory VLAs ( $\pi$ lineage).

MEM [42] equips a pretrained VLA with mixed-modal memory: a short-horizon stream of recent video frames compressed by a video encoder, and a long-horizon stream of language capturing abstracted semantic progress (e.g., which recipe stages are complete). $\pi_{0.7}$ [35] builds on the $\pi_{0.6}$ -MEM architecture and inherits the same memory design. Both approaches thus combine visual and textual memory, similar to UniWALM. Two key differences: (i) MEM and $\pi_{0.7}$ attach memory to a pretrained VLM/VLA backbone (autoregressive), whereas UniWALM’s language and action experts are trained from scratch on top of a video-only backbone; and (ii) UniWALM co-denoises language, action, and video synchronously in a single unified diffusion representation, whereas MEM’s long-horizon text summary is produced autoregressively by the pretrained VLM.

## Language-generating policies (CoT lineage).

A closely related line of work generates intermediate language during control: Inner Monologue [21], RT-2’s chain-of-thought [6], Embodied CoT (ECoT) [54], RT-H language action hierarchies [3], and CoT-VLA [56] predict rationales, subtasks, or “language actions” autoregressively and consume them as conditioning for the next action within the same control step. UniWALM differs on three axes. First, language is co-denoised synchronously with action in a single unified diffusion representation rather than produced autoregressively before conditioning. Second, the generated string is re-consumed as prompt on the following control step, closing an explicit memory loop across time rather than serving as within-step reasoning. Third, UniWALM supports both visual memory via anchor frames and textual memory via generated language, whereas the CoT lineage above uses only language-side reasoning. This distinction matters for memory-dependent tasks such as Find-the-Item: policies that reason once per step cannot carry information across step boundaries, whereas UniWALM’s readout persists as retrievable state.

## B.2 RMBench Environment and Tasks

The simulation environment for memory tasks uses RMBench [10]. RMBench organizes memory-dependent manipulation by task memory complexity: $M(N)$ denotes the class of tasks whose optimal decisions depend on retaining $N$ task-relevant past observations, capturing non-local and multi-step temporal dependencies. We evaluate on the four $M(N)$ tasks — (1) Press Button, (2) Blocks Ranking Try, (3) Cover Blocks, and (4) Battery Try — which each require repeated exploration or trial-and-error and cannot be solved from the current observation alone. RMBench is built on the RoboTwin 2.0 platform running on the SAPIEN physics engine, with a fixed dual-arm bimanual tabletop workspace using two AgileX arms. For each task we follow RMBench’s protocol of 50 expert demonstrations for training and 100 rollout episodes for evaluation.
Because RMBench requires repeated-attempt, multi-step tracking, we enable the anchor frame and task-completion channel for this benchmark; the MolmoSpaces and real-world experiments do not require them and run without them. Their implementation details are given in Sec. 3.5.
The following are the task descriptions:

• 

Press Button: press button involves pressing a button based on a count presented above the button. Given three buttons left, middle and right (confirm), the robot needs to read the number shown above left and middle button and press the respective button K times where K is the number displayed above the button.
The robot then needs to press the confirm button.
This task involves remembering the count of button presses followed pressing the confirm button.

• 

Blocks Ranking Try: The scene contains three colored blocks in a random initial arrangement and a confirm button. The task is to discover a specific target permutation by trial: the robot rearranges the blocks, hits the confirm button, receives feedback on whether the arrangement is correct, and repeats. Between attempts, the policy must retain which orderings have already been ruled out so it does not repeat a failed one.

• 

Cover Blocks: The robot faces three colored blocks and three covers. It first places a cover on each block from left to right, then must remove the covers in a fixed color order (red, then green, then blue) and return each cover to where it started. Because the blocks become visually hidden after covering, solving the second phase requires remembering which block was placed under each cover.

• 

Battery Try: A pair of batteries with random initial poses and a two-slot holder are staged on the table. The robot iteratively tries (battery, slot, orientation) combinations until both batteries seat correctly; combinations that previously failed must be recalled so the same attempt is not repeated.

## B.3 RMBench Training Configuration

For the RMBench $M(n)$ evaluation we train a separate UniWALM on the RMBench-provided demonstrations for 100k optimizer steps with batch size 448, which takes approximately 36 hours on 10 H100 nodes. The language DiT emits 64 language tokens per diffusion forward pass; all other model settings match the Implementation Details in Sec. 3.5.

## B.4 Memory Architecture Details

The following architecture choices for UniWALM’s memory channels apply across all benchmarks, independent of the specific evaluation setup.

## Visual Memory.

UniWALM conditions on one or more visual-memory keyframes captured during the episode. In our current experiments we use a single anchor frame $\mathcal{F}$ taken at episode start, which provides a persistent visual reference of the initial scene layout (e.g., pre-occlusion object positions) that is otherwise lost as later observations advance. Each visual-memory frame is passed through the same VAE encoder as the current observation and concatenated along the token dimension into the video stream, so the language and action DiTs attend to it via the shared unified self-attention. To avoid position-encoding overlap with the current observation, we shift the RoPE [41] coordinates of each visual-memory frame by the frame width $W$ and vary the 0th RoPE coordinate based on video timestep. The design accepts an arbitrary number of frames (e.g., a bank of task-relevant keyframes selected online), but we defer multi-frame visual memory to future work. Because the visual-memory keyframes and the observation are on separate RoPE grids, adding or removing memory frames does not change the network’s parameter count or interface; it only changes the number of memory tokens attended to.

## Task-Completion Supervision.

Task-completion signals are sparse, so we supervise the appended 1-D channel as a step function within each action chunk: 0 before the subtask completes and 1 at and after the completion timestep. Being part of the action vector, the channel is trained by the same flow-matching objective $\mathcal{L}_{action}$ , with no extra head or loss term.

The sweep varies three FMC hyperparameters:

•

•

• 

 $t_{\text{corrupt}}$ — the corruption time threshold: minimum diffusion time at which the correction branch is active. For $t<t_{\text{corrupt}}$ the model trains with standard flow matching; for $t\geq t_{\text{corrupt}}$ it trains the correction target $v_{\text{corr}}$ .

Each model is trained for 200k steps, and we evaluate 500 generated vs 1000 ground-truth trajectories per class using symmetric Chamfer distance in the flattened trajectory space. Chamfer is the appropriate signal here because FMC’s correction induces a different noise-to-data bijection than the baseline, so paired endpoint drift is dominated by this change of mapping rather than trajectory quality. ## Appendix C Limitations

UniWALM exhibits four main failure modes.
(i) Boundary misfires: the memory loop tracks state correctly but the task-completion signal $\beta$ fires one step late or early, causing an extra or missed press (Fig. 12; detailed case in the Failure Case subsection above).
(ii) Incorrect subtask prediction: on near-identical observations with different underlying memory state, the language stream occasionally emits the wrong next subtask.
(iii) Grasp precision: complex-geometry objects and cluttered scenes still bound task success.
(iv) Inference speed: generating an action chunk of 32 with the language expert at 10 denoising steps runs at 123 ms (76 ms without language; Sec. 3.5), which may be too slow for high-frequency closed-loop control.

## Appendix D Additional Future Work

Beyond the directions in the main paper, the UniWALM formulation opens several concrete extensions.

## Pretrained VLM initialization for the language DiT.

Our language DiT is trained from scratch. Initializing it from a pretrained vision-language model would inject broad semantic priors into the language-memory loop without altering the shared-denoising interface.

## Retrieval-augmented memory with a learned selection criterion.

The current textual memory is a single running string. Coupling it with an external episode log and a learned selection policy (choosing which past states or memory snippets to re-inject into the prompt) would extend the loop to long horizons and cross-episode settings.

## FMC from a replay buffer of the robot’s own mistakes.

FMC currently perturbs clean actions with Gaussian noise $\epsilon_{1}$ . A stronger variant is to construct the perturbation from the model’s actual rollout deviations: store rollout error pairs and train the correction target to recover the nominal path from these empirical errors rather than synthetic noise.

## Confidence-based flow matching.

A learned confidence head $c\in(0,1]$ over the predicted velocity, trained jointly with a log-penalty to prevent trivial collapse, would let the policy down-weight uncertain action predictions and expose an inference-time signal for guarded execution and targeted re-planning.

## Multi-keyframe visual memory.

Our visual-memory stream already supports an arbitrary number of frames (Sec. 3.5), but our experiments use a single anchor frame. A natural extension is to maintain a running history of keyframes (either at fixed intervals or selected online by the model) so the policy can attend to a bank of task-relevant past observations rather than a single snapshot at episode start.

## Balancing multiple conditioning signals.

When several conditioning streams are provided (e.g., a multi-keyframe visual-memory history, textual memory, current observation, and proprioception), careful training is required to prevent the policy from shortcutting to whichever stream is most predictive on the training distribution and ignoring the rest: for instance, collapsing onto the most recent keyframe while ignoring earlier ones, or ignoring the textual memory when the current frame alone is sufficient in-distribution. Explicit stream dropout, per-stream masking curricula, and information-theoretic regularizers that encourage the action expert to attend to the situation-relevant signal are promising directions for scaling UniWALM to richer memory and observation channels.

## Safety via language traces of intent.

Because UniWALM emits the next subtask and textual memory before the corresponding action is executed, the generated string is effectively a human-readable trace of the robot’s intention. This exposes a natural handle for safe deployment: downstream guards can veto or re-plan when the declared intention violates a constraint, operators can audit rollouts via the language log, and the trace supplies dense data for intention-conditioned alignment. Making this trace faithful (grounded in the actually-executed action), tamper-resistant, and expressive enough to cover safety-critical constraints is an important direction for future research.
