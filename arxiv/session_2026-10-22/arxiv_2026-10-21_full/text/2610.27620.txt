Abstract

Autonomous LLM agents act through tools under per-action authorization: a
local guard screens each tool call in isolation. We show that local authorization
does not compose into global authorization. A compositional authorization
failure (CAF) is a locally authorized execution, or a pair of locally authorized
executions, that violates a global policy spanning intent, purpose, provenance,
consent, and delegation. We characterize CAFs along two axes, expressiveness
(single-trace safety versus relational $k$ -safety) and observability (a ladder of
monitor profiles). Our central result is an impossibility: relational purpose
violations form a $2$ -safety hyperproperty with no per-trace locus of blame, so a
per-action monitor that never raises a false alarm detects none of them, independent of
the underlying model or decision procedure; they become visible only under
cross-execution monitoring, which none of the six guardrails we survey implements. We
make this constructive with AL-Synth, a SAT/SMT synthesizer (using no language
model) that emits minimal CAF witnesses, each checked against an exhaustive oracle. The
empirical signature is sharp: across nine LLM judges the per-action view approves the
synthesized witness almost without exception, blocking it at a rate comparable to a
benign control, yet the same models flag it when shown the two executions together.
Per-action authorization is therefore structurally insufficient for relational policy
conjuncts not reducible to single-trace safety: to bound them, a monitor must compare
executions or accept false alarms.

## I Introduction

Agents built on large language models act through tools: they read mail, write files,
call web services, and delegate subtasks. The dominant safeguard is per-action
authorization. A guard inspects each tool call in isolation and decides whether it is
permitted, and a sequence of approved steps is treated as an approved sequence.

This trust model is wrong in a way that matters: local authorization does not
compose. A sequence of individually permitted actions can violate a global policy,
alone or together with a second, equally compliant execution. We call such a witness a
compositional authorization failure (CAF), illustrated in Figure 1.

 $a_{1}$ $a_{2}$ $a_{3}$ $a_{4}$ each action locally authorizedglobal policy $\Phi$ over the whole trace: violated

Fig. 1: A compositional authorization failure, single-trace case. Every action passes
its local check (top), yet the composed trace violates the global policy $\Phi$ 
(bottom), with no single offending step. The relational purpose failure is witnessed
instead by a pair of individually compliant executions (Figure 3).

This is the agent-era form of a classical fact, that security properties need not compose [1], sharpened by two features. First, some
policies that agents must respect are
hyperproperties [2]: they constrain sets of executions, not single runs. A purpose constraint says that what an agent discloses must not depend on
context its declared purpose does not authorize, and checking this requires comparing
runs. Second, the guards being deployed are single-trace execution monitors in
Schneider’s sense [3]: each observes one run and decides.
The mismatch is a gap in expressive power, not an engineering gap that a better
per-trace monitor could close.

Our results are negative and constructive. We prove that one class of failure, the
relational purpose violation, has no per-trace locus of blame: a per-trace
monitor that never flags a compliant trace detects none of these violations,
because each trace alone is compliant and the violation lives only in the relationship
between runs. It becomes detectable only by comparing executions, which none of the six
guardrails we survey does. We make the result mechanical with AL-Synth, a
bounded model checker built on a SAT/SMT solver, with no language model, that
synthesizes minimal CAF witnesses and computes the monitor-coverage curve, validated
against an exhaustive oracle.

Three studies test whether the gap matters in practice. Nine language models, screening
each action of the synthesized witness, approve it almost without exception, yet the
same models flag it when shown both executions. A live open-weights agent commits a
consent-composition CAF in $22$ of $60$ rollouts, which an intent-only guard does not
measurably reduce and a composition-aware guard eliminates. An offline audit of Claude
Sonnet 4.6 finds that it resists every class we test. That agent is safe because the
model behaves, not because a monitor caught anything, and no false-alarm-free
single-execution monitor could have caught a leak, whatever the model.

Relation to classical results. The ingredients are classical, and we
claim none of them: security properties need not
compose [1], noninterference is a
hyperproperty [4, 2], execution
monitors enforce only safety [3], and noninterference can
be enforced precisely by running one execution per security
level [5]. What is new is what these facts imply for agent
authorization. An agent’s authorization policy splits into a trace-safety part and a
relational-purpose part. We give the exact condition under which the purpose part is
relational (Theorem 1), prove that no false-alarm-free per-trace monitor
detects it, whatever its decision procedure (Theorem 3), and extend
this to stochastic agents, for which even cross-execution sampling gives only
statistical detection (Theorems 4 and 5). Every
guardrail we survey sits on the trace-safety side. Given a tool schema, a workflow
policy, and a monitor profile, AL-Synth returns a minimal locally permitted
witness outside that monitor’s reach and names the observation the monitor would need
to catch it.

## II Threat Model and Background

Setting. We consider a single LLM agent that executes a bounded
episode in response to a user task. The agent issues a finite sequence of actions
(tool calls), each drawn from a typed action set, against an environment with
mutable state. A local authorization predicate decides, from the current
state and the action, whether the action is individually permitted. This predicate
abstracts the per-action guards, permission prompts, and tool-call monitors that
deployed agent frameworks use today. A global policy $\Phi$ expresses what
the user actually authorized for the episode as a whole.

Adversary. The adversary’s goal is a trace that satisfies every
local check yet violates $\Phi$ . We do not assume a jailbroken or
locally-misbehaving agent. The interesting case, and the one our theory targets,
is a benign-looking agent operating under a declared, legitimate purpose whose
composed behavior channels information or authority the purpose does not
grant. The adversary may influence the agent through ordinary means such as task
phrasing or injected content in tool results, but it does not need to defeat the
local guards; it needs the composition to do work the guards cannot see.

Running example. A scheduling assistant is asked to “find a
time for a team meeting next week” and is authorized to “share my free/busy
availability.” The purpose authorizes disclosure to depend on whether
each slot is free. It does not authorize disclosure to depend on why a
slot is busy, for instance that a busy block is a confidential interview rather
than an ordinary meeting. Every individual action the assistant takes (read the
calendar, propose slots, send the proposal) can pass a local check. Whether the
pattern of what it offers depends on the unauthorized reason is a property
of how it behaves across situations, not of any one message. We return to this example throughout.

Background. A trace property is a set of traces; a
hyperproperty [2] is a set of sets of
traces, and a $k$ -safety hyperproperty has a counterexample consisting of
 $k$ finite traces. Noninterference [4] is the canonical
 $2$ -safety property: it forbids high inputs from affecting low outputs, and a
violation is exhibited by two runs that agree on low inputs but differ on low
outputs. Realistic policies relax strict noninterference through
declassification [6], which specifies what high information may be released. An execution monitor observes a single run and may halt it, so it can enforce only safety properties of single traces [3, 7].

## III Compositional Authorization Failures

Model. An agent model is a typed transition system. A state
assigns values to a finite set of typed variables. An action $a$ carries a guard
 $g_{a}$ , a predicate on states, and an effect that updates a subset of variables.
A finite trace $t=a_{1}a_{2}\cdots a_{n}$ is locally authorized if, executing
from the initial state, each $a_{i}$ is enabled (its guard holds) in the state it is
taken from. We write $\Sigma^{*}$ for finite traces. For a trace we distinguish
three projections: $\mathsf{low}(t)$ , the declared purpose and other low inputs; $\mathsf{hi}(t)$ ,
the sensitive context the agent may read; and $\mathsf{obs}(t)$ , the outward disclosure
the agent produces.

Definition 1 (Compositional authorization failure).

Fix a model with local authorization predicate $\mathit{auth}$ and global policy
 $\Phi$ . A CAF witness is a finite, locally authorized object that witnesses a
violation of $\Phi$ : when $\Phi$ is a trace property, a single trace $t$ with
 $\mathit{auth}$ true at every step yet $t\not\models\Phi$ ; when $\Phi$ is a
hyperproperty, a finite tuple or set of traces, each locally authorized at every step,
that jointly violate $\Phi$ . We call the individual traces of a witness its
executions. For the relational purpose class the witness is a pair of executions
that are each compliant in isolation.

The global policy. We take $\Phi$ to be a conjunction of five
authorization concerns drawn from the access-control and privacy literature:

 $\Phi\;=\;C_{1}\wedge C_{2}^{D}\wedge C_{3}\wedge C_{4}\wedge C_{5},$ 

namely intent ( $C_{1}$ : actions stay within the user’s task), purpose ( $C_{2}^{D}$ :
disclosure depends only on purpose-authorized context), provenance ( $C_{3}$ : outputs
do not derive from untrusted or cross-domain sources in disallowed ways), consent
( $C_{4}$ : disclosure stays within consented scope, per action and cumulatively),
and delegation ( $C_{5}$ : delegated authority is exercised only when revalidated).
Four of the five are properties of a single trace. The purpose conjunct is not.

The purpose conjunct. Following the declassification
view [6], we parameterize purpose by a
declassification function $D$ , the purpose-authorized view of context, and
an abstraction $\alpha$ , the policy-relevant view of disclosure:

 $\displaystyle C_{2}^{D}\;=\;\big\{\,S:\forall\,t,t^{\prime}\!\in S.$ 
 $\displaystyle\mathsf{low}(t)=\mathsf{low}(t^{\prime})$ 

(1)

 $\displaystyle}{\displaystyle\wedge\,D(\mathsf{hi}(t))=D(\mathsf{hi}(t^{\prime}))$ 

 $\displaystyle}{\displaystyle\Rightarrow\;\alpha(\mathsf{obs}(t))=\alpha(\mathsf{obs}(t^{\prime}))\,\big\}.$ 

In words: two runs that agree on the low inputs and on everything the purpose
authorizes about context must agree on what they disclose. If they can differ,
disclosure is depending on something the purpose did not authorize.

The pair $(D,\alpha)$ comes from the policy. In the running example,
the purpose “schedule a team meeting” with consent “share free/busy availability”
fixes $D$ as the free/busy status of each slot, excluding the reasons slots are busy.
The abstraction $\alpha$ keeps the policy-relevant parts of a disclosure: which slots
are offered, any attached reason or label, the granularity, and the recipient.
Eq. (1) then says that, with the free/busy view fixed, the offered slots must
not depend on the reasons. For realistic workflows, specifying $(D,\alpha)$ can take
substantial human judgment. The impossibility does not depend on getting it right:
Theorem 3 holds for every pair, and violations exist exactly when the
pair is residual-nondegenerate (Definition 2, Theorem 1). A
misspecified pair changes which disclosures count as violations, and so what a
relational auditor flags, but no choice of $(D,\alpha)$ makes a nontrivial purpose
conjunct visible to a false-alarm-free per-action guard.

## IV A Two-Axis Characterization

The failure classes differ along two independent axes.

Axis 1: expressiveness. A class is either a property of a single
trace (a safety property, with a finite bad prefix as a witness) or a relational
property (a $k$ -safety hyperproperty, with a $k$ -trace witness). Intent,
provenance-by-path, consent, and delegation are single-trace. The purpose
conjunct $C_{2}^{D}$ is relational, and we prove this in §V.

Axis 2: observability. A monitor can only act on the state it is
instrumented to observe. We arrange instrumentation as a ladder of profiles
 $P_{0}$ through $P_{7}$ , each strictly more observant than the last. $P_{0}$ is pure
black box. Intermediate profiles add, in turn, an approximation of user intent,
information-flow labels and a purpose label, a provenance graph, per-action
consent state, a delegated-authority and revalidation view, and cumulative
digests of intent and consent. $P_{6}$ adds a cross-domain state-transfer view, the
strongest single-execution instrumentation we consider. $P_{7}$ is the only
profile with relational power: it can compare distinct executions of the
agent. A monitor at profile $P$ detects a class if it can both express the
class (Axis 1) and observe the state the class depends on (Axis 2).

Figure 2 places the eight subclasses on these axes. The single-trace classes
are covered one by one as instrumentation grows, and explicit labeled flow is covered,
conservatively, at $P_{6}$ . The relational purpose class is $2$ -safety, so no
single-execution profile can express it. It is covered only at $P_{7}$ , beyond every
system we survey.

## V Separation Results

We use the standard hyperproperty machinery [2].
For a set of traces $T$ , write $[T]=\{S:S\subseteq T\}$ for the hyperproperty it
induces; a hyperproperty is trace-property-induced if it equals $[T]$ for
some $T$ . We sketch each argument here. The full proofs are in Appendix A.

Lemma 1 (The monitorable region).

 $C_{1}$ , the path form of $C_{3}$ , $C_{4}$ , and $C_{5}$ are safety properties of single traces.

Each has the form “ $\forall t\in S.\,\phi(t)$ ” for a per-trace predicate $\phi$ ,
hence equals $[\{t:\phi(t)\}]$ , and each violation has a finite bad prefix. These
classes are exactly the ones a per-trace monitor can enforce. The labeled-flow form of
 $C_{3}$ , written $C_{3}^{\mathrm{lf}}$ , is itself relational ( $2$ -safety), but its
protected influence is a syntactic data flow from a labeled source to the output, and a
single-execution information-flow profile ( $P_{6}$ ) over-approximates it soundly through
taint tracking: $P_{6}$ enforces the single-trace property “no labeled value reaches a
low output,” which conservatively covers $C_{3}^{\mathrm{lf}}$ at the usual cost
of some false positives. That is why $C_{3}^{\mathrm{lf}}$ closes conservatively at $P_{6}$ .
The implicit, control-flow-dependent fragment of noninterference is not
 $C_{3}^{\mathrm{lf}}$ but the relational purpose class $C_{2}^{D}$ . Explicit-flow taint tracking misses it, and tracking control dependencies over-approximates it only by rejecting nearly every disclosure made after unauthorized context is read, compliant or not [8].

The relational purpose class $C_{2}^{D}$ is different. In a $C_{2}^{D}$ witness the agent
discloses from an authorized view that is identical in both worlds ( $\mathsf{low}$ and
 $D(\mathsf{hi})$ equal). No labeled value reaches the output, so taint tracking has nothing to
follow, and the dependence on the unauthorized reason shows only when the two executions
are compared. A single-execution monitor can over-approximate $C_{2}^{D}$ soundly, for
example by blocking every disclosure once unauthorized context is read, but only by
rejecting compliant traces. The results below make this precise: no single-execution
monitor enforces $C_{2}^{D}$ both completely and without false alarms, and cross-execution
comparison ( $P_{7}$ ) is the first observable that separates compliant from violating
disclosures.

Definition 2 (Residual-nondegenerate).

A pair $(D,\alpha)$ is residual-nondegenerate if there exist finite traces
 $a,b$ with $\mathsf{low}(a)=\mathsf{low}(b)$ , $D(\mathsf{hi}(a))=D(\mathsf{hi}(b))$ , and
 $\alpha(\mathsf{obs}(a))\neq\alpha(\mathsf{obs}(b))$ .

In plain terms, the declared declassification does not fix the disclosure, so
unauthorized context has room to move the output. We call this assumption Residual
Disclosure Freedom (RDF-D), and write RDF-DA when $a,b$ are restricted to the
locally authorized set $A$ . RDF-D characterizes $C_{2}^{D}$ (Theorem 1), and
RDF-DA makes the global policy $\Phi=[A]\cap C_{2}^{D}$ relational
(Theorem 2).

Theorem 1 (Exact characterization of $C_{2}^{D}$ ).

For every declassification $D$ and abstraction $\alpha$ :
(1) $C_{2}^{D}$ is $2$ -safety;
(2) $C_{2}^{D}$ is not trace-property-induced if and only if $(D,\alpha)$ is
residual-nondegenerate;
(3) if $(D,\alpha)$ is collapsing, $C_{2}^{D}$ is the trivial hyperproperty,
satisfied by every system.

The key observation is the singleton fact: because equality is reflexive, every
single-trace system $\{t\}$ satisfies $C_{2}^{D}$ . If $(D,\alpha)$ is nondegenerate, a
violating set contains a pair $a,b$ as in Definition 2, and finiteness
makes $\{a,b\}$ a $2$ -trace witness, which gives both $2$ -safety and, by the
singleton fact, non-inducedness. If it is collapsing, the implication in
Eq. (1) holds for all admissible pairs, so every system satisfies the
property and it is the trivial, trace-induced hyperproperty. The condition in
part (2) is exactly what the proof needs, and a constant abstraction $\alpha$ 
shows it cannot be dropped.

Theorem 2 ( $\Phi$ is relational under RDF-DA).

Let $A=\{t:C_{1}\wedge C_{3}\wedge C_{4}\wedge C_{5}\}$ , so $\Phi=[A]\cap C_{2}^{D}$ . If
 $(D,\alpha)$ is residual-nondegenerate with witnesses in $A$ (RDF-DA), then $\Phi$ 
is not trace-property-induced.

Take RDF-DA witnesses $a,b\in A$ . Each singleton satisfies $C_{2}^{D}$ by reflexivity and
lies in $[A]$ , so $\{a\},\{b\}\in\Phi$ . If $\Phi=[U]$ for some $U$ , then $a,b\in U$ ,
hence $\{a,b\}\in[U]=\Phi\subseteq C_{2}^{D}$ ; but $\{a,b\}\notin C_{2}^{D}$ by construction, a
contradiction. If RDF-DA fails, $\Phi$ collapses to a single-trace property and
per-trace monitoring suffices. RDF-D formalizes the premise of this paper: useful
assistants keep disclosure freedom beyond what their declared purpose fixes, and the
question is whether that freedom carries protected context.

## V-A The Locus theorems

The central result says that a relational purpose violation cannot be pinned to any single execution.

Theorem 3 (Set Locus).

A per-trace monitor that never raises a false alarm for $C_{2}^{D}$ detects no
violation of $C_{2}^{D}$ .

Every single trace satisfies $C_{2}^{D}$ (the singleton fact), so
a false-alarm-free per-trace monitor cannot flag any trace at all. Relational purpose violations have no per-trace locus of blame.

Contrapositively, a per-trace monitor that catches a genuine purpose violation
must also flag a compliant trace (Corollary 1). An LLM at nonzero
temperature is a distribution over traces, so the right property is distributional
independence rather than set equality. Set- $C_{2}^{D}$ over a stochastic agent’s support is
stronger than independence, since it also forbids context-independent randomness, which
leaks nothing, so independence is the deployable target.

Theorem 4 (Distributional Locus).

Let the observable $e$ available to a single-execution monitor contain exactly the
per-execution fields $\mathsf{low}$ , $D(\mathsf{hi})$ where exposed, and $\mathsf{obs}$ , but not the
nondeclassified context $H$ , not the agent’s full conditional distribution, and
not cross-context samples. Over the class of all stochastic agents, no monitor
that sees one such $e$ can soundly and completely decide
 $Y\perp H\mid\mathsf{low},D(\mathsf{hi})$ , where $Y=\alpha(\mathsf{obs})$ .

For any single observable $e$ of positive probability, one can construct a safe
agent ( $Y\perp H$ ) and a leaky agent ( $Y\not\perp H$ ) that both assign $e$ 
positive probability. The monitor sees the same $e$ under both: alarming is a
false alarm on the safe agent, and not alarming is a miss on the leaky one. A
single execution cannot certify distributional dependence model-free.

Theorem 5 (Two-dimensional barrier).

Under the ladder taxonomy and RDF-DA, no profile $P_{\leq 6}$ soundly and completely
enforces $\Phi$ , and none soundly detects $C_{2}^{D}$ . For the possibilistic property,
the relational profile $P_{7}$ crosses the barrier, since it can exhibit the
two-trace witness. For the distributional property the barrier has two dimensions,
and $P_{7}$ crosses only one of them: it crosses the expressiveness dimension,
because collecting cross-context samples escapes the per-trace limit, but it does
not cross the statistical dimension, because no finite-sample procedure can
soundly and completely decide arbitrary distributional independence over all
stochastic agents.

For the possibilistic property, $P_{7}$ compares two executions and exhibits the witness of
Theorem 1. For the distributional property, any finite sample is
consistent with two agents, one with $Y\perp H$ and one without, whose sample
distributions are arbitrarily close, so detection is statistical rather than certain.
Logics, model checking, and runtime verification for hyperproperties are established [9, 10, 11], including a probabilistic logic [12], so $P_{7}$ as a capability is known. Our
claim concerns deployment: no surveyed agent-authorization monitor implements it.

Corollary 1 (A design rule).

Detecting purpose violations admits exactly three responses: tolerate false
positives, audit offline with cross-context samples, or monitor relationally
(compare executions). A per-trace monitor that is both false-alarm-free and useful for
 $C_{2}^{D}$ does not exist.

## V-B An enumeration result, scoped

Counting, for each profile, the subclasses it cannot detect gives the
monitor-coverage curve $[8,7,6,5,4,3,2,1,0]$ from $P_{0}$ to $P_{7}$ . The endpoints
are proven: $P_{0}$ detects nothing, $P_{7}$ covers all eight classes under the
possibilistic semantics of Eq. (1), and the last class to fall is $C_{2}^{\mathrm{rel}}$ .
The intermediate values depend on our eight-class taxonomy and ladder. The central
result does not: Theorem 3 covers every per-trace monitor, whatever it
observes, so under any refinement or coarsening of the single-execution rungs the
relational row stays uncovered until a profile compares executions. Only the number and
order of the intermediate steps change. Stated narrowly: in our taxonomy, with
delegation scoped to per-action revalidation, exactly one class is not per-trace
monitorable, and it fails by expressiveness, not by any engineering limitation.

AL-Synth makes the gaps concrete. Given a model and a target class, it
synthesizes a minimal CAF witness (a trace, or a pair of traces for the relational

Dual semantics. Each action has two semantics over the same transition
system: a reference semantics, used by an exhaustive oracle, and an SMT encoding, used by
the solver. The harness checks that both induce the same CAFs, so agreement is tested
rather than assumed.

Bounded model checking. For a horizon $n$ , the solver encodes the
initial state, the variable ranges, the transition relation, and the
local-authorization invariant (at every step, the chosen action’s guard holds),
then conjoins the global violation at the final state. A satisfying assignment is
a length- $n$ CAF [13, 14]. We enumerate the complete
witness set at a horizon by adding a blocking clause after each model and
re-solving (all-SAT). For synthesis in practice we instead search for the minimal
witness, one satisfiability query per increasing horizon, which is far cheaper.

Relational witnesses by self-composition. A relational violation
is existential: it asks for a pair of traces that jointly witness a breach of
 $2$ -safety. We obtain it by self-composition [15]. Two
copies of the system run side by side, and the encoding asserts equality of the
low inputs and of the declassified view, $\mathsf{low}(a)=\mathsf{low}(b)$ and
 $D(\mathsf{hi}(a))=D(\mathsf{hi}(b))$ , together with inequality of the abstracted
observation, $\alpha(\mathsf{obs}(a))\neq\alpha(\mathsf{obs}(b))$ . This is exactly the negation of
the $C_{2}^{D}$ implication, so a satisfying assignment is a two-trace witness that the
agent’s disclosure depended on context the purpose did not authorize
(Figure 3). Generating a witness is existential, hence SAT. QBF arises only
in the universal direction, proving that a monitor cannot catch a class.

Instrumentation relativization. To synthesize a witness that is
invisible to a monitor at profile $P$ , the encoding conjoins, inside the same
query, the target violation with the negation of every safety check that $P$ can
both express and observe. The evasion is part of the constraint, not a filter
applied afterward.

## VII Validation and the Coverage Curve

We validate the solver against the exhaustive oracle on a family of small models,
small precisely so that brute-force enumeration is ground truth.

Differential testing. Three checks relate the solver to the
oracle, per class and horizon. T1, soundness: every solver witness, replayed
through the reference semantics, is locally authorized at every step and globally
unauthorized. T2, bounded completeness: the solver’s all-SAT witness set equals
the oracle’s set. T3, minimality: the solver’s minimal witness length equals the
oracle’s. All three pass for every class, including the relational class, whose
self-composed witness matches the oracle’s minimal pair. Oracle agreement is differential testing of two encodings of one intended semantics: it
catches encoding errors, but it does not show that the semantics models a deployment
correctly.

The coverage curve is measured, not assigned. For each profile and
class, the solver either synthesizes a witness the profile cannot see (a CAF that evades
every check the profile can run or, for the relational classes, the two-trace
counterexample) or certifies that none exists up to the horizon. Solver and oracle agree

## VIII Empirical Study: Monitor Blindness and Frontier Agents

We ask two questions. Do agent guardrails detect CAFs, and which ones? And does a
frontier agent commit the relational purpose violation when an adversary sets it up? The
first concerns the monitor, which is what the impossibility is about. The second
concerns the model.

## VIII-B Case study: the blind spot in a LangGraph workflow

To check that the blind spot is not an artifact of our abstract model, we reproduce it in
a scheduling workflow built on LangGraph [20], a widely used agent
framework. The graph (read, aggregate, propose) is gated by a per-action guard that runs
the standard tool-permission check plus purpose-label, provenance, and per-action consent
checks. Two worlds share the authorized free/busy view and differ only in the hidden
reason a slot is busy. The guard returns the same decisions (allow, allow, allow) in both
worlds, although the action arguments differ, and the agent offers slot $10$ in one world
and slot $11$ in the other. The AL-Synth relational auditor compares the runs
and flags the $C_{2}^{D}$ violation. We claim no vulnerability in LangGraph: the blindness
belongs to the per-action permission pattern, and the dependence could be a benign
tie-break, an adversarial choice, or an injected instruction, which no per-action guard
can tell apart.

## VIII-C A frontier agent, audited offline

The theorem says a per-trace monitor cannot catch the relational class. It does not say
whether real agents commit it. We test this directly, acting as an offline auditor with
the cross-context samples a deployed monitor lacks, on Claude Sonnet 4.6 used as a
tool-calling agent at fixed temperature (Table IV). For intent, an
injected instruction in a tool result asks the agent to forward output to an unintended
recipient, and it refuses every time. For consent, the agent stays within a narrow
authorized window every time, and on a deliberately vague variant it asks for
clarification instead of calling a tool. For relational purpose, a paired, interleaved,
pre-registered experiment holds the free/busy view fixed across two conditions that
differ only in the hidden reason, and gates on a high share rate so that a null reflects
disclosure rather than refusal. The agent does not leak.

## A false positive, kept on purpose

An initial analysis reported a
significant covert signal, stable across seeds. Raw-output inspection overturned it:
both conditions offered the identical set of slots, and the signal came from a feature
extractor counting a word whose phrasing happened to differ. Under the policy-relevant
abstraction $\alpha$ that Eq. (1) requires, the channel is clean. We keep the
episode because a result is a security result only under an abstraction that
tracks the policy, with raw-data inspection as a check that no statistical rigor
replaces.

## VIII-D Per-action judges approve the witness; the paired auditor catches it

The defense matrix places mechanisms by design. Here we put the witness in front of real
models. Nine language models judge the synthesized relational witness step by step:
eight hosted models (from Anthropic, OpenAI, Google, xAI, DeepSeek, Alibaba, Meta, and
Moonshot) and one local open-weights model. A bank of ten scenarios varies the slot pair,
the hidden reason, the task phrasing, and the A/B order, at three repetitions each, which
measure stability rather than add coverage. All judges run at temperature $0$ with a
 $4000$ -token budget, the hosted ones through OpenRouter’s default routing with no pinned
provider. Exact model identifiers are listed under Table V.

Eight judges never block the witness ( $0/30$ each). Kimi-K2.6 blocks it in $3$ of $180$ 
individual steps ( $3$ of $30$ scenario repetitions, across $3$ of the $10$ templates).
The discriminating control is a benign trace in which both worlds disclose the same slot.
DeepSeek blocks $2$ of its $180$ benign steps and Kimi $1$ , so Kimi’s witness blocks sit
in the same band as its benign blocks. They reflect single-step conservatism, not

## VIII-E A live agent commits a catchable CAF, and the right monitor closes it

The judge sweep shows that the relational class is invisible per action. A complementary
question is whether a live agent commits a class that a suitably instrumented guard
can catch, and whether the guard that closes it is the composition-aware one
rather than a more cautious per-action guard. We run Qwen3-30B as a tool-calling agent
on the cumulative-consent calendar task at temperature $0.7$ , with $60$ independent
rollouts per condition, all locally authorized and free of execution errors, under three
guards: none, an intent-closure guard that screens each action against the declared
purpose, and the composition-aware $P_{5}{+}$ guard, which denies an action once
cumulative disclosure exceeds the workflow’s consent bound.

With no guard, the agent commits the $C_{4}$ consent-composition CAF in $22$ of $60$ 
rollouts ( $37\%$ , Wilson $95\%$ CI $[26,49]$ ) and never on a clean-intent baseline or a
benign control ( $0/60$ each), so the failure is compositional rather than a local-guard
error (Table VI). The intent-closure guard leaves $20/60$ , $3.3$ 
points below no guard (Newcombe $95\%$ CI $[-13.4,19.8]$ , Fisher exact $p=0.85$ ), as
expected, since the disclosure is not visible in any single action’s purpose. The
composition-aware guard removes every offending trace ( $0/60$ , $33.3$ points below
intent-closure, CI $[21.1,45.9]$ , $p<10^{-6}$ ) while blocking $0/60$ benign and $0/60$ 
clean-intent rollouts, so no false positives were observed (one-sided $95\%$ upper bound $4.9\%$ for each control). We read this as the implementation
realizing the profile’s intended capability, not as a separate causal finding. A second
agent, Gemma-4, never commits the CAF ( $0/60$ throughout): the blind spot is structural,
while its exploitation depends on the model.

## IX Discussion

Detection requires comparison or false alarms. Single-trace monitors can
enforce intent, provenance, consent, and delegation checks when sufficiently
instrumented, but not the relational purpose conjunct without false positives
(Corollary 1). A designer has three detection options: accept and review
false positives, audit offline with cross-context samples, or monitor relationally by
comparing executions. Each has a cost, and a better single-trace guard is not among the
options. Prevention lies outside the corollary, because it changes what the agent sees
rather than what a monitor checks: generating each disclosure from the
purpose-authorized view alone removes the dependence by construction, the agent analogue
of secure multi-execution [5], at the price of an extra execution and
of any utility the unauthorized context would have added.

The model, not the monitor, carries the safety. In our experiments,
safety comes from the model’s behavior. The verifiable component, the monitor, is
provably blind to the relational class, so deployments rely on an unverifiable,
model-specific property that may not survive the next model. This argues for investing
in relational monitoring and offline purpose audits.

Limitations. Our validation is differential testing on small
models, not a proof of correctness and not a scalability study
(§VII). The symbolic models are clean and the tasks synthetic, which
bounds the empirical claims but not the theorem: the impossibility assumes no model of
any API, and noisier tools only add traces, which leaves the singleton fact intact. The
symbolic model feeds only the synthesizer, and its witness replays on an agent
framework (§VIII). The agent-behavior experiments cover two model
families, the nine-model campaign evaluates judges rather than autonomous tool-using
agents, and the guardrail matrix is design-derived, a bound whose direction
§VIII states. The purpose conjunct is modeled in the declassification
style [6] rather than the planning semantics of
purpose [21], and we view the two as complementary. Measuring the
relational class on realistic multi-tool workloads is the natural next step.

## X Related Work

Hyperproperties and their verification. Clarkson and
Schneider [2] introduced hyperproperties and $k$ -safety hyperproperties. Temporal logics for them [9] and model checking [10] followed, with runtime verification of $k$ -safety [11] and a logic for probabilistic hyperproperties [12]. We use this machinery rather than extend it.

Enforcement and composition. Schneider’s enforceable
policies [3] and the computability classes of enforcement
mechanisms [7] delimit what an execution monitor can do. Our
Locus theorems instantiate these limits: agent guardrails are execution monitors, and
relational purpose lies outside their reach. Noncomposability of security
properties [1], the access-control safety
problem [22], and noninterference [4] are the
roots of the questions we ask.

Declassification and purpose. We parameterize purpose by
declassification in the sense of Sabelfeld and
Sands [6]. Tschantz, Datta, and
Wing [21] formalize purpose restrictions through a planning
semantics. We see this as complementary to the information-flow view we adopt, and reconciling the two is open.

LLM-agent security. Indirect prompt
injection [23] is the overt, single-trace face of agent
insecurity, and our $C_{1}$ experiment lives in that space. Recent defenses are
per-execution monitors: task-alignment checking of each
action [16], control- and data-flow isolation with
capabilities [18], and information-flow taint-tracking
planners [8]. We place these on our ladder in §VIII. None compares distinct executions of the same purpose,
and the strongest of them concedes the gap: Fides [8] enforces
explicit secrecy but, by its authors’ own analysis, does not prevent implicit flows
through control-flow decisions, which is exactly the relational purpose channel our
Locus theorem isolates.

## XI Conclusion

Local authorization does not compose. We formalized the failure along expressiveness and
observability, and proved that the relational purpose violation has no per-trace locus
of blame, so no false-alarm-free per-action guard can detect it. AL-Synth makes
the result constructive: it computes the coverage curve, validated against an exhaustive
oracle, and names the observation each CAF class requires. Nine judges and a LangGraph workflow exhibit the separation in practice, a live agent shows the composition-aware guard closing a catchable CAF, and an offline audit finds no leak by a frontier model on the cases tested. The takeaway is a design rule, not a patch: to bound relational purpose, or any policy conjunct that is genuinely relational on the permitted executions, a monitor must compare executions or accept false alarms.

## Ethics Considerations

AL-Synth is dual-use: it synthesizes authorization-evading traces. The risk is
bounded because it works over an abstract model the analyst supplies and emits abstract
action sequences, not exploits, so using it against a real target already requires a
formal model of that target and its monitors. Its purpose is defensive, and the benefit
outweighs the marginal uplift to an attacker who already holds such a model. The study
used the authors’ own API accounts and local deployments, touched no third-party data or
production accounts, and collected no human-subjects data. We release the artifact
(https://github.com/anmolpandey299/al-synth) with documentation framing its defensive use.

## AI Disclosure

Two uses of generative AI are relevant. As a writing aid, a large language model
assistant helped draft and edit the prose across all sections. It did not originate the
theorems, the synthesizer, or the experimental design, which the authors developed,
implemented, and validated, and the authors verified the correctness and originality of
all content, including every reference and reported number.

Generative AI is also the object of study: §VIII evaluates language
models as tool-using agents and as per-action and relational judges, and reports their
settings (identifiers in Appendix C). Capable models are
necessary because the separation turns on whether disclosures depend on unauthorized
context, which weaker models do not exercise. We minimized query volume, report full

detects no violation. $\blacksquare$ 

Theorem 4.
Fix an observable value $e=(\mathsf{low},D(\mathsf{hi}),y)$ with $y=\alpha(\mathsf{obs})$ of positive
probability. Construct agent $\mathcal{A}_{0}$ whose output is independent of $H$ 
given $(\mathsf{low},D(\mathsf{hi}))$ and assigns $e$ positive probability, and agent
 $\mathcal{A}_{1}$ whose output depends on $H$ and also assigns $e$ positive
probability under some value of $H$ . Both are consistent with the single observed
 $e$ . A sound-and-complete monitor must alarm on $\mathcal{A}_{1}$ and not on
 $\mathcal{A}_{0}$ , but it sees the same $e$ in both, so any fixed decision on $e$ is
wrong for one of them. Hence no monitor seeing one such $e$ decides the property
soundly and completely over the class of all stochastic agents. $\blacksquare$ 

Theorem 5.
The first two clauses are Theorems 2 and 3 read on
the ladder: a $P_{\leq 6}$ monitor is single-execution, so it cannot express
 $C_{2}^{D}$ , and by Theorem 2 it cannot soundly and completely enforce
 $\Phi$ . For the possibilistic property, a $P_{7}$ monitor compares two executions
and exhibits the witness of Theorem 1, crossing the barrier. For
the distributional property, the expressiveness dimension is crossed because
cross-context sampling represents the comparison a per-trace monitor cannot, while
the statistical dimension is not crossed: by a standard indistinguishability
argument, for any finite sample there are two agents, one with $Y\perp H$ and one
without, whose sample distributions are arbitrarily close, so no finite-sample
test decides independence soundly and completely over all agents. Detection is
therefore statistical, not certain. $\blacksquare$ 

## Appendix B Monitor-Profile Survey

We map recent and deployed agent-authorization mechanisms to the profile ladder of
§IV. For each, we record from its primary source what per-execution
state it observes, whether it compares distinct executions of the same purpose, and
the resulting profile. Table II is the result. Every entry is
single-execution: each system inspects the current run (a tool call, its arguments,
data-flow or taint labels, or the running plan), and none compares two executions
of the same purpose to test whether disclosure depends on unauthorized context.
This substantiates the claim that no surveyed monitor reaches $P_{7}$ .

We assign each design the strongest profile its primary source plausibly supports, a
deliberately charitable upper bound: under-crediting a mechanism would only widen the
gap we report, so generosity makes our conclusion harder to reach, not easier. Task
Shield is $P_{1}$ because it checks each action against the user’s task (per-action
intent). RTBAS reaches $P_{3}$ because it carries information-flow taint and dependency
labels (provenance), and we charitably credit it with the weaker intent and
purpose-label observables a $P_{3}$ monitor subsumes. CaMeL reaches $P_{5}$ because it
extracts data and control flow and enforces capabilities (provenance, per-action
consent, and delegation scope). Fides and SAFEFLOW reach $P_{6}$ because they add
confidentiality and integrity labels with cross-domain reasoning. In every row the
cross-execution column is no for the same structural reason: each mechanism evaluates a
single execution and never compares two executions under matched low inputs and
declassified context, which is the only way to witness a relational purpose violation.
The assignment is thus generous on every axis except the one that matters, and on that
axis every surveyed design sits at zero.

The most advanced surveyed designs are information-flow systems. Taint tracking is conservative by construction, which places these systems in the false-positive corner of Corollary 1, and the strongest states its own limit: Fides enforces explicit secrecy but does not prevent implicit flows through control-flow decisions [8]. That residual channel is the
relational purpose violation of the Locus theorem, which AL-Synth’s relational
mode ( $P_{7}$ ) expresses by comparing same-purpose executions.
