Abstract.

Reasoning about fine-grained placement constraints, such as support and containment, is essential for realistic 3D scene creation.
It remains a significant challenge for existing methods that rely on simplified object representations like oriented bounding box (OBB), which are blind to the detailed geometry.
To address this limitation, we introduce GALA, a geometry-aware language model with explicit point cloud perception for controllable object placement.
Our model performs autoregressively by predicting the 6D pose of one target object at a time conditioned on the scene context and placement instruction.
We utilize a two-stage training strategy: the first stage aligns geometric and textual modalities through pretraining tasks, and the second stage fine-tunes the model for placement.
To facilitate this task, we also curate a multi-source scene dataset covering diverse room types and fine-grained furniture arrangements, which will be open-sourced for community benefit.
Experiments on our benchmark show our model significantly outperforms baselines without explicit geometric reasoning.
We further develop a multi-stage plan–place–verify agent pipeline that uses the model for text-driven scene generation.

## 1. Introduction

Generating realistic 3D scenes is important in game development, film production, architectural design, and embodied AI training, where virtual environments must be both physically plausible and semantically meaningful.
Scene construction can be viewed as an iterative process of single-object placement: each step inserts a new object conditioned on the scene built so far. This single-object placement problem is the focus of this work.
Placing a new object requires understanding both high-level semantic constraints, such as user instructions and object relationships, and low-level geometric constraints, such as collision avoidance, support, and containment.

However, most existing methods place objects only at the level of oriented bounding box (OBB): each object is represented by its center, size, and rotation.
This abstraction is sufficient for coarse arrangements, but it struggles with the geometric constraints in realistic scenes, as shown in Fig. 1.
Three basic failure modes are common in practice. First, a chair placed under a desk must clear the desktop with its seat while avoiding the table legs.
Second, small objects like books are often placed inside shelves whose internal cavities are invisible to the OBB.
Third, cushions placed on curved surfaces, such as sofas, require reasoning about support heights that vary across the contact region.
In all three cases, OBB-only methods cannot encode the fine-grained constraints, leading to either collisions (in OBB space), floating, or misalignments with the underlying geometry.

We view this limitation as primarily a geometry-awareness problem rather than an algorithmic one.
A natural solution is to bring geometric information into the placement problem through a 3D representation of the objects and the scene.
Among possible 3D representations, point clouds offer a favorable trade-off: they are lightweight, easy to obtain, and uniform across asset libraries, and recent work on 3D multimodal LLMs (Xu et al., 2024; Hong et al., 2023; Mao et al., 2026) shows that LLMs can consume point clouds directly.
Our core hypothesis is simple: LLM-based placement models augmented with point clouds can handle fine-grained arrangements beyond OBB reasoning.

Building on this hypothesis, we introduce GALA, a geometry-aware placement model.
The model is a multimodal LLM built on a strong LLM backbone, extended with a point cloud encoder and a projector that maps geometry features into the LLM embedding space.
Given an existing scene, an object to be placed, and a placement instruction, the model predicts the 6D pose of the target object.
The instruction specifies the intended relation and makes object insertion controllable.
To make the point cloud tokens readable to the LLM, we adopt a two-stage training recipe: geometric pretraining aligns the projector, and task fine-tuning adapts the full model for object placement.
Existing scene datasets, such as 3D-FRONT (Fu et al., 2021), contain noisy scenes and provide limited examples of fine-grained placement.
We therefore curate a multi-source scene dataset from 3D-FRONT, Imaginarium (Zhu et al., 2025), SpatialLM (Mao et al., 2026), and an artist-crafted set of 300 scenes, followed by filtering noisy layouts and adding fine-grained placement examples.
Finally, to make our model easier to use and support automated scene generation, we develop a multi-stage agent pipeline that converts textual user prompts into complete 3D scenes through object planning, instruction generation, and geometry-aware placement.

We summarize our contributions as follows.

• 

We introduce a geometry-aware language model for controllable object pose prediction conditioned on placement instruction and point cloud geometry, enabling fine-grained placement beyond OBB-based reasoning.

• 

We curate a multi-source high-quality scene dataset, combining public scenes and artist-crafted scenes.
The dataset is physically and visually verified, contains complex spatial relations, and will be open-sourced for community benefit.

• 

We develop a plan–place–verify agent system for automatic text-driven scene generation, integrating object planning, instruction generation, and geometry-aware placement.

## 2.1. Data-driven Scene Synthesis

Early learning-based approaches represent an indoor scene as a set of oriented bounding boxes and learn the joint distribution of object classes and box parameters, including convolutional (Wang et al., 2018; Wang et al., 2019) or recursive (Li et al., 2019) priors, autoregressive models (Paschalidou et al., 2021; Bucher and Armeni, 2025; Feng et al., 2026), and diffusion-based models (Tang et al., 2024).
Other lines of work model scenes as graphs and predict pairwise relations (Zhou et al., 2019; Gao et al., 2023; Zhai et al., 2023; Zhai et al., 2024; Lin and Mu, 2024).
These methods reason at the OBB level, so they cannot express the geometric detail needed to slide a chair under a table or place a book on a specific shelf inside a cabinet. They also tie generation to the scene dataset distribution, which limits generalization to unseen room types.

## 2.2. LLM- and VLM-based Scene Layout

A recent line of work treats LLMs and VLMs as priors over indoor scenes.
LayoutGPT (Feng et al., 2023) prompts an LLM with in-context examples to output object positions and sizes from a scene description, while LayoutVLM (Sun et al., 2025) leverages the visual abilities of modern VLMs to generate scenes from text.
Holodeck (Yang et al., 2024) decomposes scene generation into LLM-driven planning, asset retrieval, and constraint-based placement.
Because these model outputs are still coarse layouts, several methods add explicit optimization or solvers after the language-model stage.
(Gumin et al., 2025; Wu et al., 2026) generate indoor scenes through LLM-generated programs followed by layout optimization.
Co-Layout (Xiang et al., 2026) couples an LLM-driven agent workflow with grid-based integer programming to jointly optimize room layouts and furniture placements.
FirePlace (Huang et al., 2025a) similarly uses VLM-generated constraints and a solver for object placement.
Closer to our setting, PlaceIt3D (Abdelreheem et al., 2025) trains a 3D LLM for language-guided placement on reconstructed scanned scenes, but predicts a placement mask rather than a numeric 6D pose, and does not consider fine-grained containment relations.
These methods show that pretrained foundation models carry useful priors over spatial common sense, but they still make geometric decisions with coarse boxes, constraints, or solvers.
As a result, fine-grained placements that depend on object shape are not handled through native 3D geometric perception.

## 2.3. 3D Multimodal Large Language Models

Recent 3D multimodal LLMs extend language models from image-text reasoning to point-cloud and scene-level understanding.
Early systems such as 3D-LLM (Hong et al., 2023) and PointLLM (Xu et al., 2024) show that LLMs can describe 3D content, answer questions, and follow instructions when supplied with 3D inputs.
This direction has since expanded to more structured 3D tasks: 3D-LLaVA (Deng et al., 2025) studies general 3D instruction following, SegPoint (He et al., 2024) and Reason3D (Huang et al., 2025b) use LLMs for point-level segmentation from referring or reasoning queries, and SpatialLM (Mao et al., 2026) targets structured indoor scene understanding.
Recent 3D VLM work further studies spatial reasoning itself, such as SpatialStack (Zhang et al., 2026a), which focuses on point-language reasoning for 3D spatial relations.
These works make 3D geometry accessible to foundation models, but their outputs are mostly language responses, masks, or structured scene descriptions rather than precise poses for inserting a new object into an existing scene.
Our work uses the 3D multimodal formulation for object placement, where the model must map scene geometry, target object geometry, and a placement instruction to a numeric 6D pose.

## 3. Method

## Problem Formulation

We study a single-object placement task in a bounded scene region.
The scene region is described by a 2D footprint polygon $\mathcal{B}\subset\mathbb{R}^{2}$ , together with a floor point cloud $P_{\mathcal{B}}$ sampled on the area it encloses.
A scene consists of a set of existing object instances $\mathcal{O}_{\mathrm{exist}}=\{O_{i}\}_{i=0}^{N-1}$ .
Each existing object $O_{i}$ is associated with an identifier $i$ , a semantic category string $c_{i}$ , an axis-aligned size $\boldsymbol{s}_{i}=(w_{i},d_{i},h_{i})$ , and a point cloud $P_{i}$ .
Once placed, it has a 6D pose $\boldsymbol{p}_{i}=(x_{i},y_{i},z_{i},\phi_{i},\theta_{i},\psi_{i})$ , where $(x_{i},y_{i},z_{i})$ denotes the translation, and $(\phi_{i},\theta_{i},\psi_{i})$ denotes the roll, pitch, and yaw angles, respectively.
Here we use a world frame with $+X$ pointing right, $+Y$ pointing forward, and $+Z$ pointing up. By convention, an object faces the $-Y$ direction when $\psi_{i}=0$ , and positive yaw values are defined counterclockwise.
The object to be placed, $O_{\mathrm{tar}}$ , is specified by its category $c_{\mathrm{tar}}$ , size $\boldsymbol{s}_{\mathrm{tar}}$ , and point cloud $P_{\mathrm{tar}}$ , while the placement instruction $\boldsymbol{I}$ constrains the desired spatial relations to the scene and reference objects, for example “place the table against the west wall, in front of the sofa (id 0), and to the left of the wardrobe (id 3)”.
We want to train a predictor $f_{\theta}$ to output the 6D pose of the target object,

(1)

 $\boldsymbol{p}_{\mathrm{tar}}\;=\;f_{\theta}\!\left(\,\mathcal{B},\;P_{\mathcal{B}},\;\mathcal{O}_{\mathrm{exist}},\;c_{\mathrm{tar}},\;\boldsymbol{s}_{\mathrm{tar}},\;P_{\mathrm{tar}},\;\boldsymbol{I}\,\right).$ 

## 3.1. Geometry-Aware Multimodal Architecture

As illustrated in Fig. 2, we instantiate $f_{\theta}$ as a multimodal LLM whose text backbone is a pretrained causal LLM and whose geometric branch is a 3D point cloud encoder $\mathcal{E}$ followed by a projector $g$ .

## Point cloud perception module

To achieve precise geometric perception of 3D scenes, we employ Utonia (Zhang et al., 2026b), a state-of-the-art, self-supervised point transformer model. Its pretraining on diverse 3D data is crucial, as it mitigates the need for domain-specific priors, allowing the model to capture scene-level scale and fine-grained object geometry.
The encoder $\mathcal{E}$ takes a point cloud $P\in\mathbb{R}^{N_{p}\times C}$ with $N_{p}$ input points and $C$ channels (coordinates, color, and normals) as input, and returns a feature matrix $\mathcal{E}(P)\in\mathbb{R}^{M\times d_{e}}$ , where $M$ is the number of output point features, typically with $M<N_{p}$ , and $d_{e}$ is the feature dimension.

To avoid feature conflation from a single scene-level point cloud, we encode each object’s geometry independently. This gives the model separate point features for each instance.

## Geometric-to-text projection

We use a projector to align geometry features with the text embedding space.
The projector $g:\mathbb{R}^{d_{e}}\rightarrow\mathbb{R}^{d_{h}}$ is parameterized by a two-layer MLP with GELU activation, where $d_{h}$ is the LLM hidden dimension.
For the point cloud $P_{i}$ of $i$ -th object $O_{i}$ , the coupled encoder-projector architecture generates a block of geometric token embeddings,

(2)

 $\mathbf{H}^{(i)}=g(\mathcal{E}(P_{i}))=\left(\boldsymbol{h}^{(i)}_{1},\dots,\boldsymbol{h}^{(i)}_{M_{i}}\right),\quad\boldsymbol{h}^{(i)}_{m}\in\mathbb{R}^{d_{h}}.$ 

## Interleaved multimodal context

We interleave the projected point-cloud tokens with the text tokens according to their positions in the prompt.
The prompt verbalizes the inputs of Eq. 1 as a sequence of text segments, each followed by the point-cloud token block of the geometry it introduces.
The leading segment $\mathbf{u}_{\mathcal{B}}$ describes the footprint polygon $\mathcal{B}$ and is followed by the floor block $\mathbf{H}^{(\mathcal{B})}=g(\mathcal{E}(P_{\mathcal{B}}))$ .
Each existing object $O_{i}$ then contributes a segment $\mathbf{u}_{i}$ that lists its identifier, category, size, and pose $(i,c_{i},\boldsymbol{s}_{i},\boldsymbol{p}_{i})$ , followed by its geometry block $\mathbf{H}^{(i)}$ , for $i=0,\dots,N-1$ .
Segment $\mathbf{u}_{\mathrm{tar}}$ lists the target category and size $(c_{\mathrm{tar}},\boldsymbol{s}_{\mathrm{tar}})$ but no pose, and is followed by $\mathbf{H}^{(\mathrm{tar})}=g(\mathcal{E}(P_{\mathrm{tar}}))$ , while the final segment $\mathbf{u}_{\mathrm{ins}}$ carries the instruction $\boldsymbol{I}$ .
The floor and existing-object point clouds are encoded in world coordinates, the target point cloud in its canonical coordinates.
For example, $\mathbf{u}_{0}$ reads “object 0: sofa; size [2.10, 0.90, 0.85]; pose [1.20, 2.00, 0.43, 0, 0, 90]; point cloud: <pc>”, where the placeholder <pc> is replaced by the projected tokens $\mathbf{H}^{(0)}$ .
Writing $\mathbf{U}_{j}=\mathrm{TextEmb}(\mathbf{u}_{j})$ for each segment embedding, we obtain the interleaved context sequence,

(3)

 $\mathbf{X}_{\mathrm{ctx}}=\left[\mathbf{U}_{\mathcal{B}};\mathbf{H}^{(\mathcal{B})};\mathbf{U}_{0};\mathbf{H}^{(0)};\cdots;\mathbf{U}_{N-1};\mathbf{H}^{(N-1)};\mathbf{U}_{\mathrm{tar}};\mathbf{H}^{(\mathrm{tar})};\mathbf{U}_{\mathrm{ins}}\right].$ 

The causal LLM prefills this sequence with standard self-attention, perceiving the scene context and the target geometry jointly before it autoregressively decodes the target pose.

## 3.2. Dataset Construction

To train the geometry-aware placement model, we construct a high-quality scene dataset containing object semantics, point-level geometry, spatial relations, and 6D poses, following the pipeline in Fig. 3.
The dataset combines four complementary sources: two public datasets, 3D-FRONT (Fu et al., 2021) and Imaginarium (Zhu et al., 2025); a SpatialLM-PCG dataset generated from SpatialLM (Mao et al., 2026) scene annotations through procedural asset replacement and small-object enrichment; and an artist-crafted scene collection.
The PCG dataset increases the frequency and diversity of complex object relations, with construction details provided in the supplemental material.
As summarized in Fig. 4, the dataset covers a wide range of scene complexities. SpatialLM-PCG and artist-crafted scenes provide many placement instructions and increase the number of support and containment relations.

## Dataset filtering

As shown in Fig. 3, all sources are processed by a unified filtering pipeline before training.
Physics simulation and geometric validation correct or remove floating objects, severe interpenetrations, and out-of-bound placements.
We then render each candidate scene and use a VLM to score placement plausibility, scene coherence, visual quality, style consistency, and semantic reasonableness.
We discard samples failing these checks to reduce noisy supervision.

## Scene data structuring

We then convert each retained scene into single-step autoregressive placement samples.
For each object, we extract its category, size, location, rotation, and point cloud, and derive spatial relations from oriented bounding boxes in the world coordinate frame.
We build a floor-rooted scene tree $\mathcal{T}$ from relations defining placement dependencies: abs edges attach floor-supported objects to room-level location cues, while on/within/under edges attach objects to their supporting, containing, or overhead parents.
These labels are geometric predicates rather than colloquial terms: within requires the child OBB to lie inside the parent OBB, and on requires the child bottom to contact the parent OBB top.
A breadth-first traversal maps this tree to the linear placement order $\boldsymbol{\pi}=\mathrm{BFS}(\mathcal{T})=(\pi_{1},\dots,\pi_{N})$ .
For each target object in this order, the instruction is formed from its tree edge and augmented with nearby next to relations to provide local distance, direction, and facing context, such as left/right and front/behind, relative to already placed objects.
The target 6D pose serves as the supervision signal.

## 3.3. Two-Stage Training Strategies

Multimodal LLMs commonly separate modality alignment from downstream task fine-tuning: a lightweight projector is first trained to map visual or geometric features into the LLM token space, and the aligned model is then adapted to task-specific supervision (Liu et al., 2023; Xu et al., 2024; Deng et al., 2025).
We follow this recipe because our point encoder, projector, and LLM operate in different feature spaces.
We first align the geometric and language modalities through auxiliary alignment tasks, and then fine-tune the model on autoregressive placement.

## Training objective

Both stages use the standard causal language modeling objective.
For a training sample with context $\mathbf{X}_{\mathrm{ctx}}$ , let $\mathbf{t}=(t_{1},\dots,t_{L})$ denote the complete task-specific target token sequence.
With teacher forcing, we optimize the negative log-likelihood of the target tokens,

(4)

 $\mathcal{L}=-\sum_{\ell=1}^{L}\log p(t_{\ell}\mid\mathbf{X}_{\mathrm{ctx}},t_{<\ell}).$ 

## Stage 1: geometric–language alignment

We first construct auxiliary alignment samples from the scene dataset.
Each sample pairs the floor point cloud or a set of object point clouds with a textual question answerable only from geometry.
The questions cover boundary descriptions, object captions, object centers, sizes, rotations, and pairwise distances or displacements.
Since Utonia stays frozen, this stage does not learn geometry from scratch: the geometric competence already comes from large-scale pretraining, and the projector only has to map the pretrained features into the language embedding space.
PAR3D (Dai et al., 2026) builds part-aware 3D reasoning on the same encoder, indicating that its features retain shape detail well beyond a bounding box.

## Stage 2: autoregressive placement training

The aligned model is then fine-tuned on autoregressive placement samples.
Following the placement order $\boldsymbol{\pi}$ , the model conditions at step $n$ on the ground-truth poses of $O_{\pi_{1}},\dots,O_{\pi_{n-1}}$ and uses the pose of $O_{\pi_{n}}$ as the supervision target.
We serialize each 6D pose $\boldsymbol{p}=(x,y,z,\phi,\theta,\psi)$ into a fixed-format textual sequence and tokenize it with the LLM tokenizer.
The point encoder is kept frozen, while the projector and LLM are jointly trained to combine the textual instruction with geometric context and predict a precise pose.
At inference time, placement proceeds autoregressively: at each step, the model conditions on previously predicted poses, generates a textual pose sequence, parses it into numeric pose parameters, updates the scene with the newly placed object, and advances to the next one.

## 3.4. Agent Pipeline for Automated Scene Generation

For text-driven scene generation, we design a multi-stage agent pipeline that wraps GALA in a plan-place-verify loop, as shown in Fig. 5.
The pipeline separates semantic decisions from numeric ones: two off-the-shelf LLM agents decide what to place and how to describe it, while GALA, the only trained component, turns each description into a 6D pose.
The planner analyzes the user prompt once per scene and expands it into an ordered object list, giving each entry a category, a retrieval description, an estimated size, and the earlier objects its placement depends on.
Assets are retrieved from an asset library by description and size, and the list is ordered coarse to fine so that anchors precede the objects they support.
At each step, the instruction generator reads the current scene state, serialized as per-object identifiers, categories, sizes, and poses, together with the next object in the list.
It emits a placement instruction in the same relation vocabulary used for training, such as “place the mouse (id 14) on the mouse pad (id 13)”, so that GALA receives the same kind of instruction at inference as during training.
GALA predicts the pose of the target object, after which a verifier checks the updated scene for out-of-boundary placements, collisions, floating objects, and unsatisfied relations, and sends any failure back to the instruction generator for the next iteration.
The loop terminates once the object list is exhausted; the planner and instruction generator prompts are listed in the supplemental material.
Gallery results from this agent pipeline are shown in Fig. 10, spanning living rooms, storage spaces, corridors, rooftops, and outdoor alleys.

## 4.1. Experimental Settings

## Datasets

We use the two-stage datasets produced by the construction pipeline in Section 3.2.
To avoid leakage, we split scenes into train, validation, and test sets with stratified sampling over the source collections at an 18:1:1 ratio.
All evaluations are conducted on the test set.

## Evaluation metrics

We evaluate placements along two complementary axes: instruction following and geometric sensitivity.
Jointly, we deem a placement valid if its pose is well-formed, satisfies all specified relations, and is collision-free and non-floating.
We report two success rates over this criterion: Instruction Valid Rate, the overall validity across all test samples, and Within Valid Rate, the validity on containment (within) samples that serves as our primary geometry-sensitive metric since such relations demand local geometric reasoning.
We further report the Floating Rate and the bottom-surface Support Ratio to gauge physical support from the floor or existing objects.
Detailed metric definitions are provided in the supplemental material.

## Implementation details

We implement our model using LLaMA-Factory (Zheng et al., 2024), with Qwen3-0.6B (Yang et al., 2025) as the LLM backbone and Utonia (Zhang et al., 2026b) as the point encoder, for approximately 0.7B total parameters.
Training follows the two-stage recipe in Section 3.3.
In Stage 1, we train only the projector for 3 epochs with a global batch size of 256 and a learning rate of $1\times 10^{-3}$ .
In Stage 2, we fine-tune the LLM and projector for 4 epochs while keeping the point encoder frozen, using a global batch size of 128, an LLM learning rate of $2\times 10^{-5}$ , a projector learning rate of $5\times 10^{-4}$ , and cosine scheduling with 5% warmup.
We train models in bfloat16 on 8 NVIDIA H20 GPUs for about 7 hours.
At inference time, placing one object takes about one second on a single H20 GPU using roughly 3 GB of memory, and the supplemental material breaks down the runtime of the full agent pipeline.

## 4.2. Comparisons with State-of-the-Art Methods

## Quantitative Comparisons

We compare external baselines using a single-object insertion protocol, where each method places one target object in a fixed scene.
ATISS (Paschalidou et al., 2021) and ReSpace (Bucher and Armeni, 2025) serve as OBB-based references conditioned on object category.
Neither method accepts a specified placement instruction as input, so they are evaluated with only physical metrics.
For instruction conditioned baselines, we use a controlled LayoutVLM (Sun et al., 2025) adaptation: existing objects are fixed, only the target object is optimized, and the instruction is supplied as structured relations instead of being interpreted by a VLM, so that the baseline is scored on placement rather than on scene planning.
The supplemental material details this adaptation.
We also evaluate GPT-OSS-120B (Agarwal et al., 2025) as a zero-shot large parameter model baseline.
For ATISS and ReSpace, which predict both pose and size, we scale the target point cloud by the predicted size before computing physical metrics.

## 4.3. Ablation Studies

We isolate the contribution of point cloud input, Stage 1 alignment pretraining, and high-quality training scenes through controlled ablations on the same test dataset.
The high-quality scenes include the Imaginarium and artist-crafted subsets.

## Effect of point cloud input

The Instruction Valid Rate remains comparable across variants, indicating point cloud input does not substantially improve generic instruction-conditioned validity.
Removing point cloud input weakens the model most directly on the Within Valid Rate, where instruction following must be grounded in local containment geometry.
The same ablation also increases floating failures and reduces bottom-surface support, suggesting text-only context is insufficient for reliably grounding objects on available support surfaces.
Figure 7 corroborates these numbers: without point cloud input, the predicted objects frequently miss the referenced container, e.g., the fruit is placed outside the bookcase (column 1) even though the textual relation is parsed correctly.
Aggregate validity rates do not capture every fine-grained geometric failure. Measured directly, point cloud input reduces the target-center height error on within samples by about 14%, and a dedicated user study on this ablation prefers the point-cloud variant by a wide margin. Both analyses are reported in the supplemental material.

## Effect of alignment pretraining

Removing Stage 1 alignment pretraining leads to a similar degradation, even though the model still receives point cloud input during placement fine-tuning.
The Within Valid Rate decreases from 65.62% to 62.69%, showing the benefit of projector alignment.
Figure 7 exposes the same weakness qualitatively: without alignment pretraining, the fruit hovers in mid-air instead of resting on the shelf plank (column 1), and the blanket stays on the countertop and cuts into the basin instead of being placed inside the open compartment of the sink cabinet (column 4).
Together, these two ablations indicate explicit point cloud geometry and alignment pretraining are complementary.

## Effect of high-quality scenes

Removing high-quality training scenes including the Imaginarium and artist-crafted scenes produces the largest drop in Within Valid Rate.
This result suggests high-quality scenes primarily improve fine-grained geometric grounding for containment relations rather than generic instruction following validity.
The Floating Rate and Support Ratio also degrade, indicating these high-quality scenes provide useful supervision for stable object placement.
The qualitative cases in Fig. 7 mirror this trend: without high-quality scenes, the placed objects exhibit clear collisions or misalignment with the referenced anchors, e.g., the blanket cuts through the body of the sink cabinet and juts out beyond its side (column 4) and the briefcase overlaps the shelf frame (column 2) instead of resting inside it, whereas our full method produces collision-free placements that consistently satisfy the specified relations.
A stratified analysis in the supplementary material further shows this drop is concentrated on the high-quality test subset.

## 5. Conclusions

We propose GALA, a geometry-aware language model for controllable object arrangement.
By augmenting LLMs with point cloud perception and a two-stage training recipe, GALA can predict conditioned 6D poses.
Our approach captures fine-grained spatial constraints that are often missed by OBB-only methods.
We also integrate GALA seamlessly into an interactive agent framework for automated scene generation and editing.
Furthermore, we will release a dataset of high-fidelity scenes with verified, complex placements to facilitate future research.

## Limitations

Despite its advantages, GALA currently supports only a predefined set of placement instructions and cannot yet handle open-ended placement requests. Its performance also degrades when generalizing to previously unseen container geometries. Moreover, because objects are placed autoregressively, errors in earlier placements may propagate to subsequent ones.

## Future Work

Future research will extend this framework to handle noisy real-world scanned scenes, and support diverse interactive editing operations.
Another promising direction is explicit shape- or part-level supervision losses during two-stage training, which could strengthen geometric grounding.
Finally, because our model currently decodes pose tokens directly from context, future work could explore explicit chain-of-thought reasoning over geometry, in which the model first thinks about intermediate decisions, such as support-surface selection and the available space on that surface, before generating the pose.

SpatialLM provides room-scale semantic layouts in the form of object categories, approximate 3D boxes, and coarse poses.
We use these layouts as structural scaffolds rather than final training scenes.
As shown in Fig. 11, each proxy object is replaced by a plausible asset through category-constrained, size-and-shape-aware retrieval.
For a proxy object with category $c_{i}$ and box size
 $\mathbf{s}_{i}=(w_{i},d_{i},h_{i})$ , we consider only assets with the same
semantic category. Each candidate asset $m$ has a canonical box size
 $\mathbf{a}_{m}=(w_{m},d_{m},h_{m})$ and is ranked by

(5)

 $E(i,m)=\left\|\log\mathbf{a}_{m}-\log\mathbf{s}_{i}\right\|_{1}+\lambda\left\|\log\hat{\mathbf{a}}_{m}-\log\hat{\mathbf{s}}_{i}\right\|_{1},$ 

where $\hat{\mathbf{s}}=\mathbf{s}/(wdh)^{1/3}$ is a scale-invariant shape descriptor, and $\lambda$ balances absolute size matching and proportion matching.
We select the asset minimizing Eq. 5, then scale, orient, and place it to preserve the original layout.
The second term penalizes mismatched aspect ratios, reducing artifacts from extreme anisotropic scaling while keeping the spatial organization provided by SpatialLM.

After the major furniture layout is instantiated, we add small objects procedurally to enrich local interactions.
Candidate support and storage furniture, such as tables, cabinets, shelves, and TV stands, are assigned affordance regions derived from their geometry.
Small assets are sampled from category-compatible libraries and placed on, within, or near these regions with randomized offsets and orientations.
The generated objects remain anchored to plausible functional locations while increasing the frequency and diversity of support, containment, proximity, and directional relations in the placement instruction data.
The gallery in Fig. 12 illustrates the diversity of the curated scenes that result.

## Appendix C Reference Object Selection

Each autoregressive step conditions on the already placed objects.
To keep this context compact, we select a reference subset instead of passing the entire scene when the number of placed objects exceeds $K=8$ .

## Training-time selection

During data generation, the target pose is known and can be used to identify geometrically relevant references.
We first compute all spatial relations between the target object and the existing objects.
Among these relations, we retain the most informative ones for the language instruction by sorting relation candidates by relation priority and then by footprint edge distance.
Support and containment relations (on, under, and within) have the highest priority, followed by next-to proximity and then directional and facing relations.
The objects explicitly mentioned by these selected relations are always retained.

In addition, if the target object has a parent in the dependency forest, we retain up to $S=6$ already placed siblings under the same parent, chosen by increasing footprint edge distance to the target.
These sibling references help represent local occupancy around shared supports or containers, such as multiple items on the same shelf or table.
The remaining slots are filled with the nearest existing objects by footprint edge distance.
The final selected set is sorted back into autoregressive order before being serialized.
If the mandatory references exceed the nominal cap, we keep all mandatory references rather than dropping supporting or sibling context.

## Rollout-time selection

At inference time, the target pose is unknown, so edge-distance ranking to the target is unavailable.
We therefore use an importance-based proxy.
Mandatory semantic dependencies specified by the planner are retained first; if a retained object is itself a sub-object, its parent is recursively retained as well.
The remaining slots are allocated between large anchors and recent context: 60% of the available slots are assigned to objects with the largest footprint area, and the rest to the most recently introduced objects.
As in training, the selected references are returned in autoregressive order.
This policy preserves stable scene anchors while keeping the most recent local context available for the next placement.

## Appendix D Design-Prior Object Ordering

Our autoregressive training samples require a deterministic order for introducing objects into a scene.
Instead of relying on the arbitrary order stored in the source datasets, we use the design-prior heuristic of Algorithm 1, which approximates a coarse-to-fine layout process.
It places large structural anchors first, then introduces smaller objects once the supporting or containing geometry they depend on is available.

We first infer a dependency forest from pairwise spatial relations.
If object $O_{i}$ is on, within, or under object $O_{j}$ , then $O_{j}$ is treated as the parent of $O_{i}$ , because $O_{j}$ provides the support, container, or overhead structure needed to localize $O_{i}$ .
When multiple parent candidates exist, we prefer supporting relations over containment and under-object dependencies, and select the smallest parent footprint among candidates with the same priority.
This favors the most specific geometric reference, such as a shelf board over the entire cabinet.
Floor-covering objects are not used as supporting parents for on relations.

      end if

   end foreach

   if $\mathcal{C}_{i}\neq\varnothing$ then

       $\mathrm{parent}(i)\leftarrow$ 
the candidate with highest priority and smallest footprint area;

   end if

end foreach

Break each cyclic dependency by making the lowest object in the cycle a root;

 $\mathcal{R}\leftarrow\{i\mid\mathrm{parent}(i)=\varnothing\}$ ;

Sort $\mathcal{R}$ by increasing $(-a_{i},b_{i},i)$ ;

 $\pi\leftarrow\mathcal{R}$ ;

 $\mathcal{L}\leftarrow\mathcal{R}$ ; // current breadth-first layer

while $\mathcal{L}\neq\varnothing$ do

    $\mathcal{L}^{\prime}\leftarrow\varnothing$ ;

   foreach $p\in\mathcal{L}$ in order do

       $\mathcal{K}_{p}\leftarrow\{i\mid\mathrm{parent}(i)=p\}$ ;

      Sort $\mathcal{K}_{p}$ by increasing $(-a_{i},b_{i},i)$ ;

      Append $\mathcal{K}_{p}$ to $\mathcal{L}^{\prime}$ ;

   end foreach

   Append $\mathcal{L}^{\prime}$ to $\pi$ ;

    $\mathcal{L}\leftarrow\mathcal{L}^{\prime}$ ;

end while

return $\pi$ ;

The resulting sequence is not meant to model a single universal human ordering.
Instead, it encodes the practical dependency: fine-grained objects are easier to place after their geometric anchors are present.
In the generated training data, object identifiers are reassigned according to this sequence, so each autoregressive step conditions only on objects already introduced by the design-prior order.

## Appendix E Evaluation Metric Definitions

This section gives the exact definitions of the metrics reported in the main paper and in this supplement.
Each evaluation sample contains an existing scene, a target object point cloud, a predicted 6D pose, and a set of expected instruction relations.
All methods, including the baselines, are scored by the same evaluator.

## Collision

Collisions are detected directly on raw point clouds, without convex-hull or mesh conversion, so that hollow containers such as cabinets and shelves are treated as the open geometry they are.
We voxelize the posed target point cloud and every existing-object point cloud at a resolution of $0.02\,\mathrm{m}$ , and denote by $V_{\mathrm{tar}}$ the set of occupied target voxels and by $V_{\mathrm{ovl}}$ the subset of them also occupied by some existing object.
A placement is marked as colliding when

(6)

 $|V_{\mathrm{ovl}}|\,/\,|V_{\mathrm{tar}}|>0.20.$ 

Thresholding a ratio rather than an absolute overlap keeps the criterion scale-invariant across object sizes and tolerates the thin-shell interpenetration that point-cloud discretization inevitably produces, while still rejecting placements that pass through existing geometry.

## Floating Rate and Support Ratio

To measure physical support, we first transform the target object point cloud by the predicted pose and take the lowest 10% of its points by $z$ value as the bottom surface $B$ .
A 2D support height map is built from the floor point cloud and from existing-object points no higher than the target bottom plus a small gap tolerance.
For each bottom point $p\in B$ , we search a $5\times 5$ voxel neighborhood in this map and record the nearest supporting height below the point.
The point is considered supported if its vertical gap to this support surface is at most $\tau_{\mathrm{gap}}=0.05\,\mathrm{m}$ .
The Support Ratio is

(7)

 $r_{\mathrm{sup}}=\frac{1}{|B|}\sum_{p\in B}\mathbb{I}\left[\operatorname{gap}(p)\leq\tau_{\mathrm{gap}}\right].$ 

If the target object height is available and the predicted center height is within $0.05\,\mathrm{m}$ of the floor-contact height from both sides, the sample is treated as floor-supported directly.
For the full point-cloud check, we also flag a placement as sinking when the median bottom-surface gap is below $-\tau_{\mathrm{gap}}$ , indicating the object has sunk into the supporting surface.
A placement is counted as floating when $r_{\mathrm{sup}}<0.30$ or when this sinking condition holds.
We report Floating Rate as the fraction of floating placements and Support Ratio as the mean of $r_{\mathrm{sup}}$ , where samples resolved by the floor-contact shortcut above contribute $r_{\mathrm{sup}}=1$ .

## Instruction Valid Rate and Within Valid Rate

For each sample $i$ , let $P_{i}$ indicate whether the model output can be parsed as a valid 6D pose, $S_{i}$ indicate whether all expected instruction relations are satisfied, $C_{i}$ indicate collision, and $F_{i}$ indicate floating.
Let $I_{i}$ be the Instruction Valid indicator:

(8)

 $I_{i}=P_{i}\wedge S_{i}\wedge\neg C_{i}\wedge\neg F_{i}.$ 

The Instruction Valid Rate is the average of this indicator over all evaluated samples.
The Within Valid Rate uses the same indicator on the subset $\mathcal{W}$ of samples whose expected relations contain at least one within relation:

(9)

 $\operatorname{WithinValid}=\frac{1}{|\mathcal{W}|}\sum_{i\in\mathcal{W}}I_{i}.$ 

This subset is particularly sensitive to point-level geometry because containment and insertion often depend on openings, shelves, and support surfaces missing from coarse bounding boxes.

## Appendix G LayoutVLM Adaptation

LayoutVLM synthesizes a scene by having a VLM propose differentiable spatial constraints and a gradient-based solver optimize the asset poses jointly.
Since our protocol fixes the scene and inserts a single object, we supply the instruction directly as the structured relations of Table 4, which grants the baseline oracle instruction parsing, and let its solver optimize only the target pose while all existing objects stay frozen.
Like the original method, the adaptation reasons over oriented bounding boxes and derives the placement height from the reference box, using its top face for on and its center height for within.
For the whole-scene comparison in the main paper, it runs autoregressively under the same protocol as our model, inserting objects one at a time in the order and with the per-step instructions of the held-out test scene.

⬇

You are a professional scene layout assistant. Your task is to generate placement instructions for objects in a scene.

## Coordinate and Relation Vocabulary

- Use a right-handed coordinate system: +X = right/east, +Y = front/north, +Z = up.

- Absolute relations:

 * Wall: "against east/west/north/south wall"

 * Corner: "at northeast/northwest/southeast/southwest corner"

 * Region: "in front/back/left/right/center region"

- Relative relations:

 * Directional: "left", "right", "in_front", "behind" (edge distance < 1.5m)

 * Proximity/orientation: "next_to" (edge distance < 0.5m), "face_to"

 * Support/containment: "on", "under", "within"

## CRITICAL: Space Awareness Before Using Direction Relations

Before using a direction relation, compute the object's bounding box and check that the target direction is not blocked by a wall or boundary. If an object is already against a wall on one side, do NOT place another object further in that direction.

## Guidelines

- First analyze the scene context and existing objects to understand the scene layout

- Calculate available space in each direction before choosing a relation

- Use existing object IDs and short descriptions as references

- Combine absolute and relative relations when appropriate

- Be specific but concise

- Consider the object's function and typical placement patterns

## Main Objects vs Sub-Objects

- Main objects are standalone room-level objects (e.g., bed, sofa, desk, wardrobe). Set "parent_id": null and include appropriate absolute relations.

- Sub-objects are placed ON/WITHIN/UNDER a parent object (e.g., pillow on a bed, book on a shelf, chair under a desk). Set "parent_id" to the parent ID and omit absolute relations.

## Relation Rules

- Include at most 3 relations total, prioritized as: on/within/under > next_to > directional.

- Use at most one wall relation; use a corner relation instead of combining two wall relations.

- For any sub-object resting on or contacting a bed or sofa, use "within" rather than "on".

- If a parent already has sub-objects, add a directional relation to an existing sibling to avoid collision.

{

 "thinking": "Your step-by-step reasoning about where to place the object...",

 "parent_id": null,

 "expected_relations": {

 "relative_relations": [

 {"type": "relation_type", "target_id": reference_object_id}

 ],

 "absolute_relations": ["relation_type"]

 }

}

## Representative Examples

- Main object: next_to + directional relation to an existing anchor, with an optional wall relation.

- Sub-object: support/containment relation to its parent only.

- Crowded parent: support/containment relation to the parent plus a directional relation to an existing sibling.
