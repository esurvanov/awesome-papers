Abstract

Long-horizon dialogue agents need to keep user memories stable enough for personalization while adapting when the user genuinely changes. Existing memory systems often append every observation or overwrite old entries by heuristic rules, which makes transient noise hard to distinguish from real belief drift. We introduce PreCoMem, a memory consolidation framework inspired by predictive coding that represents memory as confidence-weighted beliefs about the user’s state. Its core signal, Effective Surprisal, combines semantic deviation and contradiction evidence, then downweights this signal when retrieval is diffuse and unreliable. According to effective surprisal, a two-threshold gate maps each turn to one of three deterministic updates: MAINTAIN reinforces supported beliefs, PROFILE stores ambiguous cues as low-confidence hypotheses, and CORRECT softly decays reliably contradicted facts. The PROFILE stage acts as an explicit waiting room, preventing premature commitment to noisy evidence. Experiments on LoCoMo, LongMemEval-S, and PersonaMem-v2 show consistent state-of-the-art accuracy; our new DiMoBench confirms that PreCoMem adapts to non-stationary belief drift without over-reacting to noise. The code is available at https://github.com/ZhongWishing/PreCoMem.

## 1 Introduction

Figure 1: Memory evolution case study (coffee $\rightarrow$ tea). PreCoMem autonomously manages the lifecycle of facts and hypotheses, achieving a stable transition between conflicting belief states without manual intervention.

Large Language Models (LLMs) are moving from stateless responders toward long-term partners that interact with the user over hundreds or thousands of turns [32, 39, 44]. Such partners need more than stored transcripts; they require a user model to sustain personalized interaction [51, 15].
To formalize the core units of this user model, we define a belief as a compact, actionable claim about the user’s preferences, goals, or life context, paired with a confidence weight that can be reinforced or revised over time.
This user model underpins both agent personalization and behavioral self-correction, thereby redefining the role of long-term memory: rather than merely serving as simple context extension [30, 41], long-term memory enables the agent to maintain consistent behavior across sessions.

The harder question is not whether information can be stored, but how it should be consolidated and revised. A practical memory consolidation mechanism must decide which observations to retain, how strongly to trust them, and when to maintain, revise, or correct stored items without explicit supervision. We refer to this as the memory stability–plasticity problem: the agent should preserve stable user traits while remaining plastic enough to adapt when those traits change [6]. Long-horizon interaction makes the problem hard for three coupled reasons. First, most turns carry little signal, while a small fraction may contain cues indicative of more persistent user states. Second, user preferences and life facts evolve over time [5], so the system must adapt under non-stationarity and belief drift [49, 7]. Third, corrective feedback is rarely explicit [14], and noisy retrieval over long contexts further blurs the picture [48, 25, 4, 43]. Therefore, the brittle memory update mechanism causes two opposite failures: premature correction from noise, or persistent over-reliance on outdated memories, which we call old-memory pull, a phenomenon related to loss of plasticity and retrieval interference in continual adaptation systems [6, 11].

Recent memory systems have made impressive progress on retrieval and storage organization. Hierarchical and OS-style stores [30, 23, 10], structured indices with timestamps or topic shards [34, 40, 21, 38], and agentic retrievers [45, 46] all sharpen what the system can recall. However, the question of when to update is still often handled by recency overwriting, fixed-threshold importance, or one-shot append rules [51, 2]. These triggers cannot reliably separate persistent drift from transient noise [11], so they collapse the stability–plasticity trade-off precisely where long-horizon dialogue stresses it most. A fuller literature discussion is provided in Appendix Appendix A.

We draw inspiration from predictive coding, which posits that learning is driven by mismatch between expectation and reality, i.e., prediction error [8, 3]. In information theory the same quantity is called surprisal [19, 29]. We use this view as a design principle for the update path rather than as a claim that dialogue memory is a fully specified probabilistic model. The resulting criterion is simple: events consistent with current memory should be reinforced, while surprising events may require learning or correction [33, 36]. Crucially, surprisal must be paired with a measure of retrieval reliability, so that update decisions stay conservative when recall itself is uncertain or noisy [18, 48].

Building on this view, we propose PreCoMem (Predictive Cognitive Memory), a self-evolving long-term memory framework for conversational LLM agents. PreCoMem operates in two active phases over a shared memory store. In memory leveraging, it retrieves confidence-weighted beliefs to condition response generation. In memory evolution, it compares new observations with recalled evidence and computes Effective Surprisal $S_{\mathrm{eff}}$ , a reliability-adjusted mismatch score. A two-threshold gate then routes each update to MAINTAIN, PROFILE, or CORRECT, corresponding to consistent, ambiguous, and reliably contradictory evidence. Figure 1 illustrates this loop on a coffee-to-tea preference shift, where a low-confidence hypothesis is gradually promoted to a fact while the contradicted old fact is softly decayed.

In summary, we (i) propose PreCoMem, a memory consolidation framework that casts long-term memory as a dynamic prediction of the user’s state; (ii) introduce a reliability-weighted surprisal signal that gates each update through MAINTAIN, PROFILE, or CORRECT; and (iii) evaluate on LoCoMo, LongMemEval-S, PersonaMem-v2, and DiMoBench/DiMoBench-XL, controlled write-path stress tests with gradual drift and decoy retrieval. PreCoMem outperforms the strongest contemporary baselines while keeping effective memory stable across 1050 turns.

## 2 PreCoMem

## 2.1 Framework overview

Figure 2: The PreCoMem framework. Two active phases operate over a shared memory store. Phase 1, Memory Leveraging: a confidence-modulated retrieval score combines semantic, lexical, and topic signals to select Top- $K$ beliefs $\mathcal{C}_{t}$ for response generation. Phase 2, Memory Evolution: the effective surprisal $S_{\mathrm{eff}}$ and a two-threshold gate route each turn to MAINTAIN, PROFILE, or CORRECT, illustrated by representative low/medium/high- $S_{\mathrm{eff}}$ turns. Memory Store: an editable Belief Store $\mathcal{B}$ of FACT/HYPO nodes with confidence weights, linked by provenance to an immutable Episodic Cache $\mathcal{E}$ under a shared topic index; belief items are updated independently, and the drawn links are provenance pointers and topic groupings (Appendix Section C.11).

As illustrated in Figure 2, PreCoMem operates as a closed loop of two active phases around a shared memory store. Memory Leveraging retrieves confidence-weighted beliefs and uses them to condition response generation. Memory Evolution then revises the memory state in light of the new interaction: it computes Effective Surprisal $S_{\mathrm{eff}}$ against recalled evidence, and routes the update to one of three deterministic operators—MAINTAIN, PROFILE, or CORRECT. This read–write loop differs from prior memory systems in two ways. First, every belief item carries a continuous confidence weight $w_{t}(m)\!\in\![0,1]$ that is reinforced or softly decayed by the operators, instead of relying on discrete commit decisions such as Add/Ignore/Update in O-Mem [40] or binary expiry intervals in EverMemOS [10]. Second, PROFILE buffers ambiguous observations as low-confidence hypotheses, letting weak evidence accumulate across turns before it is committed or discarded.

In implementation, each operator pairs a closed-form update rule with a fixed-prompt LLM sub-agent. The sub-agent only identifies which items are relevant and emits one bounded scalar, such as evidence_strength, severity, or initial_confidence. The deterministic layer then plugs these scalars into Equations 7, 8 and 10. Thus the LLM proposes local magnitudes, while the gate, confidence bounds, and closed-form $w$ updates control when and how memory changes accumulate. Algorithm 1 (Appendix Section B.4) gives the per-turn pipeline.

## 2.2 Memory primitives

Dialogue and memory state. At turn $t=1,2,\ldots$ , the user input is $u_{t}$ , the agent response is $y_{t}$ , and $Q_{t-1}$ is a rolling working-memory window. Long-term memory is $\mathcal{M}_{t}=(\mathcal{B}_{t},\mathcal{E}_{t},\mathcal{T}_{t})$ . The belief store $\mathcal{B}_{t}$ contains editable facts and hypotheses with confidence weights. The episodic cache $\mathcal{E}_{t}$ stores immutable raw dialogue traces with source pointers. The optional topic table $\mathcal{T}_{t}$ is only a retrieval prior. This keeps beliefs editable and evidence traceable.

Items, confidence, and hypothesis lifecycle. A memory item $m$ has content $c(m)$ , type $\tau(m)\in\{\texttt{FACT},\texttt{HYPOTHESIS}\}$ , and retrieval metadata such as embeddings, topic labels, entities, timestamps, and source pointers into $\mathcal{E}_{t}$ . For belief items, $w_{t}(m)\in[0,1]$ is an operational support score. Episodic traces are fixed at $w_{t}(e)\equiv 1$ and used only as provenance, not in confidence-weighted Top- $K$ ranking. A HYPOTHESIS is a provisional belief: it is reinforced under supporting evidence, decayed when evidence stays absent, and promoted to FACT when confidence crosses $\tau_{\mathrm{promote}}$ . Type transitions are one-way. Contradicted facts are softly decayed by CORRECT (Section 2.4) rather than demoted, yielding low-confidence “deprecated” facts that confidence-weighted retrieval naturally deprioritizes. Appendix Section C.7 confirms this retention is accuracy-neutral.

## 2.3 Memory leveraging: evidence recall and response generation

In Memory Leveraging, PreCoMem recalls a compact evidence set from long-term memory and leverages it to generate the current response.

Evidence recall. Given $u_{t}$ and short-term context $Q_{t-1}$ , PreCoMem ranks candidates in $\mathcal{B}_{t}$ with a confidence-modulated score. The score combines three retrieval signals: semantic similarity, lexical overlap (BM25), and topic relevance. Omitting $Q_{t-1}$ in the notation,

 $s(u_{t},m)=w_{t}(m)\sum_{j=1}^{3}\alpha_{j}s_{j}(u_{t},m),\quad m\in\mathcal{B}_{t},$ 

(1)

where $(s_{1},s_{2},s_{3})=(s_{\mathrm{sem}},s_{\mathrm{fact}},s_{\mathrm{topic}})$ and $\boldsymbol{\alpha}=(\alpha_{1},\alpha_{2},\alpha_{3})^{\top}$ is a convex weight vector. The multiplier $w_{t}(m)$ biases retrieval toward high-confidence items. The Top- $K$ belief items form $\mathcal{C}_{t}=\{m_{i}\}_{i=1}^{K}$ with retrieval scores $\mathbf{s}_{t}$ . Linked episodic traces from $\mathcal{E}_{t}$ are appended as provenance context, but they do not participate in Top- $K$ ranking. The same scores $\mathbf{s}_{t}$ are retained for the reliability estimate in Section 2.4.

Evidence-conditioned response. The recalled evidence texts $\{c(m)\mid m\in\mathcal{C}_{t}\}$ , together with $u_{t}$ and the short-term window $Q_{t-1}$ , condition the response model:

 $y_{t}=\texttt{Respond}(u_{t},Q_{t-1},\mathcal{C}_{t}).$ 

(2)

We reuse the same recall outputs $(\mathcal{C}_{t},\mathbf{s}_{t})$ to perform memory evolution in Section 2.4.

## 2.4 Memory evolution: regime-gated belief updating

Given the recall outputs $(\mathcal{C}_{t},\mathbf{s}_{t})$ and the new interaction $(u_{t},y_{t})$ ,
PreCoMem computes a prediction-error signal adjusted by retrieval reliability,
and applies a regime-gated update to the belief store.
It also writes the new turn back into the episodic cache for future provenance and recall.

Retrieval reliability. Surprisal computed against recalled evidence can be misleading when recall is uncertain, so we derive a reliability coefficient from the entropy of retrieval scores. Let $\mathbf{s}_{t}=\{s_{i}\}_{i=1}^{|\mathcal{C}_{t}|}$ denote the Top- $K$ retrieval scores returned with $\mathcal{C}_{t}$ , and let $\hat{s}_{i}=(s_{i}+\epsilon)/\sum_{j}(s_{j}+\epsilon)$ be the smoothed normalization. We define the normalized entropy $H_{t}$ and the reliability coefficient $\rho_{t}$ as

 $H_{t}=\frac{-\sum_{i}\hat{s}_{i}\log\hat{s}_{i}}{\log\max\{|\mathcal{C}_{t}|,2\}}\in[0,1],\qquad\rho_{t}=1-H_{t}.$ 

(3)

Because $H_{t}$ is minimized when one item dominates and maximized under near-uniform scores, $\rho_{t}$ measures score concentration as a proxy for evidence precision. Diffuse recall (small $\rho_{t}$ ) downweights deviation signals to avoid over-updating; concentrated recall (large $\rho_{t}$ ) preserves them for correction. Thus the gate becomes aggressive only when recall is concentrated and the raw contradiction/deviation signal is large. Since $\rho_{t}$ enters only multiplicatively, it can defer an update but never trigger one on its own; whether CORRECT fires still depends on the contradiction term below, and Appendix Section C.8 verifies empirically that $\rho_{t}$ tracks evidence precision. The constant $\epsilon>0$ ensures numerical stability.

Raw surprisal proxy. We define:

 $S_{\mathrm{raw}}(u_{t})=\lambda\,d_{\mathrm{sem}}(u_{t},\mathcal{C}_{t})+(1-\lambda)\,d_{\mathrm{conf}}(u_{t},\mathcal{C}_{t}),$ 

(4)

where $\lambda\in(0,1)$ , $d_{\mathrm{sem}}$ is the normalized semantic deviation between $u_{t}$ and score-weighted recalled evidence, and $d_{\mathrm{conf}}$ is a verifier-based contradiction score quantifying how strongly $u_{t}$ conflicts with recalled beliefs (see Appendix Section B.2).

Effective surprisal. We define:

 $S_{\mathrm{eff}}(u_{t})=\rho_{t}\,S_{\mathrm{raw}}(u_{t}),$ 

(5)

which corresponds to a precision-weighted prediction error that becomes conservative when recall is unreliable.
We use $x_{t}:=S_{\mathrm{eff}}(u_{t})$ as the scalar gate score below. Appendix Section B.1 gives an optimization view that interprets $x_{t}$ as a Monte Carlo surrogate of a long-horizon predictive objective.

Regime-gated evolution. Given two ordered thresholds $\theta_{\mathrm{low}}<\theta_{\mathrm{high}}$ , PreCoMem maps the gate score $x_{t}$ into three regimes:

 $a_{t}=\begin{cases}\texttt{MAINTAIN},&x_{t}\leq\theta_{\mathrm{low}}\\
\texttt{PROFILE},&\theta_{\mathrm{low}}<x_{t}\leq\theta_{\mathrm{high}}\\
\texttt{CORRECT},&x_{t}>\theta_{\mathrm{high}}.\end{cases}$ 

(6)

Two-threshold gate. Low, medium, and high $x_{t}$ correspond to consistent, ambiguous, and reliably contradictory evidence. PROFILE handles the middle regime that a binary maintain/correct rule must either ignore or overwrite. We fix $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})=(0.2,0.6)$ throughout the main experiments to keep behavior controllable and the comparison reproducible across benchmarks; the cost-sensitive break-even derivation, operator ablations, threshold sensitivity, and dynamic-threshold variant are in Appendix Sections B.3, C.4, C.5 and C.5.

## MAINTAIN (reinforcement).

When surprisal is low, PreCoMem strengthens supported beliefs in $\mathcal{C}_{t}$ via:

 $w_{t+1}(m)=w_{t}(m)+\eta_{t}(m)\,(1-w_{t}(m)),\quad m\in\mathcal{C}_{t}\cap\mathcal{B}_{t},$ 

(7)

where $\eta_{t}(m)\in(0,1]$ is the per-item evidence_strength returned by the Maintain-Agent; weakly supported items barely move, while strongly supported ones are pulled toward $1$ . The optimization view in Appendix Section B.3 treats $\eta_{t}(m)$ as a scalar step size.

## PROFILE (hypothesis writing).

When surprisal is medium, the observation is novel but not decisively contradictory. PreCoMem generates a low-confidence hypothesis $h$ and writes it as a HYPOTHESIS belief:

 $\displaystyle h$ 
 $\displaystyle=\texttt{GenerateHypothesis}(u_{t},\mathcal{C}_{t}),\qquad\tau(h)=\texttt{HYPOTHESIS},$ 

(8)

 $\displaystyle b_{t}^{(c)}$ 
 $\displaystyle=w_{\min}^{(c)}+\sigma(x_{t})\bigl(w_{\max}^{(c)}-w_{\min}^{(c)}\bigr),\qquad w_{0}(h)=\tfrac{1}{2}\,b_{t}^{(c)}+\tfrac{1}{2}\,\mathrm{clip}\bigl(q_{t},[w_{\min}^{(c)},w_{\max}^{(c)}]\bigr),$ 

where GenerateHypothesis is the Profile-Agent under a fixed prompt, $\sigma(x)=1/(1+e^{-x})$ , $c\!\in\!\{\textsc{explicit},\textsc{latent}\}$ is the class label assigned by the agent, and $q_{t}$ is the agent’s initial_confidence, clipped to the class band $[w_{\min}^{(c)},w_{\max}^{(c)}]$ . The gate score thus supplies a reproducible prior $b_{t}^{(c)}$ inside the band, and the agent scalar can shift $w_{0}$ by at most half the band width. Explicit-event hypotheses paraphrase stated facts or actions and use the band $[0.60,0.70]$ . Latent-inference hypotheses capture deduced traits, moods, or hidden goals and use $[0.50,0.59]$ . These initial values are low relative to stable FACTs, which sit at $w\!\geq\!0.80$ and meet the promotion threshold $\tau_{\mathrm{promote}}\!=\!0.80$ . A fresh hypothesis therefore ranks below committed facts in confidence-weighted retrieval (Equation 1) and still needs repeated support to graduate. In later turns, hypotheses are reinforced under MAINTAIN when supported and decayed when evidence remains absent:

 $w_{t}(h)\leftarrow w_{t}(h)\exp\bigl(-\gamma\,a_{t}(h)\bigr),\qquad a_{t}(h)=t-\ell(h),$ 

(9)

where $\ell(h)$ is the turn at which $h$ was created or last received supporting evidence and $\gamma>0$ is a decay rate. The rule is applied once per turn to unsupported hypotheses: any supporting update resets $\ell(h)$ and skips the decay in that turn, and hypotheses flagged as decay_protection by the agent (explicit events) are exempt, so the compounding decay over consecutive unsupported turns (cumulative factor $\exp(-\gamma\,n(n+1)/2)$ after $n$ turns; Appendix Section B.3) prunes only guesses that are never revalidated. Hypotheses are promoted to facts once confidence crosses $\tau_{\mathrm{promote}}$ , with $0\!\leq\!w_{\min}^{(c)}\!<\!w_{\max}^{(c)}\!<\!\tau_{\mathrm{promote}}\!\leq\!1$ enforced for every class so that promotion always requires repeated support.

## CORRECT (soft correction).

When surprisal is high and recall is reliable, the new observation likely contradicts existing high-confidence beliefs. PreCoMem records the new observation as a fresh belief node (a FACT with initial weight $0.85$ ) and separately decays the retrieved beliefs it contradicts. The decay side is:

 $w_{t+1}(m)=w_{t}(m)\exp\!\bigl(-\beta\,x_{t}\,\zeta_{t}(m)\bigr),\quad m\in\mathcal{C}_{t}\cap\mathcal{B}_{t},$ 

(10)

where $\beta>0$ controls the correction strength and $\zeta_{t}(m)\!\in\![0,1]$ is the per-item contradiction severity returned by the Correct-Agent; non-contradictory items receive $\zeta_{t}(m)\!\approx\!0$ and are essentially unchanged, enabling selective correction without extra thresholds. We deliberately separate this context-aware decay magnitude from the fixed NLI contradiction score that feeds $d_{\mathrm{conf}}$ (Equation 22 in Appendix Section B.2): the NLI score drives the gate via $S_{\mathrm{raw}}$ , whereas $\zeta_{t}$ localizes how strongly each retrieved belief should decay. A derivation is provided in Appendix Section B.3.

## Trace and topic write-back.

After generating $y_{t}$ , PreCoMem appends the turn trace $(u_{t},y_{t})$ to the episodic cache $\mathcal{E}_{t+1}$ with a fixed-capacity eviction policy; optionally, new topics are added to $\mathcal{T}_{t+1}$ when detected, yielding $\mathcal{M}_{t+1}=(\mathcal{B}_{t+1},\mathcal{E}_{t+1},\mathcal{T}_{t+1})$ .
When PROFILE/MAINTAIN/CORRECT creates or updates belief items, we record source pointers to supporting traces so beliefs remain editable while evidence remains traceable.

## 3 Experiments

## 3.1 Experimental setup

Benchmarks. We evaluate on LoCoMo [28] (1,500+ questions in long contexts), LongMemEval-S [43] (500 questions covering six question types over five long-term memory abilities), and PersonaMem-v2 [16] ( $1{,}000$ personas and $20{,}000+$ implicit preferences, evaluated under both 32k and 128k contexts; Figure 3(c)–(f)). To stress-test belief drift under sparse signals we additionally introduce DiMoBench, which adds controlled non-stationarity and decoy retrieval (Section 3.3). Two third-party benchmarks, AMemGym [1] and LoCoMo-Plus [22], are evaluated under their official protocols in Appendix Section C.1.

Baselines. We compare PreCoMem against O-Mem [40], MemoryOS [17], MemOS [23], Mem0 [2], A-Mem [45], GAM [46], MemBox [38], TiMem [21], and EverMemOS [10], each under its officially recommended configuration; we standardize the backbone LLM and embedding model across methods whenever applicable.

Evaluation protocol. We adopt the LLM-as-a-judge protocol from MemOS [23]: each answer is scored by a primary judge (gpt-4.1-mini) and two auxiliary gemini-2.5-flash judges (run with distinct system prompts to reduce judge-correlation) in a blinded setup, with accuracy reported as the average of the three binary judgments [20, 9, 12, 35, 47]. Appendix Section C.3 reports human–LLM agreement on LoCoMo, LongMemEval-S, and DiMoBench plus a cross-method spot-check on baseline outputs.

Implementation details. PreCoMem uses gpt-4.1 (or gpt-4o-mini) for all LLM-based reasoning and memory operations and Qwen3-Embedding-0.6B for dense embeddings across methods. Unless otherwise specified, $k{=}10$ , $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})=(0.2,0.6)$ , $\lambda{=}0.5$ , $\beta{=}1.0$ , $\boldsymbol{\alpha}{=}(0.4,0.4,0.2)$ , and $\gamma{=}0.05$ ; sensitivity studies and the adaptive variant are in Appendix Sections C.5, C.5 and C.5.

## 3.2 Main results

Main results are reported in Table 1: the upper block on LoCoMo and the lower block on LongMemEval-S. We make three observations.

(1) Overall performance. PreCoMem achieves the best overall accuracy on both tabulated benchmarks. On LoCoMo it leads the strongest baseline (TiMem) by $+1.69$ with gpt-4o-mini ( $73.57$ vs. $71.88$ ) and $+1.02$ with gpt-4.1 ( $85.06$ vs. $84.04$ ); both gaps exceed the cross-seed standard deviation of either system reported in Table 1. On LongMemEval-S it reaches $89.39$ under gpt-4.1 ( $+3.23$ over EverMemOS), and the gpt-4o-mini appendix block follows the same pattern ( $84.28$ , $+1.96$ ; Appendix Section C.3). On PersonaMem-v2 (Figure 3(e)–(f)) under gpt-4.1, PreCoMem reaches $72.31$ Open-Ended at 32k and $67.84$ at 128k, $+3.37$ and $+2.89$ over EverMemOS. The advantage also holds on two third-party benchmarks we did not design: $0.458$ Overall / $0.329$ normalized Memory on AMemGym against $0.430$ / $0.296$ for the strongest system reported there, and $22.4$ on LoCoMo-Plus against $21.05$ for full-context GPT-4o (Appendix Section C.1). Figure 3(a)–(d) further shows that, with the answer model held fixed, delegating memory construction to PreCoMem on a one-tier-smaller backbone still beats the larger backbone’s native memory in all twelve comparisons.

(2) Where gains come from.
On LoCoMo, the gain concentrates on the Open-Domain split (PreCoMem $48.23$ under gpt-4.1, $+1.30$ over MemOS; consistently best under gpt-4o-mini), whose questions typically ask for a latent state that is not stated in a single turn and must be inferred from cues spread across sessions (Appendix Section C.3), while EverMemOS, O-Mem, and TiMem retain narrow leads on Single-Hop / Multi-Hop / Temporal under gpt-4.1 from their dedicated read-path designs.
On LongMemEval-S (gpt-4.1), the largest gains occur on the question types whose answers depend on updating or aggregating user-specific memory: SSP (single-session preference, $+9.24$ over O-Mem), KU (knowledge update, $+4.75$ over O-Mem; every KU question carries an old value superseded by a newer one), and MS (multi-session aggregation, $+3.55$ ). The SSA gain (assistant-side single-session information, $+3.96$ ) reflects selective memory use: the single target session lies among $48.9$ sessions on average, and confidence-weighted retrieval acts as an implicit reranker. PersonaMem-v2 reproduces this pattern: PreCoMem’s lead is largest on anti-stereotypical, dynamic, and ownership-disambiguation categories that most stress write-path quality, and shrinks to under two points on stereotypical or static cues where population priors suffice. PreCoMem’s advantage is therefore strongest when answers require selective memory use, belief updating, or cross-session aggregation; a structural analysis attributes the gains to two design properties absent from contemporary baselines—continuous per-belief confidence that buffers ambiguous cues, and a confidence-weighted retrieval score that acts as an implicit reranker (Appendix Section C.10).

(3) Accuracy–efficiency trade-off. Figure 5(a) shows the LoCoMo performance–cost frontier as we vary $k$ : PreCoMem peaks at $k\!=\!10$ with moderate token usage, while larger $k$ yields diminishing returns. Supporting diagnostics on hypothesis lifecycle, Top- $k$ sensitivity, and memory footprint are reported in Appendix Sections C.3, C.5 and C.7.

## 3.3 Ablation studies and belief-drift adaptation

Figure 4: Component ablation and DiMoBench dynamics.
(a) Component ablation on LoCoMo and LongMemEval-S.
(b) Moving-average accuracy under implicit drift on DiMoBench.
(c) Operator-level ablation on DiMoBench.

Component ablation. We ablate three core components while keeping the backbone, prompts, and hyperparameters fixed. ES removes the effective-surprisal gate by setting the gate score to $0$ ; RR removes retrieval-reliability adjustment via $\rho_{t}\!\equiv\!1$ ; CW removes confidence weighting globally, in retrieval and in every lifecycle test, by setting all belief weights to $1$ . Figure 4(a) reports LLM-judge accuracy on LoCoMo and LongMemEval-S. Removing ES causes the largest drop on LoCoMo ( $73.57\!\to\!31.46$ ; similar on LongMemEval-S): with the gate score zeroed every turn is routed to MAINTAIN, so this reinforce-only variant marks the lower bound of surprisal-gated evolution, the primary mechanism under non-stationarity, while route-matched controls that isolate the gate’s marginal value are reported in Appendix Section C.4. Removing CW ( $\!\to\!43.42$ ) and RR ( $\!\to\!56.81$ ) also substantially reduces accuracy, with the same trend on LongMemEval-S. Letting the same LLM emit the entire write decision end-to-end instead of bounded scalars lowers accuracy by $2.75$ / $3.15$ points on LoCoMo / LongMemEval-S and raises the cross-seed standard deviation $20\times$ on LoCoMo (under gpt-4.1; Appendix Section C.4). Appendix Section C.4 shows the NLI contradiction term drives most gains.

DiMoBench setup. DiMoBench (Dialogue Implicit Memory Drift Benchmark) is a controlled diagnostic setting for gradual attitude and preference drift. A user’s latent stance reverses around a change point, while keyword-matched chatter and entity confounders pollute the stream so naive retrieval and overwrite-style updates become brittle. The released suite has five independent $350$ -turn dialogues, each driven by a distinct persona, with $200$ QA pairs per dialogue ( $1{,}000$ total; results averaged across personas); DiMoBench-XL extends this to $1050$ turns and three sequential drifts, with 420 QA pairs each, 2,100 in total (Appendix Sections C.6 and C.6).

Update dynamics. Figure 4(b) plots LLM-judge accuracy across dialogue turns. Before the change point all methods are stable; afterwards PreCoMem experiences a transient drop but recovers fastest and stabilizes at $84\%$ , while EverMemOS, TiMem, and O-Mem plateau at 78–80% and Mem0 fails to recover ( $54\%$ ). End-to-end traces are provided in Appendix Section C.11.

Operator ablation on DiMoBench. Ablating each operator individually (Figure 4(c)) yields qualitatively distinct failure modes: removing PROFILE caps the asymptote at $72\%$ (vs. $84\%$ ); removing CORRECT delays recovery (turn $320$ vs. $250$ ) and lowers the plateau to $77\%$ ; removing MAINTAIN fails to stabilize within the horizon ( $54\%$ at the end), confirming that the three operators play distinct stabilizing roles. Appendix Section C.4 provides the full analysis, and the same three qualitative signatures reproduce on the third-party AMemGym benchmark (Appendix Section C.1).

## 3.4 Hyperparameter analysis

We sweep the retrieval budget $k\!\in\!\{1,\ldots,20\}$ on LoCoMo (gpt-4.1). Accuracy rises sharply through $k\!\approx\!6$ , peaks at $k\!=\!10$ (Overall $85.06\%$ ), then drops mildly. Larger $k$ flattens the Top- $k$ score distribution, lowering $\rho_{t}$ and dampening the effective surprisal $x_{t}$ that drives CORRECT. It also increases the chance that one retrieved item spuriously appears contradictory under the max-based contradiction component $d_{\mathrm{conf}}$ . We therefore fix $k\!=\!10$ ; the full sweep and retrieval-latency profile are reported in Appendix Sections C.5 and C.9. Because the write path acts only on retrieved beliefs, Appendix Section C.8 further measures how often the belief due for an update actually enters the Top- $k$ and what a miss costs.

## 3.5 Memory scalability

Figure 5: Hyperparameter and memory-scalability analysis.
(a) LoCoMo accuracy–efficiency frontier as the retrieval budget $k$ varies; overall accuracy peaks at $k\!=\!10$ , beyond which additional context yields diminishing returns and dilutes retrieval reliability $\rho_{t}$ .
(b, c) Memory scalability under long-horizon belief drift: raw memory grows linearly, while effective memory quickly plateaus on both DiMoBench and DiMoBench-XL (panel (c) shows one representative persona).

A natural concern for any long-term memory system is whether storage and retrieval cost scale gracefully with the conversation length. We examine this on three settings spanning natural and stress-test horizons: the LoCoMo benchmark (ten multi-session dialogues, mean $\bar{N}\!=\!588$ turns), DiMoBench (350 turns, 1 drift), and DiMoBench-XL (1050 turns, 3 drifts; five personas, of which a representative one is plotted, the others staying within $\pm 1.4$ of it; Appendix Section C.6). Two quantities are tracked every 10 turns on DiMoBench and every 50 turns on DiMoBench-XL:

• 

Raw count $N_{\mathrm{raw}}(t)=|\mathcal{B}_{t}|$ : the number of belief items physically stored, including deprecated facts. Deprecated facts are previously committed FACTs whose confidence has been softly decayed below $0.1$ by repeated CORRECT updates (Equation 10); we keep them in $\mathcal{B}_{t}$ as provenance hooks rather than deleting them.

• 

Effective count $N_{\mathrm{eff}}(t)=\sum_{m\in\mathcal{B}_{t}}w_{t}(m)$ : the confidence-weighted total mass. Intuitively, this is the equivalent number of fully-supported items the agent “acts on” through the confidence-weighted retrieval score in Equation 1. A deprecated fact at $w\!=\!0.05$ contributes only $0.05$ to $N_{\mathrm{eff}}$ , which matches its negligible influence on Top- $K$ ranking.

Figure 5(b, c) shows $N_{\mathrm{raw}}$ grows roughly linearly with the dialogue, but $N_{\mathrm{eff}}$ saturates by turn 200 (at $25.8$ – $28.5$ on the representative persona, with the other personas within $\pm 1.4$ of it) and, apart from a transient dip at each drift, stays in that band. Moreover, deprecated facts occupy only $1.0\%$ of Top-10 slots on average even after 1050 turns and three drifts (Appendix Table 19). Confidence weighting therefore turns linearly growing storage into a roughly constant retrieval surface.

Table 2 extends this picture to physical storage on LoCoMo, where we measure the final $\mathcal{B}_{t}$ size of each system under matched backbone and embedding protocols. By default (A0) PreCoMem keeps deprecated facts as provenance hooks for traits that may resurface later, since confidence-weighted retrieval already filters them out of the Top- $K$ ; the optional A1 configuration ( $w\!<\!0.05$ prune) trades this provenance for tighter storage and matches A0 within seed variance (Appendix Section C.7). Both O-Mem and EverMemOS commit each interaction through a discrete decision (Add/Ignore/Update in O-Mem; episodic-trace formation with a binary $[t_{\mathrm{start}},t_{\mathrm{end}}]$ validity in EverMemOS), so neither maintains a continuous per-item confidence and $N_{\mathrm{eff}}$ is undefined. Even on raw count alone, A1 stores fewer items than both baselines while still leading on accuracy by $+2.6$ and $+3.4$ overall points, so storage remains bounded in both the soft sense ( $N_{\mathrm{eff}}$ plateau) and the hard sense. This suggests the memory gain is not purchased by unchecked accumulation.

## 4 Conclusion

PreCoMem treats long-horizon conversational memory not as a transcript to be stored, but as confidence-weighted beliefs about the user’s state that must be continually checked. A reliability-adjusted surprisal signal routes each turn into MAINTAIN (reinforce supported beliefs), PROFILE (buffer ambiguous cues as low-confidence hypotheses), or CORRECT (softly decay contradicted facts). The PROFILE waiting room is the central design choice: it lets evidence accumulate before commitment, so the agent stays consistent under noise without freezing under genuine drift. Across LoCoMo, LongMemEval-S, PersonaMem-v2, and DiMoBench, this discipline yields the best overall accuracy while keeping memory bounded over a thousand turns; qualitative case studies (Appendix Section C.11) show calibrated recommendations beyond retrieval-only baselines. We see continuous confidence and explicit hypothesis lifecycles as a useful baseline for long-term memory systems, where what to commit matters as much as what to recall. Our evaluation covers English dialogue benchmarks; other languages and modalities are left for future work.

## Appendix A Related work

## Long-term memory for conversational LLMs.

Early work attacks the fixed context window with externalized hierarchical or virtual memory [51, 30]. More recent systems either organize the store more aggressively or learn richer write rules. Structured organizations include interlinked note stores with associative links [45], time-aware knowledge graphs [34], OS-style hierarchical scheduling [23, 10], and dedicated memory-box layouts that segment a user’s history into typed shards [38]. Learning-based update rules optimize memory operations against downstream rewards [42, 50, 46], while interpretable triggers target a single failure mode such as preference change [37], redundancy [24, 21], controllable reliance [13], or affective state [27]. A systematic gap shared by these systems is the stability–plasticity regime: append-only memories [45] treat every observation as equally valid and dilute retrieval; overwrite memories compress aggressively but lose information that later turns out to be relevant [2]; OS-style memories [23, 10] schedule access well but still fall back on importance heuristics for writes; and reinforcement-trained memories [42, 50, 46] face sparse credit assignment, since most reward signal is several turns downstream of the responsible read/write decision. PreCoMem is complementary to all of these: it treats the write path as a single regime-gated decision driven by a calibrated prediction-error signal, instead of relying on recency heuristics or task-specific reward shaping.

## Predictive coding and surprisal as write signals.

Predictive coding theory holds that perceptual systems update internal models when observations deviate from prediction [8, 3], and information theory gives this deviation a precise scalar form: surprisal [19, 29]. The same logic has long shaped accounts of episodic memory: novel events are encoded preferentially, and reactivation drives reconsolidation of related traces [33, 36]. Translating this into long-term conversational memory requires two extra ingredients absent from prior memory systems. First, surprisal must be calibrated against retrieval reliability, otherwise diffuse recall produces noisy update signals [18, 48]. Second, surprisal must be regime-gated, since consistent, ambiguous, and reliably contradictory evidence call for qualitatively different memory edits. PreCoMem operationalizes both ingredients: $S_{\mathrm{eff}}$ multiplies raw surprisal by an entropy-based reliability coefficient, and a two-threshold gate maps the result to MAINTAIN/PROFILE/CORRECT.

## Benchmarking long-term memory.

LoCoMo [28] provides 1,500 $+$ questions over multi-session dialogues with explicit single-hop, multi-hop, temporal, and open-domain splits. LongMemEval-S [43] tests five core abilities (information extraction, multi-session reasoning, knowledge updates, temporal reasoning, abstention) with 500 questions over chat histories of roughly $115$ k tokens each. PersonaMem-v2 [16] stresses implicit personalization across $1{,}000$ personas and $20{,}000+$ preferences, where most signal is buried in everyday task-oriented turns. Two more recent benchmarks move closer to the write path: AMemGym [1] evaluates memory on-policy against a simulated user whose latent task state changes across periods, and LoCoMo-Plus [22] probes implicit cognitive constraints (causal, state, goal, and value) over long dialogues; we report both in Section C.1. EvalMem [26] complements these end-task benchmarks with an operation-level diagnostic framework that scores individual memory operations such as adding, updating, and deleting items. These benchmarks probe the read path or the end result of memory updates; none of them, however, isolates the write-path decision under continuous, gradual drift with adversarial retrieval interference. Our companion benchmark DiMoBench fills this gap with five independent $350$ -turn dialogues, one per persona, whose latent attitudes reverse gradually across change points; an extended variant, DiMoBench-XL, contains five independent $1050$ -turn dialogues, each with three sequential drifts.

## Appendix B Additional method details

## B.1 From expected predictive loss to a per-turn on-policy loss

## Conceptual predictive loss.

Let $h_{t}=(u_{\leq t},y_{<t})$ denote the dialogue history up to turn $t$ . The conceptual predictive loss

 $\mathcal{L}_{\mathrm{pred}}(t)=\mathbb{E}_{u\sim p(u\mid h_{t})}\!\left[S_{\mathrm{eff}}(u)\right]$ 

(11)

captures the expected effective surprisal under the (unknown) interaction distribution $p(u\mid h_{t})$ , and the long-horizon goal is to update the memory state to reduce future expected losses,

 $\min_{\mathcal{M}_{t+1}}\;\mathbb{E}\!\left[\mathcal{L}_{\mathrm{pred}}(t+k)\mid\mathcal{M}_{t+1}\right],\qquad k\geq 1.$ 

(12)

## Monte Carlo surrogate.

Because $p(u\mid h_{t})$ is generally unknown, under a fixed response policy we treat the observed turn $u_{t}$ as a Monte Carlo sample and use the estimator

 $\widehat{\mathcal{L}}_{\mathrm{pred}}(t):=S_{\mathrm{eff}}(u_{t}).$ 

(13)

Defining the per-turn on-policy loss $x_{t}:=\widehat{\mathcal{L}}_{\mathrm{pred}}(t)$ yields an unbiased estimate

 $\mathbb{E}\!\left[x_{t}\mid h_{t}\right]=\mathcal{L}_{\mathrm{pred}}(t).$ 

(14)

In the main text we write $S_{\mathrm{eff}}(u_{t})$ without explicitly conditioning on the memory state; implicitly, $S_{\mathrm{eff}}$ depends on the retrieved evidence produced by $\texttt{Retrieve}(\mathcal{M}_{t},u_{t})$ .

## Greedy regularized surrogate for memory updates.

The long-horizon objective in Equation 12 can be approximated on-policy by folding “future benefit” into a myopic, regularized surrogate:

 $\mathcal{M}_{t+1}\approx\arg\min_{\mathcal{M}}\;x_{t}(\mathcal{M})+D(\mathcal{M},\mathcal{M}_{t})+\Omega(\mathcal{M}),$ 

(15)

where $x_{t}(\mathcal{M})$ denotes the effective-surprisal loss one would obtain if evaluated with memory state $\mathcal{M}$ , $D$ is an edit/stability cost (e.g., penalizing large changes or changes to high-confidence beliefs), and $\Omega$ is a capacity/complexity penalty that discourages unbounded growth of provisional beliefs.
Concretely, we instantiate $\Omega$ with a lightweight pruning rule for the hypothesis pool: belief items with $\tau(m)=\texttt{HYPOTHESIS}$ are removed once their confidence falls below a small threshold (we use $w_{t}(m)<0.1$ ), which controls memory size while retaining only actively supported hypotheses.
In contrast, belief items with $\tau(m)=\texttt{FACT}$ are not directly deleted; due to the one-way promotion scheme in Section 2.2, outdated facts are instead handled by soft-decay correction that reduces their confidence and thus deprioritizes them under confidence-weighted retrieval.
The Memory Evolution phase instantiates a discrete, interpretable approximation of Equation 15: action selection corresponds to cost-sensitive choice (Section B.3), while operator updates admit simple optimization views (Sections B.3 and B.3).

## Why low-confidence facts are retained rather than pruned.

We deliberately apply the $w_{t}(m)<0.1$ pruning rule only to hypotheses, not to facts. Two design considerations motivate this asymmetry. First, because retrieval is confidence-weighted, an outdated fact with $w\!\approx\!0.02$ contributes roughly 50 $\times$ less to the retrieval score than a currently supported fact with $w\!\approx\!1$ ; such items are naturally pushed out of the Top- $K$ evidence set by currently supported beliefs and become functionally inactive under confidence-weighted retrieval even though they remain in storage. Second, long-horizon dialogue often revisits past user traits after long gaps (e.g., a user stops drinking coffee for months and then mentions it again); retaining the deprecated fact at low confidence preserves the reasoning chain and episodic-cache links needed to recover such context, whereas hard deletion would force the system to rebuild that trait from scratch. The resulting effective memory, i.e., the subset of items that can still influence Top- $K$ retrieval, therefore remains controlled even if raw storage accumulates history. Under truly extreme horizons, raw storage can be further bounded by a timestamped time-to-live on long-deprecated facts without modifying the core operators; we leave this as an engineering safeguard rather than a core mechanism.

## B.2 Retrieval scoring and surprisal component definitions

## Retrieval scoring.

Let $\mathbf{e}(\cdot)$ be a text embedding function and let $\mathcal{P}_{t}$ be the merged candidate pool recalled from $\mathcal{B}_{t}$ and $\mathcal{E}_{t}$ . We use three reproducible relevance signals:

 $\displaystyle s_{\mathrm{sem}}(u_{t},m)$ 
 $\displaystyle=\tfrac{1}{2}\left(1+\cos(\mathbf{e}(u_{t}),\mathbf{e}(c(m)))\right)\in[0,1],$ 

(16)

 $\displaystyle s_{\mathrm{fact}}(u_{t},m)$ 
 $\displaystyle=\frac{\mathrm{BM25}(u_{t},c(m))}{\max_{m^{\prime}\in\mathcal{P}_{t}}\mathrm{BM25}(u_{t},c(m^{\prime}))+\epsilon}\in[0,1],$ 

(17)

where $\epsilon>0$ is a stability constant. For topical relevance, we maintain topic prototypes $\{\mathbf{t}_{z}\}_{z=1}^{Z_{t}}$ (e.g., $\mathbf{t}_{z}=\mathbf{e}(\ell_{z})$ for topic description $\ell_{z}$ ) and define

 $\displaystyle s_{\mathrm{topic}}(u_{t},m)$ 
 $\displaystyle=p(z(m)\mid u_{t}),$ 

(18)

 $\displaystyle p(z\mid x)$ 
 $\displaystyle=\operatorname{softmax}_{z}\!\left(\cos(\mathbf{e}(x),\mathbf{t}_{z})\right).$ 

We assign each item a topic label at write time as $z(m)=\arg\max_{z}p(z\mid c(m))$ , and $Z_{t}$ denotes the number of topics at turn $t$ .

## Surprisal components.

Let $\hat{s}_{i}$ be the normalized retrieval weights from Equation 3. We compute a score-weighted evidence embedding

 $\mathbf{e}(\mathcal{C}_{t})=\sum_{i=1}^{K}\hat{s}_{i}\,\mathbf{e}(c(m_{i})),$ 

(19)

and define semantic deviation as a cosine distance:

 $d_{\mathrm{sem}}(u_{t},\mathcal{C}_{t})=\tfrac{1}{2}\left(1-\cos(\mathbf{e}(u_{t}),\mathbf{e}(\mathcal{C}_{t}))\right)\in[0,1].$ 

(20)

For contradiction, let

 $\pi_{t}(m):=\mathrm{Verif}_{\mathrm{conf}}(u_{t},c(m))\in[0,1]$ 

(21)

be the calibrated contradiction probability predicted by a fixed NLI verifier.
In all experiments, $\mathrm{Verif}_{\mathrm{conf}}$ is instantiated as the cross-encoder/nli-deberta-v3-base cross-encoder:
given the premise–hypothesis pair $(c(m),u_{t})$ , let $\mathbf{z}(u_{t},c(m))\in\mathbb{R}^{3}$ denote its logits over $\{\text{entail},\text{neutral},\text{contr}\}$ .
We fit a scalar temperature $T>0$ on the MultiNLI (MNLI) matched development split and define
 $\pi_{t}(m)=\operatorname{softmax}(\mathbf{z}(u_{t},c(m))/T)_{\text{contr}}$ , and set

 $d_{\mathrm{conf}}(u_{t},\mathcal{C}_{t})=\max_{m_{i}\in\mathcal{C}_{t}}\pi_{t}(m_{i})\in[0,1].$ 

(22)

## Memory item fields.

A memory item $m$ is a typed belief node (FACT or HYPOTHESIS) with content $c(m)$ , confidence weight $w_{t}(m)\in[0,1]$ , and the retrieval metadata listed in Section 2.2; the three metadata fields are constructed as follows. Entities and keywords are proposed by the write-path sub-agent at write time (the Profile-Agent’s evidence_keywords); no separate entity-recognition model is involved, and they are stored as a structured field that is used only by the lexical term $s_{\mathrm{fact}}$ of Equation 1. Topic labels are assigned at write time as $z(m)=\arg\max_{z}p(z\mid c(m))$ with the prototypes of Equation 18; the topic table $\mathcal{T}_{t}$ keeps one running-mean centroid per topic and acts only as the topic prior $s_{\mathrm{topic}}$ . Dense embeddings are computed solely from the belief text, $\mathbf{e}(c(m))$ with Qwen3-Embedding-0.6B (normalized); entity and topic information never enter the embedding and contribute only through their own terms. Episodic traces are embedded from their own dialogue text and serve as provenance only. Section C.11 shows a serialized snapshot.

## Cold start.

When the belief store is still empty, retrieval returns no evidence and the surprisal terms above are undefined. By convention the first observations of a user are then handled by PROFILE: they enter the store as provisional hypotheses that later turns can reinforce, correct, or let decay, exactly as for a populated store. Section C.8 reports how reliably first mentions are written under this convention.

## B.3 Operator and gate derivations

## MAINTAIN update.

The MAINTAIN update in Equation 7 is a single gradient-descent step on the convex consolidation loss
 $\ell^{+}(w)=\tfrac{1}{2}(1-w)^{2}$ . For a scalar weight $w$ ,

 $w_{t+1}=w_{t}-\eta\nabla\ell^{+}(w_{t})=w_{t}+\eta(1-w_{t}),$ 

which matches Equation 7. If $w_{t}\in[0,1]$ and $\eta\in(0,1]$ , then $w_{t+1}\in[0,1]$ and the residual shrinks as $1-w_{t+1}=(1-\eta)(1-w_{t})$ .

## CORRECT update.

For a retrieved belief item $m$ , let $x_{t}=S_{\mathrm{eff}}(u_{t})$ denote the on-policy loss and let $\zeta_{t}(m)\in[0,1]$ be the per-item severity returned by the Correct-Agent (Appendix D); operationally $\zeta_{t}(m)$ plays the role of a context-aware contradiction weight, and reduces to a calibrated NLI score $\pi_{t}(m)$ when the agent is replaced by the fixed verifier in Equation 21. Consider the KL-proximal mirror-descent update:

 $w_{t+1}=\arg\min_{w\geq 0}\;x_{t}\,\zeta_{t}(m)\,w+\tfrac{1}{\beta}\mathrm{KL}(w\|w_{t}),$ 

(23)

where for scalar weights,

 $\mathrm{KL}(w\|w_{t})=w\log\frac{w}{w_{t}}-w+w_{t}.$ 

(24)

Taking the first-order optimality condition of Equation 23 gives
 $x_{t}\,\zeta_{t}(m)+\tfrac{1}{\beta}\log\frac{w_{t+1}}{w_{t}}=0$ , hence

 $w_{t+1}=w_{t}\exp\!\left(-\beta x_{t}\,\zeta_{t}(m)\right),$ 

(25)

which matches Equation 10.

## Two-threshold gate.

We interpret the gate in Equation 6 as selecting an action that minimizes an on-policy risk plus an action cost:

 $a_{t}=\arg\min_{a\in\{\mathrm{M,P,C}\}}\widehat{J}_{t}(a),\qquad\widehat{J}_{t}(a)=\widehat{L}_{t}(a)+c(a).$ 

(26)

Using the proxy $\widehat{L}_{t}(a)=x_{t}-\Delta_{a}(x_{t})$ with a linear improvement model $\Delta_{a}(x)\approx g_{a}x$ yields

 $\widehat{J}_{t}(a)\approx(1-g_{a})x_{t}+c(a).$ 

The action boundaries are given by pairwise equality of these lines: $\widehat{J}_{t}(\mathrm{P})=\widehat{J}_{t}(\mathrm{M})$ gives

 $x_{t}=\frac{c(\mathrm{P})-c(\mathrm{M})}{g_{\mathrm{P}}-g_{\mathrm{M}}}=:\theta_{\mathrm{low}},$ 

and $\widehat{J}_{t}(\mathrm{C})=\widehat{J}_{t}(\mathrm{P})$ gives

 $x_{t}=\frac{c(\mathrm{C})-c(\mathrm{P})}{g_{\mathrm{C}}-g_{\mathrm{P}}}=:\theta_{\mathrm{high}},$ 

which gives the two thresholds:

 $\theta_{\mathrm{low}}=\frac{c(\mathrm{P})-c(\mathrm{M})}{g_{\mathrm{P}}-g_{\mathrm{M}}},\qquad\theta_{\mathrm{high}}=\frac{c(\mathrm{C})-c(\mathrm{P})}{g_{\mathrm{C}}-g_{\mathrm{P}}}.$ 

(27)

We treat $(c(a),g_{a})$ as interpretable design abstractions rather than quantities to be estimated end-to-end: they motivate a two-threshold rule and explain why the boundaries should be ordered, but the operating point $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})=(0.2,0.6)$ is calibrated empirically via the sensitivity sweep in Section C.5, and a personalized data-driven instantiation is given in Section C.5.

## PROFILE initialization.

Equation 8 fuses a gate-level prior with the agent’s scalar. The class label $c$ returned by the Profile-Agent selects the band $I_{c}=[w_{\min}^{(c)},w_{\max}^{(c)}]$ ; the deterministic layer computes the prior $b_{t}^{(c)}=w_{\min}^{(c)}+\sigma(x_{t})\bigl(w_{\max}^{(c)}-w_{\min}^{(c)}\bigr)$ , clips the agent’s initial_confidence $q_{t}$ to $I_{c}$ , and averages the two. For example, with $I_{c}=[0.60,0.70]$ , $x_{t}=0.4$ and $q_{t}=0.65$ , one obtains $b_{t}^{(c)}=0.6599$ and $w_{0}(h)=0.6549$ . Because $q_{t}$ is clipped before it is halved, two agent scalars that differ by the full band width move $w_{0}$ by at most $0.05$ , so the number of MAINTAIN updates needed for promotion under Equation 7 changes by at most one, and $w_{\max}^{(c)}<\tau_{\mathrm{promote}}$ guarantees that no single agent output can commit a hypothesis as a FACT. The narrow range of $\sigma(x_{t})$ inside the band is therefore intentional: the class band carries the semantics, and the within-band value only fine-tunes the starting point. The agent additionally returns the decay_protection flag that governs Equation 9.

## Hypothesis decay horizon.

Equation 9 is applied once per turn to every unprotected hypothesis that received no supporting evidence in that turn, with the exponent $a_{t}(h)$ measured from the last evidence-bearing update $\ell(h)$ . For a hypothesis that is never reinforced the factors compound, so after $n$ consecutive unsupported turns

 $w_{\ell+n}(h)=w_{\ell}(h)\exp\!\Bigl(-\gamma\,\frac{n(n+1)}{2}\Bigr),$ 

(28)

which is faster than a fixed per-turn factor. This is intended: it instantiates the capacity penalty $\Omega$ of Equation 15 (hypotheses are pruned below $w=0.1$ ) and is why effective memory plateaus over the dialogue (Section 3.5). With the decay rate $\gamma=0.05$ used in our experiments, an unsupported latent hypothesis started inside its band is pruned after eight consecutive unsupported turns. The horizon counts only consecutive unsupported turns: a single reinforcement resets $\ell(h)$ and restarts the window, and explicit-event hypotheses are decay-protected, so only guesses that are never revalidated are culled.

## B.4 Per-turn pipeline (hybrid execution)

Algorithm 1 makes the hybrid execution discussed in Section 2.4 explicit. Each turn invokes (i) a deterministic Retrieve step, (ii) a deterministic computation of $\rho_{t},S_{\mathrm{raw}},x_{t}$ , (iii) a regime-specific LLM sub-agent (one of Maintain-Agent, Profile-Agent, Correct-Agent; prompts in Appendix D) that emits per-item scalar scores, and (iv) a deterministic application of the closed-form updates in Equations 7, 8 and 10. The sub-agents only inject which items to touch and how strongly; gating, soft-decay, reinforcement, and hypothesis-promotion mechanics are entirely symbolic.

## Appendix C Additional experimental details

## C.1 Third-party benchmarks: AMemGym and LoCoMo-Plus

To test whether the write-path advantage transfers to data we did not design, we evaluate PreCoMem on two public benchmarks built by other groups: AMemGym [1], an on-policy benchmark with gold state transitions in which a simulated user’s latent task state (for example a project’s preparation stage or budget band) changes across periods, and LoCoMo-Plus [22], a static benchmark of 401 implicit cognitive-constraint questions. Both are run under their official protocols with the same backbone for all compared systems.

## AMemGym.

We use the official on-policy v1.base release (code snapshot ffcd188, data 4b8f64f) at the official 20-profile / 11-period setting (ten gold state transitions per profile; 943 sessions and 2,200 questions per run) with three paired seeds $(13,42,1234)$ . The user simulator is gpt-4.1 ( $T{=}0.2$ ); PreCoMem and all of its variants use gpt-4.1-mini ( $T{=}0$ ) with text-embedding-3-small, Top- $K{=}10$ , $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})=(0.2,0.6)$ and $\lambda=0.5$ . Each AMemGym session is a single user turn, so one gate event is logged per session. We report the benchmark’s two headline scores, the Overall accuracy over the 2,200 questions and the normalized Memory score defined by AMemGym (Overall rescaled between the benchmark’s random-answer and upper-bound references), together with its native write / read / utilization failure rates. ## C.2 Backbone-generalization protocol and token usage

## Scale-vs-mechanism protocol behind Figure 3(a)–(d).

Each x-axis group of Figure 3(a)–(d) fixes the model that answers the questions: Qwen3.5-35B, Qwen3.5-122B or GPT-5-Chat. The two bars of a group differ only in how memory is built and maintained. The left bar runs the answer model with its own native memory, instantiated by O-Mem at the same scale, so every such bar already includes a full memory system. The right bar keeps the answer model unchanged and delegates memory construction (the write path and retrieval) to PreCoMem running on a one-tier-smaller backbone: Qwen3.5-9B for the Qwen3.5-35B group, Qwen3.5-35B for the Qwen3.5-122B group, and GPT-5-mini for the GPT-5-Chat group. The right bar exceeds the left one in every group and on every dataset (all twelve $\Delta>0$ ): memory construction can be delegated to a much cheaper model and still beat the larger model’s native memory, i.e., with the answer model held equal the mechanism substitutes for roughly one tier of model scale.

## Hypothesis lifecycle statistics.

Figure 6: Hypothesis lifecycle under PreCoMem. A hypothesis created by PROFILE (Stage 1) enters multi-turn verification (Stage 2): consistent support raises its confidence toward the promotion threshold $\tau_{\mathrm{promote}}$ (Stage 3 $\to$ Stage 4, becoming a stable core-profile belief that ranks above hypotheses in confidence-weighted retrieval), while no/weak support lets its weight decay; once $w_{t}$ falls below the prune threshold the hypothesis is removed from the active pool (Stage 5a); a committed FACT that is later reliably contradicted is instead softly decayed and kept for provenance (Stage 5b). ## Category-level annotation supporting the attribution.

The attribution of the gains in the main text rests on the benchmark annotations. On LoCoMo, Open-Domain is the only split whose questions are inferential in form (20.8% begin with “Would/Might/What would…”) and whose gold answers are hedged inferences (14.6%); every other split scores 0.0% on both. Its target is typically a state not stated in a single turn: 49.0% of its questions carry two or more evidence pointers and 32.3% span two or more sessions (mean gap 4.51 sessions). Session span alone does not explain this: Multi-Hop spans more sessions (10.27 on average) yet has no hedged answers, since it joins co-valid stated facts, whereas Open-Domain must infer and revise a latent state. Temporal resolves from a single evidence pointer in 87.5% of cases, which is why no gain appears there. On LongMemEval-S, all 78 KU questions have exactly two answer sessions, an old value and the value superseding it, so an un-updated memory is wrong by construction; SSA questions instead have one answer session whose gold evidence lies in assistant turns (51 of 56), a single target among $48.9$ sessions on average, so the SSA gain comes from confidence-weighted retrieval acting as an implicit reranker. We therefore attribute the drift-related gains to KU, SSP, cross-session MS and Open-Domain, and describe SSA as selective memory use.

## C.4 Component, operator, and control ablations

## Fine-grained ablation of raw-surprisal components.

The raw-surprisal term $S_{\mathrm{raw}}=\lambda\,d_{\mathrm{sem}}+(1-\lambda)\,d_{\mathrm{conf}}$ mixes a semantic-gap signal and a verifier-based contradiction signal (Equation 4, Section B.2). To disentangle their individual contributions, we ablate each component by forcing one branch to zero. w/o $d_{\mathrm{sem}}$ sets $\lambda\!=\!0$ , keeping only the contradiction verifier; w/o $d_{\mathrm{conf}}$ sets $\lambda\!=\!1$ , keeping only the semantic gap. As shown in Table 10, both components are useful, but $d_{\mathrm{conf}}$ contributes substantially more: removing it costs $-10.08$ points on LoCoMo and $-11.57$ points on LongMemEval-S, roughly double the drop from removing $d_{\mathrm{sem}}$ ( $-5.74$ and $-6.63$ points respectively). This matches the design intuition: the semantic gap alone cannot distinguish a genuinely contradictory utterance from one that is merely off-topic relative to current memory, whereas the NLI-based contradiction score directly detects reliable negation and drives CORRECT. Keeping both signals, on the other hand, gives the best trade-off between sensitivity (detecting drift cues via $d_{\mathrm{sem}}$ ) and precision (avoiding spurious corrections via $d_{\mathrm{conf}}$ ).

## DiMoBench evolution-operator ablations.

We ablate PreCoMem’s three evolution operators on DiMoBench: PROFILE (hypothesis writing), CORRECT (surprisal-gated soft correction), and MAINTAIN (reinforcement/smoothing). We report accuracy every 10 turns from turn 150 to 350. As shown in Figure 4(c), removing PROFILE lowers the final accuracy ceiling (72%), removing CORRECT substantially slows post-drift recovery, and removing MAINTAIN leads to high-variance dynamics that do not stabilize within our evaluation horizon (ending at 54% accuracy).

## Operator-level analysis.

DiMoBench is designed to separate three regimes that stress different update behaviors: a stable pre-change phase (turns $\approx$ 150–200), a short change-point phase with mixed/ambiguous cues and decoy retrieval (turns $\approx$ 200–240), and a stable post-change phase where the latent attitude has reversed (turns $\approx$ 240–350). Under this structure, the three operators contribute in complementary ways.

PROFILE: buffered adaptation under implicit drift. Many change-point cues are neither clean confirmations nor decisive contradictions: they are novel, partially ambiguous, and often entangled with confounders. PROFILE converts these medium- $S_{\mathrm{eff}}$ signals into low-confidence, testable hypotheses, enabling the system to accumulate multiple weak cues before committing. This “waiting room” is especially important on DiMoBench because questions explicitly probe trend/change-point reasoning and hypothesis-vs-fact distinction. When PROFILE is removed, the system loses this intermediate representation and commits weak cues without a waiting room (premature commitment under decoys), which reduces the asymptotic ceiling (72% vs. 84% for full PreCoMem).

CORRECT: targeted suppression of outdated beliefs. After the drift, previously correct high-confidence beliefs become systematically misleading, and decoy retrieval makes stale evidence likely to reappear. CORRECT provides a selective revision mechanism by downweighting contradicted items via the $\zeta_{t}(m)$ -modulated soft decay while leaving non-contradictory items largely unchanged. This targeted decay is crucial for reducing old-memory pull and preventing interference from pre-change beliefs. Without CORRECT, outdated facts remain competitive in retrieval, so the agent must rely on accumulating new nodes and indirect effects to “outvote” entrenched beliefs, yielding a substantially slower recovery (reaching 75% only around turn 320 vs. turn 250) and a lower final plateau (77% vs. 84%).

MAINTAIN: consolidation for stability. MAINTAIN acts as a consolidation step that repeatedly reinforces supported beliefs, which sharpens confidence-weighted retrieval, increases retrieval reliability $\rho_{t}$ (by making the score mass more concentrated), and stabilizes the routing signal $x_{t}(=S_{\mathrm{eff}})$ . It also underpins the hypothesis lifecycle: hypotheses created by PROFILE require repeated reinforcement to cross the promotion threshold and become stable facts. This stabilization is critical in the post-change phase, where the system should stop oscillating and settle into the post-change regime. When MAINTAIN is ablated, supported post-change beliefs cannot be progressively consolidated; retrieval remains diffuse and volatile, the reliability-adjusted loss becomes noisy, and updates keep “chasing” confounded evidence. Empirically, this yields persistent volatility: accuracy continues to fluctuate and ends at 54% at the end of our evaluation.

## Route-matched and factorial controls.

## LLM-direct-write baseline.

A natural alternative to the hybrid design of Section 2.1 is to let the same LLM decide the whole write step. The direct-write baseline matches PreCoMem in every other component (retrieval, embedding, Top- $K{=}10$ , context, judge, seeds, gpt-4.1); the only change is that the LLM emits the entire write decision as one object, {route, target_ids, operation, new_weights, new_belief}, whose weights are written verbatim, replacing the gate, the closed-form updates and the $[0,1]$ clamping. Table 13 shows that accuracy is lower in every seed ( $-2.75$ on LoCoMo, $-3.15$ on LongMemEval-S) while per-query tokens are slightly higher (3.2k / 3.9k against 3.1k / 3.8k), so the loss is not offset by efficiency. The more telling difference is stability: the cross-seed standard deviation is $20\times$ higher on LoCoMo (1.42 against 0.07) and $2.1\times$ higher on LongMemEval-S, because unconstrained numeric decisions make the memory trajectory run-dependent. Replaying the write decisions on a frozen store, direct write emits a missing target id in 3.6% of decisions, a self-contradictory operation in 2.7% and invalid JSON in 1.8% (mutually exclusive categories); such malformed writes corrupt the store silently and compound, whereas the closed-form updates stay in $[0,1]$ by construction. The loss is spread over all LoCoMo splits (Single-Hop $-1.65$ , Multi-Hop $-4.80$ , Temporal $-2.70$ , Open-Domain $-6.50$ ). The deterministic layer is what keeps long-horizon memory bounded.

## Turn-level versus per-item routing.

PreCoMem computes one gate score per turn and routes the whole retrieved set to a single operator; the per-item magnitudes $\eta_{t}(m)$ and $\zeta_{t}(m)$ apply after routing. A turn can therefore reinforce several beliefs, or correct several beliefs, at once, but it cannot reinforce one belief, correct another and profile a third in the same step. To measure how often this matters we annotated gold operators per retrieved item on 9,006 turns (all LoCoMo dialogues plus the LongMemEval-S evidence sessions): 3,475 turns touch at least one retrieved belief, and 95.83% of them are expressible by a single route, either a single belief or several beliefs sharing one operator. The remaining 145 turns (1.61% of all turns, 21.4% of the 678 multi-item turns) are genuinely mixed. A per-item variant, identical in retrieval, backbone and closed-form updates but routing each item independently, raises the whole-turn agreement with the gold operators on these 145 turns by $+5.5$ points and their question accuracy by $+3.5$ points, at $+31\%$ write calls and $+14\%$ write tokens, for a net gain of $+0.3$ points over the full evaluation. Given the small net benefit at a materially higher cost, we keep turn-level routing as the default and regard per-item claim extraction as a direction for future work.

## Mechanism-level analysis.

We provide a more formal explanation of why oversized $k$ can hurt PreCoMem beyond generic retrieval noise. Recall that PreCoMem uses entropy-based retrieval reliability $\rho_{t}$ and the max-contradiction term $d_{\mathrm{conf}}$ :

 $\displaystyle\hat{s}_{i}$ 
 $\displaystyle=\frac{s_{i}+\epsilon}{\sum_{j=1}^{k}(s_{j}+\epsilon)},$ 

(29)

 $\displaystyle H_{t}$ 
 $\displaystyle=\frac{-\sum_{i=1}^{k}\hat{s}_{i}\log\hat{s}_{i}}{\log k},$ 

 $\displaystyle\rho_{t}$ 
 $\displaystyle=1-H_{t}.$ 

 $\displaystyle S_{\mathrm{eff}}(u_{t})=x_{t}$ 
 $\displaystyle=\rho_{t}\Big(\lambda\,d_{\mathrm{sem}}(u_{t},\mathcal{C}_{t})+(1-\lambda)\,d_{\mathrm{conf}}(u_{t},\mathcal{C}_{t})\Big),$ 

(30)

 $\displaystyle d_{\mathrm{conf}}$ 
 $\displaystyle=\max_{m\in\mathcal{C}_{t}}\pi_{t}(m).$ 

## (1) $k\uparrow$ flattens scores $\Rightarrow\rho_{t}\downarrow$ and CORRECT is suppressed.

The reliability $\rho_{t}$ decreases when the normalized score distribution $\hat{\mathbf{s}}$ becomes less concentrated.
To make this explicit, consider a simple extension model where the Top- $k$ distribution over the original $k_{0}$ items is $\mathbf{p}\in\Delta^{k_{0}-1}$ , and increasing $k$ adds $k_{1}$ additional tail items whose total normalized mass is $\delta\in(0,1)$ and is approximately uniform within the tail:

 $\mathbf{p}^{\prime}=\big((1-\delta)p_{1},\ldots,(1-\delta)p_{k_{0}},\underbrace{\tfrac{\delta}{k_{1}},\ldots,\tfrac{\delta}{k_{1}}}_{k_{1}\ \text{items}}\big),k=k_{0}+k_{1}.$ 

(31)

By concavity of Shannon entropy, injecting nonzero tail mass strictly increases entropy unless $\delta=0$ . A direct decomposition yields

 $\mathcal{H}(\mathbf{p}^{\prime})=(1-\delta)\mathcal{H}(\mathbf{p})+h(\delta)+\delta\log k_{1},$ 

(32)

where $\mathcal{H}(\cdot)$ is unnormalized entropy and $h(\delta)=-\delta\log\delta-(1-\delta)\log(1-\delta)$ is the binary entropy.
Thus, for typical retrieval where the tail receives non-negligible probability mass, $H_{t}$ increases with $k$ and $\rho_{t}$ decreases.

This interacts with the fixed-threshold gate: CORRECT is triggered when $x_{t}=S_{\mathrm{eff}}(u_{t})>\theta_{\mathrm{high}}$ .
Since $x_{t}=\rho_{t}S_{\mathrm{raw}}(u_{t})$ with $S_{\mathrm{raw}}(u_{t})\in[0,1]$ , the event can be rewritten as

 $\rho_{t}S_{\mathrm{raw}}(u_{t})>\theta_{\mathrm{high}}\quad\Longleftrightarrow\quad S_{\mathrm{raw}}(u_{t})>\frac{\theta_{\mathrm{high}}}{\rho_{t}}.$ 

(33)

Therefore, as $\rho_{t}$ decreases, the required raw-surprisal level $\theta_{\mathrm{high}}/\rho_{t}$ increases, making reliable correction harder to trigger and strengthening old-memory pull. This effect is most visible for Temporal queries, where Top- $k$ often mixes pre- and post-change evidence, yielding a less concentrated score mass (higher $H_{t}$ ) even when the underlying contradiction is real.

## (2) $k\uparrow$ amplifies spurious contradictions via a max statistic.

The contradiction term uses an order statistic $d_{\mathrm{conf}}=\max_{m\in\mathcal{C}_{t}}\pi_{t}(m)$ .
If we view $\pi_{t}(m)$ for irrelevant/mismatched retrieved items as random variables with CDF $F_{0}$ on $[0,1]$ , then for $k$ candidates,

 $\Pr\!\left(d_{\mathrm{conf}}>\tau\right)=1-\Pr\!\left(\pi_{t}(m)\leq\tau\right)^{k}=1-F_{0}(\tau)^{k},$ 

(34)

which is monotonically increasing in $k$ for any $\tau\in(0,1)$ with $F_{0}(\tau)\in(0,1)$ . When $1-F_{0}(\tau)$ is small, the increase is approximately linear:

 $1-F_{0}(\tau)^{k}\approx k\,(1-F_{0}(\tau)).$ 

(35)

Thus, larger evidence sets increase the probability of observing an artificially high contradiction score from at least one mismatched memory, which can (i) inflate $S_{\mathrm{raw}}$ through the $(1-\lambda)d_{\mathrm{conf}}$ component and (ii) distract response generation by presenting a “hard contradiction” that is not actually relevant to the query. Together with (1), this explains why performance can decline for large $k$ despite higher coverage.

## Implication.

The empirical peak at $k{=}10$ reflects a regime where coverage is sufficient to retrieve the right evidence, while $\rho_{t}$ remains high enough to permit timely CORRECT actions and the max-contradiction term remains less exposed to spurious outliers. This motivates using $k{=}10$ as a robust default under a moderate compute budget.

## Sensitivity to gating thresholds.

Theoretically, one may dynamically compute or adapt the thresholds (e.g., by estimating the action costs/effects in Equation 27), which could yield better per-sample or per-stage performance. However, such on-policy adaptation introduces additional computation and confounds controlled evaluation because the observed behavior becomes entangled with an evolving threshold schedule.

We therefore adopt a fixed threshold pair $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})$ in all experiments and justify a reasonable choice via a sensitivity study. For controllable and cost-bounded ablation, we select a representative LoCoMo sample (Sample 1; 400 dialogue turns and 105 QA pairs) whose question types are relatively balanced and whose scale supports rapid iteration. We sweep $\theta_{\mathrm{low}}\in\{0.10,0.15,0.20,0.25,0.30\}$ and $\theta_{\mathrm{high}}\in\{0.50,0.55,0.60,0.65,0.70\}$ in steps of $0.05$ ( $5{\times}5=25$ configurations) and evaluate LLM-judge accuracy on this sample. As shown in Figure 8, the deployed default $(0.20,0.60)$ (red box) sits at the center of a high-performing plateau: its four direct neighbors $(0.15,0.60)$ , $(0.25,0.60)$ , $(0.20,0.55)$ and $(0.20,0.65)$ all stay within a narrow $1.3$ – $2.6$ -point band of the peak. Accuracy decays smoothly toward the corners (down to roughly $64$ – $67$ % near $\theta_{\mathrm{low}}{=}0.30,\theta_{\mathrm{high}}{=}0.70$ and the symmetric corner), confirming that the gate is locally robust rather than knife-edged.

Importantly, this fixed choice is a trade-off: we do not claim $(0.2,0.6)$ is universally optimal for every LoCoMo sample. Rather, it provides a stable and interpretable operating point with competitive accuracy under a fixed computational budget, and we keep it constant across experiments for fair comparison and reproducible observations.

## Adaptive thresholding for personalization.

One natural question is whether the fixed gating thresholds $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})=(0.2,0.6)$ are appropriate for all users, or whether different user populations would benefit from different thresholds. Intuitively, users differ in belief stability: some keep stable preferences so that short-term deviations are noise, while others change frequently so that the same deviations reflect real drift. A fixed threshold cannot simultaneously satisfy both regimes. We therefore discuss and evaluate a simple adaptive-thresholding extension of PreCoMem.

## User stability index.

We summarize each user’s recent dynamics with a scalar stability index $\psi_{t}\in[0,1]$ , computed from interaction statistics over a sliding window of length $W$ :

 $\psi_{t}=\omega_{1}\,\psi_{\mathrm{corr}}+\omega_{2}\,\psi_{\mathrm{life}}+\omega_{3}\,\psi_{\mathrm{var}},$ 

(36)

where (i) $\psi_{\mathrm{corr}}=1-N_{\mathrm{correct}}^{(W)}/N_{\mathrm{total}}^{(W)}$ captures how rarely CORRECT fires in the recent window, (ii) $\psi_{\mathrm{life}}=\min\!\left(1,\bar{L}_{\mathrm{belief}}/L_{\mathrm{ref}}\right)$ captures average belief lifespan relative to a reference $L_{\mathrm{ref}}$ , and (iii) $\psi_{\mathrm{var}}=\exp\!\left(-\kappa\cdot\mathrm{Var}\!\left[S_{\mathrm{eff}}^{(W)}\right]\right)$ captures the variance of effective surprisal. The coefficients satisfy $\omega_{1}+\omega_{2}+\omega_{3}=1$ , and we use $\omega_{1}{=}0.5,\omega_{2}{=}0.3,\omega_{3}{=}0.2$ in the experiments below ( $\kappa$ and $\omega_{i}$ are specific to this variant and unrelated to the $\gamma$ and $\alpha_{j}$ of the main text).

## Threshold adaptation.

We then map $\psi_{t}$ to thresholds by linear interpolation between a conservative upper configuration and an aggressive lower configuration:

 $\displaystyle\theta_{\mathrm{low}}(t)$ 
 $\displaystyle=\theta_{\mathrm{low}}^{\min}+\psi_{t}\!\left(\theta_{\mathrm{low}}^{\max}-\theta_{\mathrm{low}}^{\min}\right),$ 

(37)

 $\displaystyle\theta_{\mathrm{high}}(t)$ 
 $\displaystyle=\theta_{\mathrm{high}}^{\min}+\psi_{t}\!\left(\theta_{\mathrm{high}}^{\max}-\theta_{\mathrm{high}}^{\min}\right),$ 

with $\theta_{\mathrm{low}}\!\in\![0.10,0.35]$ and $\theta_{\mathrm{high}}\!\in\![0.40,0.80]$ . Intuitively, a stable user ( $\psi_{t}\!\to\!1$ ) receives larger thresholds, so the system requires stronger evidence before updating; a dynamic user ( $\psi_{t}\!\to\!0$ ) receives smaller thresholds, so the system reacts faster. To avoid oscillation, we smooth the thresholds with an exponential moving average with coefficient $\mu{=}0.1$ .

## Theoretical view.

From a Bayesian perspective, the thresholds encode a prior on belief persistence: stable users have a stronger prior that beliefs are unchanged, so a higher $\theta_{\mathrm{high}}$ corresponds to requiring stronger likelihood evidence to revise them, and vice versa for dynamic users. From a signal detection perspective, $\theta_{\mathrm{low}}$ and $\theta_{\mathrm{high}}$ trade off false-update rate (triggering CORRECT on noise) against missed-update rate (failing to trigger on genuine drift); since these two error rates have different relative costs for different users, the Bayes-optimal decision boundary is user-dependent. Equation 37 is a minimal realization of this idea that only reads summary statistics PreCoMem already maintains and introduces no extra trainable parameters.

## Empirical results on LoCoMo.

We evaluate the adaptive variant, denoted PreCoMem (DT), on the full LoCoMo benchmark with two backbones (gpt-4o-mini and gpt-4.1), keeping every other setting identical to the main experiments. As shown in Table 15, relaxing the fixed thresholds to Equation 37 yields consistent gains in overall accuracy ( $+0.98$ on gpt-4o-mini, $+1.15$ on gpt-4.1), with the largest improvement on the Open-Domain subset under gpt-4o-mini ( $+3.92$ ), which is the category most exposed to long-horizon drift. The same trend holds on LongMemEval-S, where PreCoMem (DT) lifts the overall score from $84.28$ to $85.36$ under gpt-4o-mini, with the largest gains on KU (knowledge update, $+1.62$ ) and SSP (single-session preference, $+1.95$ ); these are precisely the question types that require per-user calibration of how aggressively to update beliefs.

## C.6 DiMoBench: construction and extended-horizon stress test

## Construction pipeline and characteristics.

DiMoBench (Dialogue Implicit Memory Drift Benchmark) is designed to isolate belief-drift adaptation under sparse and implicit cues. The released suite consists of five 350-turn two-speaker dialogues, each built around a distinct persona drawn from a different combination of Big-Five extremes and life stages; for clarity the exposition below focuses on one canonical persona, but every quantitative result on DiMoBench (the dynamics in Figure 4(b) and the operator ablation in Figure 4(c)) is averaged across the five personas to avoid a single-persona artifact; the human–judge agreement audit in Table 8 uses the canonical persona, whose per-type accuracies lie within $0.15$ points of the five-persona means. Within each persona the user’s latent attitude toward a target topic remains stable in turns 1–200, gradually reverses in turns 201–210 via 3–4 implicit events, and is then reinforced with denser behavioral signals in turns 211–240 before entering a low-frequency maintenance stage in turns 241–350.

To stress long-horizon robustness, DiMoBench injects confounders: every 30 turns we insert irrelevant chit-chat or hypothetical narration that shares surface keywords with the target topic, and we introduce multiple similar entity names to induce attribution ambiguity. Each persona contributes 200 QA pairs distributed across the dialogue (denser sampling near the change point and sparser in the long maintenance tail; $1{,}000$ in total across the five personas), covering (i) current-state inference, (ii) history recall, (iii) change-point detection, and (iv) hypothesis vs. fact distinction. Importantly, questions avoid explicit sentiment keywords and instead require reasoning from behavioral cues (plans, actions, reactions), making drift detection and correction rely on implicit evidence chains rather than lexical matches.

## Why DiMoBench is needed.

Existing long-horizon dialogue benchmarks predominantly evaluate the read path: whether a system can correctly retrieve and reason over a static conversational record (LoCoMo [28]) or whether it can infer implicit personalization from accumulated preferences (PersonaMem-v2 [16]). None of them explicitly stress-test the write path, i.e., whether a memory system can correctly decide when to maintain, update, or correct its stored beliefs under gradual, implicit drift. DiMoBench is designed to fill this gap along three axes that are absent from existing benchmarks simultaneously: (i) continuous non-stationarity, where the latent attitude reverses gradually over hundreds of turns without any explicit announcement; (ii) implicit behavioral cues, where the drift manifests only through activity choices, reactions to invitations, and hedging language rather than sentiment keywords; and (iii) adversarial retrieval interference, where five tagged interference types (entity_confusable, keyword_trap, temporal_decoy, hypothetical_vs_fact, none) systematically probe two stability–plasticity failure modes: old-memory pull and premature correction. This write-path orientation is what lets DiMoBench reveal the distinct contributions of MAINTAIN, PROFILE, and CORRECT in Section C.4, which cannot be isolated on LoCoMo or PersonaMem-v2 alone.

## Six-stage construction pipeline.

DiMoBench is constructed by a six-stage progressive pipeline with an explicit generator–verifier separation (GPT-4o for generation, Gemini-2.5-Pro for verification) to avoid self-reinforcing biases. Figure 9 visualizes the full pipeline as an end-to-end flow, and Table 16 summarizes the stages; details follow below.

Stage 1 (Persona). Each persona is characterized by one core emotional/behavioral slot (e.g., “attitude toward social activities”) with a well-defined initial state and target state, a set of Big-Five personality dimensions, a small social circle of 2–3 named characters (some deliberately confusable to enable interference evaluation), routine daily activities, and a psychologically plausible drift trigger.

Stage 2 (Life skeleton). The 350-turn trajectory is organized into 35 sessions of 10 turns each. Sessions 1–20 (turns 1–200) establish baseline behavior; session 21 (turns 201–210) introduces the drift trigger via 3–4 implicit events; sessions 22–24 (turns 211–240) reinforce the new behavior with denser cues; sessions 25–35 (turns 241–350) form a low-frequency maintenance stage with monotonically reduced divergence from a steady post-drift baseline.

Stage 3 (Dialogue generation). Sessions are generated sequentially under cumulative context management. Generation rules enforce natural small talk and topic shifts, implicit expression through activity choices and hedging language, no meta-commentary (the user never says “I’ve changed”), and frequent temporal markers (“last weekend”, “this month”) for temporal reasoning.

Stage 4 (QA generation). 200 QA pairs span all temporal phases (pre-change: 90; change-point: 10; post-change: 100). Each QA carries explicit evidence pointers (D{session}:{turn}), an interference tag, and a reasoning-type label.

Stage 5 (Consistency verification). Each QA is cross-validated by Gemini-2.5-Pro along six dimensions: (i) answer grounding (is the answer supported by cited evidence?), (ii) evidence completeness (are all relevant turns cited?), (iii) temporal consistency (does the answer reflect the correct phase?), (iv) entity accuracy, (v) interference validity (does the tag match the question?), and (vi) drift coherence (is the behavioral change gradual and plausible?). QA pairs marked REVISE are regenerated by GPT-4o using verifier feedback (max 3 rounds); pairs marked REJECT are discarded. We target an $\geq\!95\%$ ACCEPT rate on the auto-verification pass.

Stage 6 (Human–machine review). Three graduate-level annotators with NLP research experience underwent a 2-hour calibration session covering implicit emotional expression, temporal reasoning, and entity disambiguation. All annotators independently label the same 20 QA pairs, and independent annotation proceeds only after inter-annotator agreement reaches $\kappa\!\geq\!0.75$ (Cohen’s $\kappa$ ). A 20% stratified sample (stratified by temporal phase, interference type, and QA category) receives full human review; in addition, one annotator per persona performs a full 350-turn dialogue-coherence assessment. Quality targets are answer correctness $\geq\!95\%$ , dialogue naturalness $\geq\!8.0/10$ , and drift subtlety $\geq\!7.5/10$ .

## DiMoBench-XL construction.

To stress-test the system beyond DiMoBench’s 350-turn horizon and across more personas, we constructed DiMoBench-XL, a suite of five 1050-turn dialogues, each with three sequential implicit drifts. Following the DiMoBench pipeline in Section C.6, we instantiate five user personas (each with a distinct demographic and dispositional profile, sampled to span both Big-Five extremes and different life stages); within each persona we keep five independent attributes (drink preference, exercise habit, home city, employment status, social style) and apply three drifts at turns $\{280,580,870\}$ , each shifting one or two attributes via $20$ – $30$ behavioral cues distributed across the surrounding session. Per persona we sample 20 evaluation QA pairs every 50 turns ( $420$ pairs each, $2{,}100$ in total), balanced across four reasoning types and five interference tags. The whole suite is verified by Gemini-2.5-Pro with the same six-criterion protocol as DiMoBench, achieving a $96.4\%$ average ACCEPT rate across personas (range $94.8$ – $97.6\%$ ) after one revision round.

## C.8 Retrieval dependence and reliability calibration

The write path acts only on the retrieved set $\mathcal{C}_{t}$ : if the belief that should be revised is not retrieved, the contradiction cannot be detected and CORRECT cannot fire in that turn. This section quantifies that dependence and then examines what the reliability coefficient $\rho_{t}$ actually tracks.

## Belief-update recall and failure decomposition.

We call an update-due event a point at which a stored belief must be revised for a later question to be answered correctly (one per evaluation question on DiMoBench and DiMoBench-XL, one per state transition with a pre-existing belief on AMemGym, and one per knowledge-update turn on LongMemEval-S KU), and we measure the Recall@10 of the belief due for update, i.e., how often it enters the write-path Top-10 at that event. Table 23 shows that recall covers most events (89–95%), leaving an explicit 5–11% blind spot, and that misses matter: question accuracy on events whose target was retrieved exceeds that on missed events by 16–22 points. Retrieval is favorable here because a contradictory utterance shares the attribute of the belief it contradicts with opposite polarity, so the target scores high on the semantic and lexical terms of Equation 1. Decomposing all update-due events pooled over the four benchmarks, 89.3% succeed; the residual 10.7% splits into unrecovered retrieval misses (5.4%; a further 1.4% of events are missed at retrieval but corrected later), gate misses (3.1%; the target was retrieved but the turn was not routed to CORRECT) and localization misses (2.2%; the turn was routed to CORRECT but the target was not decayed). Retrieval is thus the largest single source, with half of the failures (5.3 of the 10.7 points) sitting in gating and localization; on LongMemEval-S KU, where each update is stated once, retrieval misses dominate. A miss does not stall adaptation: the observation still enters the episodic cache and can form a hypothesis, and 20% of missed events (147 of 718) are corrected later by subsequent cues or hypothesis promotion.

To separate association from causation we force the target belief into the Top-10 at every missed event (displacing the lowest-ranked item) and re-run the write path and the question. This closes only 26–32% of the hit–miss gap (last column of Table 23): forcing the hit raises accuracy on the affected questions by 4.5–6.5 points, while the rest of the gap reflects that missed events are intrinsically harder and that gating and localization can still fail once the target is retrieved.

## What $\rho_{t}$ measures: calibration.

 $\rho_{t}=1-H_{t}$ is the normalized concentration of the Top- $K$ retrieval scores. It does not judge whether an individual retrieved item is correct; it weights how far the surprisal computed from that recall can be trusted, and because it enters only multiplicatively it can make the gate more conservative but never more aggressive. Two cases illustrate the behavior. If several relevant memories are correctly retrieved with similar scores, $\rho_{t}$ is lower and the update is dampened and deferred; no information is lost, since supporting evidence keeps accumulating through the hypothesis lifecycle and a genuine change is still committed after slightly more confirmation. If a wrong memory receives a very high score, $\rho_{t}$ is high, but $\rho_{t}$ is deliberately not the sole trigger: whether CORRECT fires still depends on $d_{\mathrm{conf}}$ , an NLI verifier run against the actual new utterance, and the change is a bounded, reversible soft decay that keeps provenance.

To check that concentration is a usable proxy for evidence precision, we stratify the 2,829 gate events of the AMemGym runs (943 per seed) into quintiles of $\rho_{t}$ and measure, per quintile, the precision of the retrieved set against the user’s current gold state, the recall of the belief due for update, the accuracy of the contradiction decision against 400 blind-annotated events (80 per quintile), the correctness of the resulting update, the share of CORRECT firings judged unwarranted (false-CORRECT), and the accuracy of the next state-query probe on the touched attribute (Table 24). Precision, contradiction accuracy, update correctness and downstream accuracy all rise monotonically from Q1 to Q5, and false corrections fall from 2.1% to 0.6% (only 5 of the 612 CORRECT firings were judged false overall), whereas recall is non-monotone and peaks in the middle quintiles. $\rho_{t}$ therefore tracks evidence precision, as a precision weight on the prediction error should.

## Correction delay during drift.

A related concern is that genuine drift produces mixed retrieval evidence, old facts and new contradictions both in the Top- $K$ , which raises $H_{t}$ and may delay CORRECT precisely when it is needed. We measure this on the 600 gold transitions of the AMemGym runs (20 profiles $\times$ 10 transitions $\times$ 3 seeds). In the first period after a change, a fresh belief node encoding the new state is created for 91.3% of the transitions and enters the answering Top-10 for 88.7%; the remaining 2.6% is a read-path ranking loss, since the new belief exists but does not enter the answering Top-10. A low $\rho_{t}$ delays a warranted CORRECT in 14.2% of the transitions; of these delays 78.0% clear within one period and 94.0% within two, and only 2.8% persist to the end of the run. End-to-end, this bounded delay is what separates PreCoMem’s one-period recovery from the two periods of AWE and the 1.8–3.2 periods of the ablated variants (Section C.1); removing the weighting altogether instead costs 16.76 points on LoCoMo (RR in Figure 4(a)).

The same analysis on DiMoBench, which has gold change points, uses the $\rho$ -assessability criterion that a gold shift counts only when the outdated belief is in the Top- $K$ and $S_{\mathrm{raw}}>\theta_{\mathrm{high}}$ , so that $\rho_{t}=1$ would route the turn to CORRECT; the delay $d$ is measured in turns (Table 25). Delays are the exception and bounded on both tracks: 7.3% of the assessable shifts on DiMoBench and 14.8% on DiMoBench-XL are delayed, and 71.4% of the delays clear within one turn and 85.7% within two. DiMoBench-XL exceeds the base track, consistent with its three drifts over 1050 turns and denser decoys. Since DiMoBench counts turns whereas AMemGym counts periods, the two rates agree in magnitude without sharing a unit, which is why we report them per track.

## Cold start and genuinely new topics.

A genuinely new topic differs from every stored belief, so its semantic-deviation term $d_{\mathrm{sem}}$ is high while $d_{\mathrm{conf}}\approx 0$ , and $S_{\mathrm{raw}}$ is driven up by novelty; even when all absolute similarities are small, one loosely related item normally dominates the Top- $K$ , so $\rho_{t}$ stays moderate and $S_{\mathrm{eff}}$ lands in the PROFILE band. MAINTAIN would require an unsurprising cue with low $d_{\mathrm{sem}}$ , which a new topic is not. In cold-start probes on the AMemGym profiles, a first-time cue is written on an empty store 96.5% of the time (579 of 600 probes, each starting from a reset store); when the store is populated and the cue matches little, a usable belief forms within one period in 84.2% of cases and within two in 92.7% (600 new-topic probes), while only 5.6% of 180 distractor cues are written as hypotheses. A low match therefore costs at most a short confirmation delay. Section C.11 walks through an example.

## C.9 Retrieval and end-to-end latency analysis

## Experimental setup.

We conduct all latency evaluations on the LoCoMo dataset. To ensure a rigorous comparison, we standardize the hardware and model environment across all systems:

• 

LLM Backbone: gpt-4o-mini serves as the backbone for all generation and retrieval operations.

• 

Embeddings: All embeddings are generated using
Qwen3-Embedding-0.6B with 1024 dimensions.

• 

Configuration: Each baseline operates under its official recommended hyperparameters.

## Metrics.

We report P50 and P95 latency for both the retrieval stage and the full end-to-end (E2E) response:

• 

Retrieval latency measures only the cost of producing the retrieved evidence set $\mathcal{C}_{t}$ (memory read, scoring, and any re-ranking), and isolates the architectural cost of the memory system itself.

• 

End-to-end (E2E) latency measures the full user-visible time from receiving a query $u_{t}$ to emitting the final answer, including retrieval plus generation.

• 

P50 (Median): The median latency, representing the typical time required to process a query.

• 

P95 (95th Percentile): The threshold within which 95% of queries are completed, reflecting performance stability under high load or ambiguity.

## Results and analysis.

Table 26 summarizes the comparative performance. PreCoMem achieves a retrieval P50 / P95 of 1.95s / 3.86s and an E2E P50 / P95 of 2.35s / 4.36s.

• 

Efficiency via vectorized scoring: PreCoMem achieves a competitive P50 by leveraging a confidence-modulated hybrid scoring mechanism (Equation 1). Rather than relying on computationally intensive generative re-ranking or iterative graph traversals, our approach efficiently aggregates semantic and lexical signals through parallelizable matrix operations. This design ensures that the computational overhead remains modest relative to pure vector retrieval, even as the complexity of the belief store increases.

• 

Stability via deterministic flow: A critical advantage of PreCoMem is its robustness against latency spikes. Unlike agentic architectures (e.g., A-Mem) that may trigger unpredictable, recursive reasoning loops to resolve ambiguities, PreCoMem employs a deterministic, non-recursive retrieval flow. This architectural choice constrains both the retrieval tail (P95: 3.86s) and the E2E tail (P95: 4.36s), ensuring consistent performance without the extreme delays (E2E P95 up to 7.68s for A-Mem) often observed in stochastic agentic systems.

• 

Retrieval vs. E2E gap: The gap between retrieval and E2E latency is dominated by generation, which is largely independent of the memory backend. PreCoMem’s E2E overhead over the retrieval stage (0.4s at P50, 0.5s at P95) is comparable to other non-agentic baselines, confirming that adding PROFILE/CORRECT does not materially inflate generation cost.

## C.10 Structural comparison: why PreCoMem outperforms existing memory systems

Beyond the headline accuracy gains in Table 1, two structural properties of PreCoMem account for the consistent improvement and have no direct analogue in any of the nine baselines we compare against. We summarize the contrast along the two axes that most directly govern long-horizon behavior.

## Axis 1: Robustness to noise and faithful preservation of user core traits.

Existing systems represent the importance of an incoming observation categorically. GAM [46] writes one compressed memo per session into an immutable page-store with no per-item weight; EverMemOS [10] validates each MemCell within a hard time interval $[t_{\mathrm{start}},t_{\mathrm{end}}]$ and treats it as expired once the interval closes; TiMem [21] encodes importance through its five-level temporal hierarchy and explicitly notes the absence of a storage-time forgetting mechanism; MemBox [38] stores all events inside a sealed topic box at uniform weight; O-Mem [40] updates persona slots via an LLM that selects one of three categorical actions (Add/Ignore/Update); Mem0 [2] commits ADD/UPDATE/DELETE/NOOP and physically removes contradicted memories on DELETE; and A-Mem [45] replaces an existing note with an LLM-rewritten note via Memory Evolution. None of these systems can defer commitment when evidence is ambiguous: a weak signal is either ignored or instantly written as a fact. PreCoMem’s continuous confidence weight $w_{t}(m)\!\in\![0,1]$ paired with the HYPOTHESIS waiting room lets weak cues accumulate evidence across turns and only graduate into FACT once support concentrates. The same mechanism preserves established traits: soft-decay correction (Equation 10) reduces the influence of contradicted facts without erasing them, so a transient noise burst cannot remove a long-established trait the way a hard DELETE or overwrite would. This explains the LongMemEval-S gains on SSP (single-session preference), MS (multi-session aggregation), and KU (knowledge update) in Table 1, where ambiguous and conflicting cues dominate the question pool and categorical commit decisions are exactly the wrong granularity.

## Axis 2: Retrieval coherence and avoidance of fragmentation.

Each baseline retrieval substrate carries a structural failure mode that PreCoMem sidesteps. GAM iterates a deep-research loop over its page-store, whose answer correctness is order- and budget-sensitive; EverMemOS issues dense+BM25 retrieval over Atomic Facts, fuses by RRF, and then runs a sufficiency-check loop that can leave cross-shard inconsistency between MemCells of the same scene; TiMem performs a two-stage hierarchical recall whose scope depends on a planner classifier; MemBox returns full topic boxes wholesale with no within-box reweighting; O-Mem aggregates three parallel channels (working / episodic / persona) by union, so irrelevant attribute hits dilute the context window; Mem0 falls back on a single dense-similarity threshold and discards deleted-but-relevant facts; and A-Mem performs pure cosine top- $k$ over linked atomic notes, where the fine granularity amplifies fragmentation noise. All of these substrates therefore require an explicit reranker, sufficiency loop, or planner to suppress incoherent reads. PreCoMem instead multiplies a tri-signal relevance score by the per-item confidence $w_{t}(m)$ (Equation 1), which acts as an implicit reranker at no extra LLM call: high-support items naturally rise to the Top- $K$ , deprecated items naturally sink, and the entropy-based reliability $\rho_{t}$ (Equation 3) further damps unreliable updates when the score mass is diffuse. This is what produces the bounded retrieval contamination in Table 20 and the bounded effective memory in Figure 5(b,c), both of which scale to the 1050-turn DiMoBench-XL run without recourse to a maintenance loop.

## Coupling the two axes.

The two axes are complementary: Axis 1 controls what is committed so that the belief store stays faithful to the user’s core traits under noise, while Axis 2 controls what surfaces at read time so that the dialogue agent sees a coherent, currently-supported view. Existing baselines optimize one axis at a time (e.g., EverMemOS’s profile updates target Axis 1; GAM’s deep-research targets Axis 2) but lack a single mechanism that couples them. PreCoMem couples them through the same scalar confidence weight $w_{t}$ , which is the structural reason behind the consistent improvements observed across the four main benchmarks.

## C.11 System inspectability, traces, and qualitative analyses

## Memory store serialization and example snapshot.

To make the contents and interface of the Belief Store concrete, we describe how a belief item is serialized in practice and show an example snapshot from a DiMoBench run at turn 210, i.e., right after the change-point session. Each belief item $m\in\mathcal{B}_{t}$ carries (i) a natural-language proposition $c(m)$ , (ii) a type label $\tau(m)\in\{\texttt{FACT},\texttt{HYPOTHESIS}\}$ , (iii) a confidence weight $w_{t}(m)\in[0,1]$ , (iv) a creation timestamp and last-updated turn, and (v) pointers into the episodic cache $\mathcal{E}_{t}$ for provenance. A minimal serialization is shown in Figure 10.

Example Belief Store snapshot (turn 210, DiMoBench)
[FACT] Mike enjoys group social activities (w=0.82)
 sources=[D1:3, D1:5, D3:7]
[FACT] Mike and Leo often organize KTV outings (w=0.71)
 sources=[D2:4, D4:2]
[HYPO] Mike may be feeling socially fatigued (w=0.38)
 sources=[D21:6, D21:8]

Figure 10: Compact view of a Belief Store snapshot. Each entry shows the type, natural-language content, confidence weight, and pointers to the episodic cache. FACT items are committed, HYPOTHESIS items are tentative; confidences modulate retrieval priority but are never shown to the dialogue agent directly.

## What the dialogue agent actually sees.

Confidence weights $w_{t}(m)$ and other metadata are not exposed to the response-generation LLM. They only modulate retrieval ranking through the confidence-weighted score in Equation 1, so that high-confidence items surface near the top of $\mathcal{C}_{t}$ . The dialogue agent receives a plain-text prompt constructed from the Top- $K$ item contents $\{c(m)\}_{m\in\mathcal{C}_{t}}$ together with the relevant episodic-cache excerpts. This keeps generation-time inputs close to a standard retrieval-augmented prompt while still letting the memory system use confidences internally.

## Inspectability.

Because every belief carries explicit type, confidence, and source pointers, snapshots like Figure 10 can be dumped at any turn for inspection, regression testing, or qualitative error analysis, without re-executing the model. This also makes it straightforward to audit which episodic-cache turns support each currently-held belief, which we use for the end-to-end traces below.

## End-to-end trace examples on DiMoBench.

Below we provide two end-to-end traces that expose PreCoMem’s internal read–write decisions on a DiMoBench example dialogue. For readability, we list the retrieved belief set $\mathcal{C}_{t}$ by the episodic source turns of its items, without retrieval weights/scores, and we report only the qualitative regime of effective surprisal ( $x_{t}\!=\!S_{\mathrm{eff}}$ ) relative to $(\theta_{\mathrm{low}},\theta_{\mathrm{high}})$ .

## Trace format.

Each trace includes (i) the newly observed dialogue excerpt $u_{t}$ (one or a few turns) that triggers a memory write decision, (ii) a compact view of the retrieved evidence set $\mathcal{C}_{t}$ , (iii) the selected evolution operator (MAINTAIN/PROFILE/CORRECT), and (iv) a subsequent QA query answered using the updated memory state.

## Trace 1 (change point): early drift signal triggers PROFILE.

Pre-change belief snapshot (high confidence).
Mike enjoys crowded gatherings and rarely skips weekend social events (e.g., D1:5 “The more the merrier, I love that vibe …”; D1:7 “I wouldn’t miss weekend gatherings …”).

(Write) New observation $u_{t}$ (Session 21).

D21:6 “Someone invited me out, but I said work’s been busy and didn’t go.”

D21:8 “This weekend I went to a cafe alone, found a book and read for the whole afternoon.”

D21:9 “The environment was pretty quiet, not bad.”

Recall: Top- $K$ evidence $\mathcal{C}_{t}$ .

D1:5 “The more the merrier, I love that vibe …”

D1:7 “…I wouldn’t miss weekend gatherings …”

D2:9 “…I really can’t understand the joy of being a homebody.”

D3:7 “If I missed a gathering like this, I’d definitely have FOMO, afraid of missing out on the fun.”

D3:10 “Rest can wait, can’t miss the weekend activities! …”

D9:9 “If one day I don’t want to socialize, the sun must be rising from the west …”

D21:1 “Last weekend’s gathering, the atmosphere got a bit awkward.”

Reliability-adjusted surprisal.
The retrieved set consists of strong pre-change evidence (social enthusiasm) and a single emerging change-point cue (D21:1), none of which closely matches the new observation (skipped invitation; solo activity). The score mass is therefore spread over several items (higher entropy), making retrieval reliability $\rho_{t}$ moderate. Contradiction signals are also non-decisive: “work’s been busy” can explain a single skip, so $d_{\mathrm{conf}}$ is non-zero but not saturated. Overall, $x_{t}$ falls into the medium regime ( $\theta_{\mathrm{low}}<x_{t}\leq\theta_{\mathrm{high}}$ ).

Evolution: PROFILE.
PreCoMem writes a low-confidence hypothesis capturing a possible shift, e.g., “Mike may be starting to reduce large gatherings and explore quiet solo activities,” and links it to D21:6/D21:8--9 in the episodic cache. Crucially, PreCoMem does not immediately correct the long-standing high-confidence “social enthusiast” belief, avoiding premature overwrite from a single ambiguous event.

(Read) QA query.
Q: “Is Mike still as enthusiastic about gatherings as before?”

A: “Seems to be declining …”

Using the newly written hypothesis plus the concrete episode (D21:6 skipped invitation; D21:8--9 solo cafe), PreCoMem answers with a trend-aware response (declining / becoming evasive) while remaining cautious about permanence. In later sessions, repeated consistent cues (e.g., D23:3 “declined most invitations”) reinforce and eventually promote this hypothesis.

## Trace 2 (post-change, temporal decoy): reliable contradiction triggers CORRECT.

Precondition.
After multiple post-change sessions, PreCoMem has accumulated consistent evidence favoring solitude (e.g., D28:2 “Without gatherings I don’t feel bored anymore …”). However, an older pre-change statement remains in memory as a potential temporal decoy:

D1:8 “If there’s no gathering on the weekend, I feel like I’d be bored to death …”

(Write) New observation $u_{t}$ (Session 33).

D33:9 “Used to say I’d be bored without socializing, now being alone is actually more fulfilling.”

Recall: Top- $K$ evidence $\mathcal{C}_{t}$ .

D1:8 “…bored to death …”

D22:6 “This weekend I’m planning to stay home, maybe watch some shows or something.”

D23:2 “Used to think quiet places like that were boring, now I find them comfortable.”

D23:3 “…declined most gathering invitations …”

D25:2 “Used to think being alone was boring, now I actually enjoy it.”

D25:4 “…being alone is recharging, socializing …drains energy.”

D28:1 “Used to look forward to gatherings on weekends, now I look forward to alone time.”

D28:2 “Without gatherings I don’t feel bored anymore …”

D33:2 “Reducing socializing …not so exhausted anymore.”

Reliability-adjusted surprisal.
Here the recall distribution is more concentrated because multiple items explicitly mention the disputed claim (“bored without socializing”) and its reversal, yielding higher $\rho_{t}$ . The contradiction signal is strong: D33:9 explicitly negates the pre-change stance in D1:8, so $d_{\mathrm{conf}}$ is high. Consequently, $x_{t}$ falls into the high regime ( $x_{t}>\theta_{\mathrm{high}}$ ).

Evolution: CORRECT.
PreCoMem applies soft decay (Equation 10) to the contradicted belief(s) retrieved from $\mathcal{B}_{t}$ that encode the old stance (e.g., “weekends without gatherings are boring”), while leaving non-contradictory items largely unchanged. Because confidence weights directly modulate future retrieval (Equation 1), this correction reduces the chance of “old-memory pull” when later queries contain temporal-decoy phrasing.

(Read) QA query.
Q: “Would Mike still say ‘I’d be bored without socializing’?”

A: “No, being alone is actually more fulfilling now.”

PreCoMem retrieves the recent, high-support solitude evidence (D33:9, D28:2) and answers accordingly, while older evidence like D1:8 is downweighted by correction and recency, making the response robust to the temporal decoy.

Right: In project reasoning, it distinguishes high-confidence competencies from tentative learning (“loading”), preventing premature recommendations.

## Qualitative case studies beyond accuracy.

Figure 11 shows two cases in which the answer depends on how evidence was consolidated; a third, constructed case walks through a new topic entering the store.

## Case 1: Skill level calibration.

Figure 11 (left) illustrates this case. The user initially reports a credential (CET-6), which can tempt a retrieval-only system to over-trust a single strong signal and recommend overly advanced practice.
PreCoMem instead consolidates evidence across sessions: repeated behavioral cues (e.g., failing to articulate at an English corner) and professional feedback (teacher assessment) lower confidence in an over-optimistic self-evaluation, while preserving the belief that the foundation is adequate.
At query time, Memory Leveraging recalls these calibrated beliefs (rather than a single credential trace) to condition response generation, leading to a plan that targets fluency and practice rather than premature advanced content.

## Case 2: Project experience reasoning.

Long-horizon career discussions often mix stable skills (proven experience) with tentative claims (currently learning) and difficulty signals (struggles with complex systems).
PreCoMem uses its confidence-weighted belief store to separate what is established (e.g., Python/Flask) from what is still emerging (e.g., React “loading”) and what should be deferred (e.g., microservices architecture).
This produces right-sized recommendations: it proposes a near-term path aligned with demonstrated capability, while explicitly marking a challenge zone for later progression.

## Case 3: A new topic entering a populated store.

Suppose the store holds the user’s work and food profile but nothing about music, and the user says for the first time: “I signed up for guitar lessons and practiced for an hour last night.” No belief matches and the Top- $K$ items are only loosely related, so absolute scores are low but one still dominates, giving a moderate $\rho_{t}$ and, by the mechanism described in Section C.8, PROFILE. The Profile-Agent writes the hypothesis “the user may have taken up guitar” with $w_{0}<\tau_{\mathrm{promote}}$ , linked by provenance to that turn and retrieval-visible at once, so the agent can already answer cautiously. If guitar recurs, MAINTAIN reinforces the hypothesis until it crosses $\tau_{\mathrm{promote}}$ and becomes a FACT; otherwise it remains a low-confidence hypothesis that never outranks committed facts. A new topic therefore enters provisionally, is usable immediately, and is committed only after repeated support.

## Connection to the consolidation loop.

Across these cases, PreCoMem’s leveraging–evolution loop links response quality to memory consolidation.
Evidence recalled for the current answer is also used to update confidence through MAINTAIN/PROFILE/CORRECT (Section 2.4), so future retrieval and recommendations reflect accumulated support, implicit verification, and soft correction under contradiction.
